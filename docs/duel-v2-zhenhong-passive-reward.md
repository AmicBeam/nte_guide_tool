# 真红被动过程奖励

2026-09-21 用户要求给真红追加正向激励，并明确口径是“触发真红被动次数”，而非队伍盈蓄日志数量。此为后续训练奖励变更，未重新训练，也不改写先前13.5%的评估结果。

## 默认数值与计数

在现有胜 +10、负 -10、平局 0 基础上，真红学习方每次实际执行 `Zhenhong.on_surplus` 增加0.2奖励。0.2是本次实现的可调默认值，不是用户指定或已验证最优的系数；`--zhenhong-passive-reward` 可设置非负有限数，0恢复纯终局奖励。奖励线性累加，不设次数上限。

计数由真红角色的 `surplus_passive_triggers` 保存，旧快照缺失时按0处理，倒地和恢复保留。角色回调仅在真红存活、被动实际生效时执行，因此队伍触发盈蓄但真红倒地时不给奖励；没有延滞不触发；同次创生因九原重复两段只执行一次被动；新的实际触发继续加1。单纯发动终结或发生额外攻击不直接计次，只有它们确实再触发该被动才计。此字段是观测计数，不改变加攻、免伤、追加攻击和胜负规则。

## 学习目标

全局诊断回报＝终局回报＋0.2×本局被动总次数。各决策的训练目标为终局回报＋0.2×从该决策起后续实际发生的次数，不将过去已经获取的奖励归给后续无关动作。例如总共3次、某决策前已经1次，胜局该决策目标为10.4，而不是10.6。最后一次触发之后的动作只得到终局目标。

只在 `train=true` 且学习策略ID为 `zhenhong` 时启用；冻结对手及其他学习策略不加该奖励。只有真实终局的轨迹参与 PPO，截断局没有回报标签。原有其他入口未提供逐决策回报时继续使用各局原终局回报。

训练逐局记录被动次数、终局回报、额外奖励和总回报；配置及模型来源中记录奖励系数。独立评估仍只按实际赢家计胜率，不把过程奖励当胜局，不自动部署。下一轮必须重新使用隔离种子评估，不能仅凭触发次数或训练奖励增加断言策略更强。

## 验证

`python -m unittest tests.test_duel_v2_passive_reward tests.test_duel_v2_fixed_lineups tests.test_duel_v2_surplus_rework tests.test_duel_v2_zhenhong_buff tests.test_duel_v2_yi_ultimate`：68项通过，覆盖真实被动去重、多次累加、倒地不追加计数、JSON保存、无延滞、奖励随次数单调增加、逐决策只计未来触发、截断排除及旧纯终局轨迹兼容。本次未运行优化训练。

## 搜索学习接入

现行学习默认把前置奖和被动次数奖都设为 0，见[训练手册的现行学习方法](duel-v2-public-training.md#现行学习方法)。下面的 0.1 与 0.2 是显式打开课程时的计分方式，不是新训练的默认系数。

十人搜索运行时复用信息集搜索与策略／价值联合更新。训练树内按真红实际被动计数增量加入 `系数/10` 的收益；只作用于当前学习方的真红策略。真实完整对局保留原终局标签 `z∈{-1,0,1}`，另存 `reward_to_go=10*z+系数×未来实际触发次数`，真红价值回归使用该回报，策略仍拟合搜索访问分布。冻结历史方不获得奖励学习样本，独立评估不加激励。恢复点必须同时保存过程回报与纯终局标签；这类价值分数不是校准胜率。

## 临时前置课程：延滞＋兽牙（2026-09-22）

用户要求短期鼓励真红队先建立盈蓄前置步骤，同时长期不能只靠人工激励。该奖励只用于离线搜索训练，不修改卡效、费用、状态持续时间或对局胜负。

- 条件：对方战斗区存在由己方施加、剩余时间大于0的延滞，并且己方翳的兽牙剩余时间大于0。两种效果必须实际同时成立，手里有相关牌不计分。不要求前排非空；翳倒地后仍有效的兽牙按现行规则计入。
- 每局只奖励首次达成；刷新、延长、维持状态，以及消失后再次建立都不重复奖励。默认初始奖励为 **+0.1**，低于实际真红被动每次 **+0.2** 的奖励。0.1是实现默认值，不是用户指定或已验证最佳参数。
- 奖励系数按该策略累计优化步线性衰减：`0.1 × max(0, 1 − 更新步数/64)`。64步为可调默认课程长度，到64步及之后为0，不因原／候选适应分支、保留较早权重或恢复同策略数值模型而自动重置进度。从其他角色策略新建真红策略时从0开始。
- 当前共享搜索入口提供 `--zhenhong-setup-reward` 和 `--zhenhong-setup-decay-steps`；前者设0关闭前置奖。现有实际被动奖仍由 `--zhenhong-passive-reward` 控制，不因新增前置奖改变其每次触发计分口径。
- 只作用于正在学习的 `zhenhong` 策略；冻结对手、其他策略及独立评估不加奖励。真实对局和树内模拟均对首次达成去重；搜索树区分本次模拟是否已获得奖励，不以反复建立状态刷分。
- 只有正常终局且搜索完整的轨迹进入学习。每个决策只分配其后首次达成的奖励，不把已经得到的奖励再次分配给后续动作。保留纯终局 `z`、实际被动回报和前置奖三个独立部分；它们不冒充胜率。
- 回放价值目标按当前前置系数重算。系数归零时清除带此前前置奖生成的旧搜索标签，并先重新采样无前置奖的轨迹再继续更新。检查点保留前置达成标签、生成系数及课程进度；数值模型的来源记录 `setup_reward_updates`，它用于奖励课程计步，不代替每阶段真实参数更新统计。

### 长期验收

临时奖不是搜索与价值学习问题的替代修复。后续仍须改进分支探索、隐藏世界覆盖、多步延续和价值估计；检验模型能否从真实终局反馈学到前置步骤的收益。

独立评估始终不加入人工奖励，报告同时看前置达成、实际被动触发和真实胜负，不能只看前置率上升。还应做两项人工奖均为0的训练对照，使用新采集的纯胜负搜索标签及独立评估种子；若关闭奖励后行为和胜率退化，说明尚未学稳，不能宣布已摆脱人工激励。现有被动奖保留开关，是否撤除由该对照验证，而不是无限追加新的手写奖励。

验证入口：`python -m unittest tests.test_duel_v2_setup_reward tests.test_duel_v2_information_search tests.test_duel_v2_ten_search`。当前修改只接入奖励、衰减和边界测试，不意味着已重新训练或证明胜率改善。

## 一小时开关对照入口

`scripts/train_duel_v2_setup_trial.py`用于固定真红构筑的有界开关试验，复用 `information_search.search_game` 与 `policy_value_update`，不走PPO或另造训练算法。正式运行默认3600秒，前45分钟学习，随后9分钟冻结评估，最后6分钟汇总保存；监督器以绝对时间和单调时钟约束整个进程树。

control组前置奖为0，setup组按0.1/64步课程衰减；两组实际被动奖励均为0.2。两组从相同数值权重、构筑和重置Adam起步，共用根对局种子、冻结的娜伊零九／薄白零伊／吱零薄九对手及先后手计划。每批四个配对案例，共八个搜索工作进程；两组对应案例都正常终局并且搜索完整时才各更新相同次数。单个案例未完成则两边都不用，其他完整配对仍可更新。固定模型目录在整批采样期间不变。仅学习方样本参与更新。

初始模型、control最终模型、setup最终模型分别以同一组独立种子对三个冻结对手各64对先后手，共384局/方案。报告列实际胜率、前置达成局数、实际被动触发局数与次数、免伤期间队友倒地记录及两组实际更新次数，不把训练奖励当成胜率。有限试验不自动批准模型；只在输出目录保存数值权重和报告，不覆盖网站模型。独立种子需先在共享账本登记，通过 `--seed-reservation` 传入，`--run` 才实际启动。
