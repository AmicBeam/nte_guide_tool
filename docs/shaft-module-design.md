## 背景与参考

目标是在现有 Flask 站点中新增 `/shaft` 模块，用于计算异环角色组队 DPS。玩家可以按 0.1 秒精度编辑动作轴，查看直伤、倾陷伤害、总伤害、DPS、角色贡献、实时面板与伤害明细，并把自己的轴上传到在线市场，支持赞、踩、收藏和按角色筛选。

本轮已分析两个参考来源：

- `异环云配队.xlsx`：本地路径 `/Users/bytedance/Downloads/异环云配队.xlsx`。工作簿版本标注为 `异环云配队 V0.2.7`，作者标注为“静默之光”。它是公式和初始数据的主要参考。
- `eclairtle/EndfieldToolbox`：已克隆到 `/private/tmp/endfield_toolbox_ref`，commit `dd2214efb3b540e01d350df525474d4f1bdb273b`。该项目是 Vue 浏览器构筑与轴计算沙盒，核心分层为构筑快照、命令解析、时间线编译、运行时模拟。仓库没有 license 文件，`package.json` 也没有 `license` 字段，因此本项目只借鉴架构概念，不复制代码。

## 模块边界

`/shaft` 是独立网页工具，不进入异象对决牌桌规则层。

- 可以复用现有玩家登录态、头像、角色图片、`common/base.html`、基础样式和静态资源组织方式。
- 不复用 `GameRun`、房间、对局快照或异步对局持久化。
- 轴计算属于工具计算，不影响玩家卡牌构筑和牌桌战斗状态。
- 市场上传、赞和踩必须登录；收藏不要求登录。上传、赞、踩、收藏都必须同步写库成功后再返回，不走异步队列。
- 玩家可以把排轴保存为自己的私有草稿，不上传到市场；上传只是把私有轴发布为公开市场轴。

建议新增目录：

| 路径 | 职责 |
| --- | --- |
| `app/modules/shaft/domain/` | shaft 独立领域层，包含数据加载、面板计算、伤害公式、时间线编译、模拟器和校验 |
| `app/modules/shaft/service.py` | Flask 路由调用的应用服务，负责鉴权玩家上下文、调用 shaft 计算器和 DAO |
| `app/modules/shaft/static/` | shaft 页面 JS/CSS |

| `scripts/import_shaft_xlsx.py` | 离线导入 xlsx 到静态 JSON 的脚本 |

## 数据导入方案

运行时不直接读取 `/Users/bytedance/Downloads/异环云配队.xlsx`。xlsx 只是离线导入参考；导入后数据由本项目保存到 `app/modules/shaft/static/data/` 的静态 JSON，并随代码一起维护。线上计算、市场展示和页面 catalog 都只读取项目内保存的数据，不实时依赖用户下载目录或 xlsx 文件。

建议导出文件：

| JSON | 来源 | 用途 |
| --- | --- | --- |
| `source_meta.json` | 工作簿名称、版本、导入时间、sheet 尺寸、源文件 hash | 页面展示和公式回归定位 |
| `characters.json` | `角色` + 本项目角色图片映射 | 角色基础属性、属性、星级、图标 |
| `actions.json` | `动作` | 可摆放动作库 |
| `action_hit_profiles.json` | 腾讯文档 `角色技能数值` + 本地聚合动作 | 动作打断后的逐段累计倍率、回能、环合与倾陷 |
| `buffs.json` | `增益` | buff/debuff 定义 |
| `arcs.json` | `弧盘` | 弧盘数据 |
| `cartridges.json` | `卡带` | 卡带数据 |
| `formula_constants.json` | `中间` 与固定全局参数 | 等级、防御、反应、主词条和副词条常量 |

导入脚本需要保留 xlsx 单元格来源，例如 `source_cell: "动作!E11"`，方便后续和表格对照。导入脚本只在维护数据时运行，不在 Flask 请求链路中运行。

## 构筑与实时面板

第一版只支持角色 80 级和弧盘 80 级，不提供角色等级、弧盘等级的自由输入。常驻面板来自 `配装` 页，可翻译为以下模型：

```json
{
  "character_id": "zhenhong",
  "level": 80,
  "awakening": 0,
  "bond_level": 0,
  "bond_full": false,
  "arc_id": "穿过胭红蜃景",
  "arc_level": 80,
  "cartridge_id": "失落光芒",
  "kongmu": {
    "main_stat": "环合强度",
    "bonus_value": 10,
    "bonus_stat": "攻击",
    "passive_type": "3型被动",
    "passive_stacks": 4
  },
  "substat_counts": {
    "all_dmg": 0,
    "crit_rate": 0,
    "crit_dmg": 0,
    "harmony_strength": 0,
    "stagger_strength": 0,
    "atk_pct": 0,
    "flat_atk": 0,
    "hp_pct": 0,
    "flat_hp": 0,
    "def_pct": 0,
    "flat_def": 0
  },
  "toggles": {
    "talent_a": true
  }
}
```

配装页副词条使用“词条数”输入，网页不让玩家直接填最终百分比或固定值。每格词条的加成量如下：

| 副词条 | 单格加成 |
| --- | ---: |
| 通伤 | 1% / B |
| 暴击 | 1% / B |
| 暴伤 | 2% / B |
| 环合强度 | 6 / B |
| 倾陷强度 | 6 / B |
| 攻击% | 1.25% / B |
| 攻击 | 8 / B |
| 生命% | 1.25% / B |
| 生命 | 100 / B |
| 防御% | 1.75% / B |
| 防御 | 8 / B |

常驻面板计算顺序：

1. 基础攻击 = 角色 80 级攻击 + 弧盘 80 级攻击。
2. 大攻击区 = 角色攻击% + 弧盘攻击% + 卡带攻击% + 主词条/空幕/觉醒/羁绊/天赋/副词条词条数等百分比。
3. 小攻击区 = 弧盘/角色/家具/副词条词条数等固定攻击。
4. 面板攻击 = 基础攻击 * (1 + 大攻击区) + 小攻击区。
5. 生命、防御同理。
6. 暴击、暴伤、充能、环合强度、倾陷强度分别由角色基础 + 弧盘 + 卡带 + 主词条/空幕/天赋/副词条词条数组成。属性伤害拆为 `element_dmg_光/灵/咒/暗/魂/相` 六个独立字段，不再存在通用 `element_dmg` 运行时字段。

卡带允许跨属性装备；两件套把10%增伤直接写入卡面指定的 `element_dmg_X`，不再保留 `required_element` 或装备者属性筛选。卡带主词条与属伤空幕保留“属伤”作为存档选项名，结算时自动映射到当前角色自身属性字段。


## Buff 控制体系方案

buff/debuff 不再由玩家在页面手动填写名称和覆盖率，而是由代码内置的规则触发。页面只负责展示“谁触发了什么、当前作用给谁、影响哪些动作、何时结束”，不提供配置入口。第一版建议拆成三层：静态定义、事件触发、运行时状态。

### 静态定义

所有 buff 放入项目内数据或代码注册表，例如 `app/modules/shaft/static/data/buffs.json` 或后端 `app/modules/shaft/domain/buffs.py`。定义本身不跟玩家练度绑定，只描述触发、目标、持续、叠层和数值效果：

```json
{
  "id": "nanali_e_crit_damage",
  "name": "娜娜莉 E 暴伤",
  "priority": 100,
  "trigger": {
    "event": "action_start",
    "source": {
      "character_names": ["娜娜莉"],
      "action_names": ["e"],
      "placements": ["foreground"]
    },
    "conditions": [
      {"type": "resource_at_least", "resource": "噩梦", "value": 0}
    ]
  },
  "target": {
    "slots": ["team"],
    "character_names": [],
    "action_names": [],
    "action_types": ["普攻", "E", "Q"],
    "tags": ["追击"],
    "placements": ["foreground", "background"]
  },
  "duration": {
    "type": "time",
    "ticks": 100,
    "loop_carry": true
  },
  "stacking": {
    "mode": "refresh",
    "max_stacks": 1
  },
  "effects": {
    "crit_dmg": 0.3
  }
}
```

字段口径：

- `trigger.event` 当前支持 `passive`、`action_start`、`action_hit`、`action_end`、`foreground_enter`、`foreground_leave`、`loop_start`、`reaction_trigger`、`reaction_end`、`periodic_damage`、`dot_layer_applied` 和 `full_stack`。
- `source` 用角色、动作名、动作类型、标签和前后台位置过滤触发动作，不依赖玩家输入的 buff 名。
- `conditions` 用结构化条件描述待补机制，例如资源层数、敌人弱点、是否轨外之境、是否循环轴、前一个动作、动作命中段数。
- `target` 同时过滤角色和动作。一个 buff 可以只影响指定角色、指定动作、指定标签、指定前后台位置。
- `duration` 支持按时间、按动作次数、按命中次数、按资源存在状态结束。循环轴时只有 `loop_carry: true` 的持续状态允许从轴尾结转到轴头。
- `stacking` 支持 `refresh`、`extend`、`replace`、`independent`、`add_stack`，并统一设置 `max_stacks`。
- `effects` 只写可计算字段，如 `atk_pct`、`flat_atk`、`crit_rate`、`crit_dmg`、`all_dmg`、`basic_dmg`、`skill_dmg`、`ultimate_dmg`、`def_down`、`res_down`、`harmony_strength`、`stagger_strength`、`damage_taken_pct`。

### 事件触发

模拟器按 0.1 秒 tick 排序动作，但 buff 不需要每 tick 重算。只在离散事件点执行：

1. 进入动作前生成 `action_start`，用于启动 buff、消耗资源、切换前台状态。
2. 计算伤害前生成 `action_hit`，用于命中前加成、按段数叠层、按动作类型筛选加成。
3. 环合生成和状态自然结束分别生成 `reaction_trigger` 与 `reaction_end`；黯星被新实例顶替时只提前结算伤害，不生成 `reaction_end`。
4. 周期伤害结算和持续伤害层施加分别生成 `periodic_damage` 与 `dot_layer_applied`。
5. 动作结束生成 `action_end`，用于结束状态或触发后续状态。
6. 循环轴开启时，在轴头补发 `loop_start`，只处理轴尾仍未结束且允许结转的状态。

同一 tick 内按 `priority` 从小到大执行；同优先级按动作轴顺序执行。这样 0 秒动作也有稳定结算顺序。

### 运行时状态

运行时只保存已经触发的实例，不保存玩家手填配置：

```json
{
  "instance_id": "nanali_e_crit_damage:slot2:42",
  "definition_id": "nanali_e_crit_damage",
  "name": "娜娜莉 E 暴伤",
  "owner_slot": 2,
  "source_step_id": "step_014",
  "start_tick": 42,
  "end_tick": 142,
  "stack_count": 1,
  "remaining_actions": null,
  "target_snapshot": {
    "slots": [0, 1, 2, 3],
    "action_types": ["普攻", "E", "Q"]
  },
  "effects": {
    "crit_dmg": 0.3
  }
}
```

动作结算时先取当前动作的基础面板，再筛选所有激活实例：时间窗口命中、目标角色命中、动作过滤命中后，将 `effects` 合并到实时面板。详情面板展示 `applied_buffs` 和 `triggered_buffs`，用于调试为什么这次伤害吃到了某个状态。

### 与循环轴的关系

非循环轴只计算 `[0, 轴尾]`。循环轴开启时，轴尾未结束的状态会按以下规则处理：

- 排轴工具栏通过“循环轴”按钮打开设置弹窗；开启后可按当前队伍角色配置起始能量、起始环合值、该角色已接入的个人资源，以及一个起始环合效果。起始环合效果为单选下拉框，默认“不携带”，候选由 `formula_constants.loop_initial_reaction_options` 提供且只接受 `duration_ticks > 0` 的持续环合；每名角色最多携带一个。残虹额外支持分别输入自带蚀心、鸩火层数，取值0–10，0表示不携带；两种DOT不占用携带环合名额。起始能量受角色自身上限约束，起始环合值上限为 100，个人资源按角色资源上限约束；关闭循环轴时保留配置但不参与结算。
- 起始环合效果在循环轴第0 tick生成以该角色为贡献者的正常环合实例，沿用对应环合的持续时间、伤害节拍、DOT标签和环合强度计算；它不消耗角色起始环合值，也不伪造援护动作。非循环轴忽略该配置。
- 按用户 2026-08-11 补充口径，自检使用 `loop_initial_reaction_options` 中记录的原始实例模式与数量上限校验起始环合，并且只在循环配置的自带实例参与冲突时告警；纯轴内的正常实例冲突不属于自检问题。创生最多同时存在3个独立实例，不折算成层数或频率乘区；延滞、覆纹、浊燃、黯星、浸染最多存在1个实例。所有环合触发都会先正常生成新实例；达到容量时挤掉开始时间最早的旧实例。自带实例与轴内产生实例合计超限时告警，角色后续提供的刷新、延长或额外加层能力不改变该判定。残虹能为浊燃加层并刷新持续时间，但轴内已经产生浊燃时仍不能再把浊燃作为无冲突的循环起始环合。被新实例挤掉的浊燃会记录固定截止 tick；重叠动作之后补算的早于截止点的刷新，不得让旧实例跨过该截止点与新实例并存。黯星旧实例被挤掉时立即结算其伤害，再保留新实例，不等待旧状态自然结束。
- 循环起始环合先在上一轮的 `-loopDurationTicks` 生成并参与完整预热。若实例在 0 tick 仍有效，则将其投影为从 0 tick 开始的继承实例，保留轴尾时的剩余持续时间、运行时层数、频率乘区及未来伤害 tick；不得删除后再从 0 tick 生成完整时长的新实例。伤害 tick 先按真实计算时间继承，再通过冻结区间换算显示时间，因此 0 秒 Q 不能重置周期伤害相位。
- 残虹自带蚀心、鸩火与循环起始环合使用相同的上一轮预热和轴首继承口径，保留剩余持续时间、实际层数与下一次1秒伤害节拍；上一轮动作产生或扩散的同类DOT按10层上限正常合并。若预热后没有同类DOT跨过轴尾，则在本轮0 tick按配置层数重新播种。非循环轴或配置为0层时不生成对应DOT。
- `loop_carry: false`：轴尾结束，不结转。
- `loop_carry: true` 且剩余时间大于 0：复制一份运行时实例到轴头，`start_tick` 变为 0，`end_tick` 等于剩余 tick。
- 循环预热使用上一轮的负 tick 重放可结转状态；带触发间隔的 Buff 在首次负 tick 触发时视为尚无冷却记录，后续才按真实触发 tick 建立冷却，不能用默认 0 tick 阻断整轮预热。
- 循环预热按上一轮的动作顺序同步重放动作事件与环合事件；规则的状态修改会正常执行，包括负 tick 上黯星自然结束派发的 `reaction_end`。只有 `duration.loop_carry = true` 的 Buff 实例会跨过轴尾；由上一轮 `reaction_end` 生成的永久 Buff 也必须在轴首进入实时面板和 `applied_buffs`，不得只绘制循环 Buff 线。能量、环合值和个人资源在预热后恢复玩家配置的循环初始值，不把预热消耗或获取重复计入当前轮。
- 循环初始环合会在上一轮轴头播种；若上一轮的加层、刷新或其他状态修改跨过轴尾，本轮轴头继承这些运行时字段，再按循环初始配置刷新基础持续时间，不重置层数或频率乘区。
- 按动作次数或命中次数结束的状态，只有定义明确允许 `loop_carry` 时才结转剩余次数。
- 跨过轴尾并折回下一轮展示的 Buff 线，必须继续响应下一轮动作声明的状态清除事件；折回段在对应清除 tick 截断，不能与清除后重新产生的同键或互斥状态重叠。
- 结转状态只影响下一轮轴头，不改变轴本体 hash；市场去重仍只看动作轴、角色、弧盘、卡带。

### UI 边界

页面不再展示“触发增益配置”面板。排轴页只展示三类信息：

- 动作详情：本次动作吃到的 buff、触发出的 buff、结束时间或剩余次数。
- 时间轴提示：可选显示持续状态条，用细色带叠在角色行背景，不允许遮挡动作卡。
- 同一个 Buff 连续生效期间，仅层数变化不切分状态条；循环轴与非循环轴使用同一规则。悬停提示仍按指针所在时刻展示对应层数，Buff 新增、移除或中断时才切分状态条。
- 总览：汇总主要 buff 覆盖率、触发次数和循环轴结转状态，用于排查轴是否按预期运转。
- 配装页右侧总览底部提供“副词条贡献度”。分析使用与当前轴相同的角色、装备、敌人和动作，但基准临时把每名角色的通伤、暴击、暴伤、环合强度、倾陷强度、攻击%、生命%、防御%各设为15条（合计120条），小攻击、小生命、小防御设为0。基准总伤计算后，为上述11类词条的每个“角色 × 词条”组合单独额外增加5条并重算全队总伤；以所有组合中的最高正提升归一为100%。展示层使用“角色 × 词条”二维表格，单元格只显示归一化贡献度，无正提升时显示—。每个角色在行内单独按贡献度排名，只高亮前4个非零词条，并对第1至第4名分别使用稳定的四档前景色、浅色背景和描边；其余非零值降低视觉权重。贡献度相同时按表头词条顺序稳定选取前4个。该过程只克隆前端 `state.axis`，并使用页面已加载的 `state.catalog` 调用 `shaft_engine.js`；不发起后端请求，不回写当前配装、本地草稿、已保存轴或 `state.compareSnapshot` 中由用户主动保存的对比快照。
- 动作贡献的“合并伤害类型”按基础动作类型归类；“追击”和“附着”是附加标签，不得覆盖普攻、E、Q 等基础类型。

页面展示“实时面板”时，按 0.1 秒采样生成曲线；实际伤害计算只需在动作命中/结算事件处求一次面板。

## 伤害公式映射

xlsx 中普通动作伤害可拆为以下步骤。

全局等级与敌人参数：

```text
角色等级因子 = 6 * 角色等级 + 600
敌人防御因子 = 6 * 怪物等级 + 600 - 轨外之境修正
怪物抗性 = 云配队输入
怪物弱点属性 = 云配队输入
弱点减抗 = 云配队输入
```

单次动作：

```text
基础区 = (
         实时攻击 * 攻击倍率%
       + 实时生命 * 生命倍率%
       + 实时防御 * 防御倍率%
       ) * (1 + 基础倍率提升)
       + 固定伤害

增伤区 = 动作类型增伤
       + 该动作伤害属性对应的X属性伤害/通伤/额外标签增伤
       + 运行时增伤
       + 对敌类型等条件增伤

暴击率采用 xlsx 同款期望计算：DOT 动作为 50%，否则 min(常驻暴击 + 运行时暴击, 100%)
暴伤 = 常驻暴伤 + 运行时暴伤
双暴区 = max(1 + 暴击率 * 暴伤, 1)

结算抗性 = 怪物抗性 - 弱点匹配减抗 - 角色/状态减抗
抗性值 = 1 - 结算抗性
抗性区 = 结算抗性 > 0.6
  ? 1 / (6.25 * 结算抗性 - 1.25)
  : (抗性值 < 1 ? 抗性值 : 2 - 1 / 抗性值)

减防 = min(常驻减防 + 运行时减防, 100%)
防御区 = 心灵标签 ? 1 :
  角色等级因子 / (角色等级因子 + 敌人防御因子 * max(1 - 减防, 0))

单次伤害 = 基础区 * (
  伤害类型为真伤
    ? 1
    : (1 + 增伤区) * 双暴区 * 抗性区 * 防御区 * 反应增幅 * (1 + 最终增伤)
)

总伤害 = 单次伤害 * 动作重复次数
```

结算抗性先扣除弱点与减抗，再进入抗性区。抗性超过 60% 时使用 `1 / (6.25 × 结算抗性 − 1.25)`；不超过 60% 时仍用上面的原分支。60% 处两边都是 0.4。该高抗性分支来自用户 2026-09-24 口径，不是 xlsx 原式。

动作自带 `damage_element` 时读取该属性字段，否则读取角色自身属性字段。动作右侧面板只展示本次使用的“X属性伤害”；角色面板汇总只展示角色自身属性字段。

角色机制明确写“伤害倍率提升”“攻击倍率提升”或“倍率提升至”时，进入“基础倍率提升”乘区，直接放大动作的攻击/生命/防御倍率部分，不进入通伤、类型增伤或最终增伤区。未明确写“倍率”的普通“伤害提升”仍按对应增伤区结算。

倾陷、环合与反应：

- 动作表提供每个动作的倾陷、环合、回能、能量返还和合轴时间。
- `中间` 页按 `计算` 第 1 行的 `q/h/y/t/d/s` 标记汇总：`q` 倾陷、`h` 环合、`y` 回能、`t` 时间、`d` 单次伤害、`s` 总伤害。
- 倾陷频率按 xlsx 公式 `1 / (倾陷上限 / 全轴总倾陷 + 倾陷恢复时间 / 轴长)` 计算；基础倾陷恢复时间为 10 秒，队伍装备「最后一朵玫瑰」时延长 3 秒。
- 单次倾陷伤害由四名角色分别贡献。每名角色使用其整轴动作快照的平均倾陷增伤、平均穿防、平均减防和平均减抗计算，再乘以倾陷频率计入全队总伤与 DPS；平均倾陷增伤按动作快照将“倾陷强度 ÷ 300”与明确的倾陷伤害增伤相加后取平均，当前包含达芙蒂尔「分光」 +20% 和残虹觉醒的全队 +300%。倾陷强度只进入该倾陷伤害增伤换算，不放大动作表提供的倾陷值，因此不改变全轴总倾陷或倾陷频率。倾陷贡献不计入角色自身伤害、角色自身占比或动作贡献。配装页在角色贡献列表后使用同款行式布局提供倾陷占比与“分析详情”，弹窗展示各角色倾陷贡献、占倾陷比例、单次贡献与平均参数。达芙蒂尔「洞察」额外造成的倾陷伤害作为独立次数倍率结算，不计入“平均倾陷增伤”展示。
- 创生、创生复制体、浊燃和黯星等环合伤害同样独立计入全队总伤与 DPS，不计入角色自身伤害、角色自身占比或动作贡献；配装页在角色贡献列表后使用同款行式布局提供环合占比与“分析详情”，弹窗按角色和环合来源展示贡献。占比与分析展示层将创生复制体并入创生，底层结算事件仍保留两者的独立机制语义。
- 反应环合强度默认取“全队最高”，也可以指定角色。
- 增幅提升公式为 `0.2 * 环合强度 / (环合强度 + 180)`。
- 剧变增幅公式为 `环合强度 / 600`。
- `independent` 独立叠层 Buff 的每一层分别记录持续时间；满层后再次施加时替换结束时间最早的一层。残虹幻a的“现存 DOT 加层”按DOT伤害标签发现全队来源，复制原DOT的归属、倍率、伤害类型等性质，并以触发时为起点建立完整持续时间和触发间隔的新实例。
- 反应防御区继续使用等级/敌防公式。
- 创生、浊燃、黯星分别有独立基础量和倍率；浊燃额外读取浊燃暴伤。
- 九原天赋一按用户 2026-07-19 口径作为创生与创生复制体的独立频率乘区 ×2；娜娜莉按用户 2026-07-21 口径只改写原创生花数量，不影响伊洛伊固定20朵的创生复制体。该频率乘区仍分别作用于二者，并保持单次伤害和各自原持续窗口不变。Nanoka 原始描述为“额外生成1株创生株”，该频率折算属于项目实现口径。底层仍保留 `frequency_multiplier`、期望暴击和各伤害乘区进行结算；时间轴伤害 tooltip 不再展示合并后的乘区，而是展示基础面板/基础值、倍率或频率、层数、增伤、暴击暴伤、减防、穿防、减抗、最终增伤和最终伤害等原始数值。

这些公式应落到 Python 中，并用 xlsx 当前示例轴做快照回归测试：直伤、倾陷伤害、总伤害、DPS、各角色贡献、单动作伤害都需要和 xlsx 缓存值在可接受误差内一致。

```text
tick = round(seconds * 10)
seconds = tick / 10
```

用户编辑的轴不是 0.1 秒逐帧状态表，而是动作事件列表：

```json
{
  "axis_version": 1,
  "duration_ticks": 600,
  "team": [
    {"slot": 0, "character_id": "zhenhong"},
    {"slot": 1, "character_id": "protagonist"},
    {"slot": 2, "character_id": "nanali"},
```

编译阶段输出按时间排序的 `CompiledEvent[]`：

- `action_start`
- `damage_hit`
- `apply_status`
- `expire_status`
- `reaction`
- `energy_change`
- `personal_resource_change`
- `front_state_change`
- `snapshot`

精度策略：

- 用户输入、拖拽和市场存储使用 0.1 秒。
- 公式计算可以保留浮点秒和原始动作合轴时间，但落库和展示使用 tick。
- 所有前台或占位动作开始节点默认至少间隔 0.2 秒，即 `2 tick`；如果处在同一个真实 tick 内，则至少间隔 2 个内部时序单位。这个间隔规则独立于切人损耗，间隔不足时 UI 需要自动推开或提示玩家调整。标记为 `is_background_damage` 的纯后台伤害动作不占用前台动作开始节点，可以与前台动作或其他后台伤害同 tick。时间轴可视范围取前台与后台动作显示终点的较晚者，末尾保留 1 秒留白，因此超出前台终点的后台动作仍完整显示；总轴长、DPS 分母和循环轴实际时间继续只按前台动作计算。
- “带 Q 标签 + 原始持续时间为 0 秒 + 前台动作”或“显式配置 `is_timeline_mask=true` + 原始持续时间为0秒 + 前台动作”时，动作拥有 Q 级避障、遮罩、同列锚点、虚拟宽度和收尾免切人能力。显式遮罩动作不因此视为Q，也不触发Q类Buff、耗能或技能效果；灵可「时停选人」即为0秒无效果的专用遮罩。带 Q 标签但原始持续时间大于 0 的动作按普通动作处理，例如真红“穿梭”；真红 Q2 原始持续时间为 0，拥有与 Q 等量的上述能力。具备这些能力的动作不下沉到后台或下一行，并通过时间轴扩距处理显示重叠，但仍必须满足开始节点最小间隔；多个遮罩动作必须按可视最短宽度首尾相接排列，后一个动作的首端对齐前一个动作的尾端，拖拽时可通过改变起点自由调整先后顺序。
- 异环存在大量耗时为 0 秒的动作；0 秒动作仍然拥有动作开始节点，仍然触发前台状态、CD、能量、个人资源和动作触发 buff。同一个真实 0 秒内部允许存在严格先后顺序，按可视位置从左到右结算。
- 0 秒动作在 UI 中使用固定视觉宽度，且该动作所在时间轴的可视范围需要随之膨胀；该视觉宽度是同一真实 tick 内的内置时序坐标，只参与拖拽、排序、同 tick 内先后和视觉排斥，不参与真实轴长、DPS 分母或伤害计算。UI 不得把这段内置时序显示成 `0.1s`、`0.2s` 等假秒数，也不得把内部时序序号直接展示给用户；光标、右键菜单和动作起点仍只显示扣除虚拟宽度后的真实计算秒数。模拟器在计算真实 `start_tick`、`end_tick` 和 `duration_ticks` 前，需要扣除具备 Q 级能力的 0 秒前台 Q 动作插入的虚拟宽度。具备 Q 级能力的动作只截断其开始列已经覆盖到的其他动作，也就是被截断动作满足 `视觉开始 < Q视觉开始 < 视觉结束`；与其间隔 2 tick 或 2 个内部时序后才新开始的动作不视为被截断，仍按自身耗时计算结束时间。Q 级截断不会把已经经过的真实时间清零：被首次截断的动作结束在该 Q 动作的真实计算 tick，并占用该 tick 的下一个内部时序；与其衔接、可后台结算的普攻继续被覆盖时，折叠到同一个真实计算 tick 上按内部时序继续排列。触发遮挡的 Q 动作自身可视宽度需要扩展到被覆盖链的视觉尾端；这段扩展仍是内部时序，不折算成真实秒数，也不额外显示序号。例如真红 `龙a4` 开始 2 tick 后切队友开 Q，则 `龙a4` 计算为 `2 tick + 内部时序 0→1`，后续 `龙a5` 计算为同一 `0.2s` 上的 `内部时序 1→2`；这些内部时序只用于结算排序和测试明细，不在前端显示。
- 每次切换前台角色默认有 0.2 秒损耗，即 `switch_loss_ticks = 2`。当某个前台动作开始节点的角色不同于当前前台角色，且上一段普通前台动作耗时大于 0 时，编译器插入一次切人损耗；0 秒动作衔接下一个动作时不插入这次损耗。具备 Q 级能力的动作收尾后允许直接切换角色释放其他动作，不额外插入这 0.2 秒切人损耗；真红“穿梭”不享受该例外。UI 需要可视化切人损耗，并在前台动作起点冲突时提示玩家调整。
- 自检额外检查角色离开前台后再次切回的间隔：从切换给其他角色的前台变更节点，到该角色重新成为前台的变更节点，必须至少经过 12 tick（1.2 秒）。若使该角色离场的其他角色动作本身就是具备遮罩能力的动作，或离场后至回场前任意角色释放了这类动作，则本次切回豁免；该角色离场前自己的遮罩和回场动作自身的遮罩不提供豁免。判定复用“前台动作 + Q类型或显式遮罩标记 + 原始持续时间为0秒”，因此真红“穿梭”不能提供豁免。遮罩动作的虚拟显示宽度不计入这1.2秒，自检时间使用计算引擎的真实tick。
- 事件同 tick 排序按 `action_start -> resource/cooldown check -> apply_status -> damage_hit -> reaction -> snapshot` 稳定执行。

## 前台状态与资源

在 EndfieldToolbox 排轴能力的基础上，shaft 增加“前台状态”。

- 前台状态是可配置能力，默认开启。
- 每次产生普通前台动作开始节点时，前台状态切换到该动作角色身上；后台伤害动作不切换前台状态。专用「无」节点无论放在前台还是后台，都会在开始节点把对应角色切为当前前台；后台「无」只改变轨道占用，不取消切人、离场/入场事件或切回间隔自检。动作可用 `locks_foreground_switch` 显式控制从开始到结束的前台锁定；未配置时援护技仍默认锁定、时停0秒动作仍按虚拟展示区间锁定。援护开始时不触发切人损耗，但前台状态切换并保持为援护者；小贞同频显式关闭锁定。锁定结束后衔接当前前台角色自己的动作不产生切人损耗。
- 每名角色由 catalog 生成一个通用「闪」动作，固定前台并占用 5 tick，不造成伤害、不修改能量、环合、倾陷或个人资源；动作库排序固定为「闪」在「无」之前。
- 时间轴动作支持双击打开统一编辑框。步骤可携带布尔字段 `detached`；只有动作配置 `can_detach=true` 时该字段才保留，并用 `detached_duration_ticks` 代替普通动作时长。当前白名单为安魂曲 `a4远` 与 `e`（脱手 5 tick）和黑羽 `魔a5`（脱手 6 tick）。脱手动作名称不增加后缀，时间轴通过专属字体颜色区分。脱手步骤必须从前台开始，不能同时使用手动后台 placement。
- 有效耗时大于0、不是援护技且动作未配置 `can_interrupt=false` 的步骤可携带 `interrupted=true`、`interrupt_duration_ticks` 和 `interrupt_hit_count`；援护技、前后台0秒动作及真红 `龙e` 在前端不显示打断选项，服务端与模拟器也会忽略旧数据或手工请求中的打断字段。打断时长最短1 tick，最大为该步骤当前普通或脱手形态的完整时长；段数范围为0至动作原段数。模拟器按 `action_hit_profiles.json` 的累计节点改写本次动作倍率、回能、环合、倾陷和命中段数，不能按“选择段数 / 总段数”直接等比例换算；0段不产生动作命中事件。完整段数必须精确回到 `actions.json` 的当前聚合总值。只有腾讯表中能明确对应的逐段行可标记 `tencent-sheet`；逐段原值无法核实时允许使用聚合均分兜底，但必须标记 `aggregate-fallback`。
- 打断动作的时间轴条使用红色边框，样式优先级高于0秒Q遮罩和后台虚线边框；选择态仍可在红框外显示独立轮廓。
- `action_hit_profiles.json` 只收录具备打断资格且伤害段数大于0的动作，不统计援护、前后台有效0秒动作或显式禁用打断动作的逐段缺口。按用户 2026-08-20 确认简称映射和固定重复次数后，当前收录动作已全部具备腾讯表逐段配置，不再存在 `aggregate-fallback`；海月 `水母弹/水母闪反` 暂不支持打断。
- 旧安魂曲动作 ID 在服务端规范化和浏览器本地草稿加载时迁移：旧 `a4脱手` 变为 `a4远 + detached=true`；旧 `a4闪` 展开为 `a4远 + detached=true`，并在 5 tick 后追加同角色通用「闪」。
- 援护触发环合时，前一前台角色不足100环合仍生成对应环合实例，并消耗其全部现有环合至0；自检警告同时展示“当前值”和“距100不足值”。自由援护等明确绕过环合消耗的机制继续沿用原规则。
- 前台状态一定覆盖动作左端点；由于后续动作可以在当前动作结束前开始，前台状态不保证覆盖动作右端点。
- UI 用特殊背景色标识前台状态区间；动作条本身仍显示原动作时长。
- 部分动作或 buff 可以读取“动作开始时是否为前台”“命中时是否仍为前台”“持续期间前台是否切走”等条件。

资源模型预留两层：

| 资源 | 作用 |
| --- | --- |
| 角色能量 | 每名角色独立获得和消耗；上限取该角色终结技的能量需求，溢出部分浪费 |
| 个人资源 | 每名角色独立资源，名称和上限按角色定义，第一版只预留字段 |

动作资源规则：

- 战技没有能量要求，只受 CD 限制。
- 终结技有能量要求；能量不足时不能开始。
- 耗时大于0的动作在其计算持续 tick 内均匀提供动作回能；动作起点不再一次性获得全部回能。动作被 Q 遮罩并压缩计算时长时，总回能不会减少，而是在遮罩前剩余的有效 tick 内重新均分并全部结算。
- 0秒前台 Q 与被遮罩动作结束在同一 tick 时，先结算 Q 的瞬时耗能，再结算该 tick 的动作回能；因此释放 Q 的角色仍可收到队友的回能分享，但该 tick 的分享不能反向用于满足本次 Q 的能量门槛。
- 0秒动作没有可分摊的持续区间，仍按同 tick 内部结算顺序即时提供动作回能。
- 多个动作的回能区间重叠时，各自按 tick 独立累积后求和；每次流入仍受角色能量上限约束。
- 角色能量不能超过自身上限；初始能量和动作回能超过上限的部分不会保留。
- 真红进入“升腾之赤”后能量上限变为 12，龙 E 消耗 12 能量；退出该状态时清空自身能量。
- 所有角色的环合值上限均为 100，动作产生的溢出环合值不会保留。
- 普攻、援护、特殊动作可以有 0 能量、0 CD，也可以产生能量或个人资源。
- 动作定义预留 `personal_resource_cost`、`personal_resource_gain`、`personal_resource_required`，用于后续角色机制。

动作定义建议：

```json
{
  "id": "zhenhong_e",
  "character_id": "zhenhong",
  "action_type": "E",
  "duration_ticks": 0,
  "cooldown_ticks": 120,
  "energy_cost": 0,
  "energy_gain": 8,
  "personal_resource_cost": {},
  "personal_resource_gain": {},
  "triggers": ["zhenhong_e_buff"]
}
```

## 在线市场数据模型

现有数据库使用 Peewee + SQLite。建议新增模型：

### `ShaftAxis`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | AutoField | 主键 |
| `owner` | ForeignKey(Player) | 上传者 |
| `title` | CharField(80) | 标题 |
| `description` | TextField | 简介 |
| `visibility` | CharField | `public/private/unlisted`，市场只展示 public |
| `source_version` | CharField | 该轴最近一次保存时使用的数据版本，例如 `异环云配队 1.0.4`；应用启动或版本发布不得批量改写历史轴 |
| `team_json` | TextField | 4 人队伍与构筑摘要 |
| `axis_json` | TextField | 轴步骤 |
| `enemy_json` | TextField | 敌人配置 |
| `result_json` | TextField | 最近一次计算结果快照 |
| `duration_ticks` | IntegerField | 轴长 |
| `direct_damage` | IntegerField | 直伤排序与总览缓存 |
| `stagger_damage` | IntegerField | 倾陷伤害排序与总览缓存 |
| `total_damage` | IntegerField | 总伤害排序用缓存，等于直伤 + 倾陷伤害 |
| `dps_x100` | IntegerField | DPS * 100，避免 SQLite 浮点排序误差 |
| `like_count` | IntegerField | 点赞缓存 |
| `dislike_count` | IntegerField | 点踩缓存 |
| `favorite_count` | IntegerField | 收藏缓存 |
| `dedupe_hash` | CharField(64) | 发布去重 hash |
| `share_token` | CharField(64) nullable unique | 私有轴的随机分享凭证；首次分享生成并复用，删除原轴后失效 |
| `forked_from` | ForeignKey(ShaftAxis) nullable | 二次发布来源 |
| `created_at` | DateTimeField | 创建时间 |
| `updated_at` | DateTimeField | 更新时间 |
| `published_at` | DateTimeField nullable | 公开发布时间 |

`visibility = private` 表示玩家保存自己的排轴但不上传市场；`visibility = public` 才进入市场。保存私有轴和上传公开轴都使用同一张表，避免草稿和市场轴来回转换时丢字段。

每个玩家最多保留 50 个 `private` 排轴。新建、另存、备份和从广场保存副本都受该限制；更新或覆盖已有私有轴、创建或更新关联的公开快照不增加私有轴计数。服务端在同一数据库事务内计数并拒绝第 51 个私有轴。

发布去重：

- 二次发布时必须计算 `dedupe_hash`，公开市场中已有相同 hash 时拒绝上传。
- hash 的规范化输入只包含动作轴、角色选择、弧盘选择、卡带选择。
- `detached` 会改变动作占用时长，属于动作轴 hash 的规范化输入。
- hash 不判定具体练度，不包含副词条词条数、觉醒、角色等级、弧盘等级、buff 开关、标题、简介、作者、点赞、收藏和计算结果。
- 规范化时需要排序 JSON key、统一 tick 整数、去掉临时 step id，避免同一轴因为前端随机 ID 不同而绕过重复判断。

### `ShaftAxisCharacter`

用于市场按角色筛选，不只靠 JSON LIKE。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `axis` | ForeignKey(ShaftAxis) | 轴 |
| `character_id` | CharField(64) | 角色 ID |
| `slot` | IntegerField | 队伍位置 |

索引：`(character_id, axis)`、`(axis, slot)`。

### `ShaftAxisLike`

点赞必须登录。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `axis` | ForeignKey(ShaftAxis) | 轴 |
| `player` | ForeignKey(Player) | 玩家 |
| `created_at` | DateTimeField | 时间 |

唯一索引：`(axis, player)`。

### `ShaftAxisDislike`

点踩必须登录；同一玩家对同一轴的赞、踩互斥。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `axis` | ForeignKey(ShaftAxis) | 轴 |
| `player` | ForeignKey(Player) | 玩家 |
| `created_at` | DateTimeField | 时间 |

唯一索引：`(axis, player)`。

### `ShaftAxisFavorite`

收藏不要求登录。表结构建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `axis` | ForeignKey(ShaftAxis) | 轴 |
| `player` | ForeignKey(Player) nullable | 登录玩家 |
| `visitor_key` | CharField(64) | 未登录收藏的浏览器标识 |
| `created_at` | DateTimeField | 时间 |

唯一性：

- 登录收藏：唯一索引 `(axis, player)`。
- 未登录收藏：唯一索引 `(axis, visitor_key)`。
- `visitor_key` 由前端保存在 localStorage，首次收藏时生成；登录后可以选择把匿名收藏合并到账号。

### 可选：`ShaftAxisRevision`

如果希望保留玩家修改历史，增加 revision 表；第一版可以暂缓，只在 `ShaftAxis` 保存最新版本。

## API 草案

公开页面：

- `GET /shaft`：默认进入排轴页。
- `GET /shaft/build`：配装子页面。
- `GET /shaft/rotation`：排轴子页面。
- `GET /shaft/market`：市场子页面。

只读 API：

- `GET /api/shaft/catalog`：角色、动作、弧盘、卡带、buff、公式版本。
- `GET /api/shaft/market`：市场列表。参数：名称或备注关键字 `q`、`character_id`、`sort=dps|likes|new`、`page`、`page_size`。带 `q` 的搜索请求按登录账号、访客标识或来源 IP 限制为 3 秒一次；超频时返回 `429`、`code=shaft_market_search_rate_limited` 和 `retry_after_ms`。
- `GET /api/shaft/axes/<axis_id>`：轴详情。
- `GET /api/shaft/shared/<share_token>`：通过不可枚举 token 读取私有轴的最新已保存版本；未登录访客返回 `read_only=true` 并进入只读查看，登录接收方加载后按独立工作区处理。
- `POST /api/shaft/axes/<axis_id>/favorite`，`DELETE /api/shaft/axes/<axis_id>/favorite`：收藏或取消收藏，登录和未登录都可用；未登录时使用 `visitor_key`。

登录 API：

- `POST /api/shaft/axes`：保存自己的私有轴，或发布为公开市场轴。
- `PUT /api/shaft/axes/<axis_id>`：更新自己的轴。
- `DELETE /api/shaft/axes/<axis_id>`：删除或下架自己的轴。
- `POST /api/shaft/axes/<axis_id>/like`，`DELETE /api/shaft/axes/<axis_id>/like`。
- `POST /api/shaft/axes/<axis_id>/dislike`，`DELETE /api/shaft/axes/<axis_id>/dislike`。
- `POST /api/shaft/axes/<axis_id>/share`：仅所有者可调用；首次生成稳定分享 token，后续返回同一分享链接。
- `GET /api/shaft/me/axes`：我的轴。
- `GET /api/shaft/me/favorites`：我的收藏。

保存时浏览器必须提交由当前 `shaft_engine.js` 刚刚生成的 `result`。服务端校验轴结构、结果结构、必需汇总字段以及有限非负数值，再同步保存结果与 `dps_x100`；`character_ids` 仍从服务端已校验的队伍配置提取。发布公开轴复制已保存的私有轴结果快照，不启动 Node 重算。发布时仍必须计算 `dedupe_hash`，命中重复公开轴则返回明确错误。这个边界优先保证 Windows 服务器无需安装 Node；公开榜单数值属于客户端提交结果，不作为服务端权威防作弊数据。

`source_version` 在创建或更新私有轴时写入当时的当前版本；备份和公开快照复制来源轴的版本。应用启动、静态数据升级和版本发布都不得批量覆盖已有记录，因此卡片展示的是该轴最近一次保存或生成快照时实际使用的版本。

## 前端页面草案

`/shaft` 第一屏应是实际工具，不做营销页。页面拆成三个独立子页面，但共享当前队伍、动作轴、敌人和计算结果状态：

| 页面 | 路径 | 职责 |
| --- | --- | --- |
| 配装 | `/shaft/build` | 选择 4 名角色、弧盘、卡带、觉醒、羁绊、副词条词条数和敌人配置，并查看角色实时面板与总览 |
| 排轴 | `/shaft/rotation` | 0.1 秒动作轴编辑器，包含动作库、时刻线、插入模式、前台状态、动作详情和触发 buff 预览 |
| 市场 | `/shaft/market` | 浏览公开轴、按角色筛选、排序、赞、踩、收藏、读取到编辑器，并管理自己的私有/公开轴 |

配装页：

- 队伍区以 4 个槽位为核心，每个槽位可选角色、弧盘、卡带、觉醒、羁绊和副词条词条数。
- 敌人只配置等级、是否轨外之境和多选弱点，不选择具体敌人。
- 总览分开展示总伤害、角色伤害、环合伤害、倾陷伤害、DPS、轴长和角色自身贡献；角色自身贡献只统计可归属的动作与周期伤害，不包含环合或倾陷伤害。环合与倾陷在贡献占比列表中与角色使用相同的行式布局和分析按钮，并分别打开独立弹窗。

排轴页需要达到参考项目级别的操作密度和可视反馈：

- 左侧动作库按当前槽位、动作类型和搜索词筛选，动作条目可一键加入当前插入位置。
- 中间时刻线使用 0.1 秒刻度；动作条按真实 start/end 放置，0 秒动作有固定视觉宽度并撑开可视时间轴。
- 后台动作默认连续排列在第二行；仅当动作条的可视区间实际重叠时，后出现的后台动作才下沉到第三行。前一个动作的尾端与后一个动作的首端相接不算重叠，不为卡片间距强制交替换行。
- 原生后台动作可以通过动作详情设置同一时刻的重叠动作倍数，取值范围为 1–999；该倍数同步作用于伤害、命中段数、回能、环合及对应动作结算，不改变动作的开始时刻和可视占位。
- 支持插入到当前游标和插入到选中动作之后。玩家可以主动留出空白时间；普通编辑不得自动压缩空白，动作因冲突自动顺延时也必须保留原有空白时长。编辑器应在操作发生时解决冲突，不提供额外的“重排”操作。
- 向已有轴插入0秒前台Q时，先为其固定虚拟宽度整体腾位：插入点及其后的前台、后台动作统一后移相同视觉 tick，保持原有相对顺序。模拟器扣除新增虚拟区间后，这些既有动作的真实计算 tick 不变。
- 批量拖动只改变选中动作组的整体时间位置，并保留每个动作原有的前台/后台状态；单个可转后台的普攻或专用「无」节点在纵向拖动时允许切换前后台。「无」放到后台后不占用前台动作轨道，但仍作为显式切人节点更新当前前台角色。
- 拖拽预览与落点时刻线统一使用模拟器给出的显示起点；动作仍以原始 `start_tick` 保存和计算，但存在时停0秒投影时，红色时刻线必须跟随 `display_start_tick` 与动作卡片对齐。
- 批量粘贴以游标刻度为复制块起点，先按复制块的完整视觉跨度为原轴腾出连续区间，再保持复制块内部的相对时间整体插入；不得让复制动作与原轴后续动作逐个交替。
- 删除动作时只回收本次删除直接释放的连续占位。开启时间晚于全部被删除动作的尾部动作必须使用同一个可行前移量，尽可能保持彼此的相对时间位置，不能优先把被删除动作所属角色的下一个动作拉近；玩家主动留下的其他空白仍保留。若删除被 0 秒前台 Q 遮罩的动作使 Q 的视觉遮罩缩短，还需一并回收缩短的虚拟区间。
- 同一 tick 的前台动作开始冲突需要在模拟结果中产生警告；后台伤害动作可以与前台动作同 tick。
- 点击动作条或明细行会选中动作，并在右侧详情面板展示动作数据、实时面板、单次直伤、倾陷伤害、命中的 buff/debuff 和校验警告。
- 右侧实时面板将最终伤害作为独立乘区展示；仅当当前动作的最终伤害加成为非零时显示该项。
- 前台状态以时间背景色显示；后台伤害动作不切换前台状态。

市场页：

- 市场列表支持按名称或备注关键字搜索、角色筛选和 `DPS / 最新 / 点赞` 排序；搜索条件由后端参与分页查询。前端等待用户停止输入、完成本轮编辑后才提交搜索，不为每次按键立即调用后端；编辑完成时若仍处于 3 秒搜索冷却期，则展示加载态，并在冷却结束后只提交最新搜索词。
- 赞、踩需要登录且互斥；收藏不需要登录，未登录时用浏览器 visitor key 去重。
- 玩家可以保存自己的私有排轴，也可以发布到市场；发布时做去重 hash 比对。
- 私有原轴与其公开快照通过 `forked_from` 关联。首次上传创建公开快照后，原卡片的“上传”改为“更新 / 下架”；更新覆盖同一个公开快照并保留赞、踩、收藏计数，下架删除公开快照及其互动关联但不删除私有原轴。自己上传的公开卡片也提供“下架”。
- “我的排轴”支持按名称或备注关键字、角色和排序组合筛选，标题区域只显示私有轴总数，不显示“已用数 / 50”的限制数。所有排轴卡片显示队伍头像与名称，并始终显示单行备注区域；前端最多读取 64 个字符生成预览，超出卡片宽度时以省略号截断，完整文本仍保存在详情数据中。
- 点击广场排轴卡片时先读取公开快照并打开只读时间轴预览，不替换当前编辑工作区。尚未保存过的非本人公开轴提供“取消 / 保存到本地”；保存会创建新的私有轴，复制公开快照的备注、轴配置和计算结果，把标题改为“原标题 - 作者名”（超出标题上限时优先保留完整作者后缀），并用 `forked_from` 记录公开轴来源。再次预览同一公开轴时按钮改为“更新到本地”，更新原私有副本而不重复创建；旧版未记录来源的副本按既有“原标题 - 作者名”识别，并在首次更新时补写来源关系。
- 排轴标题栏同时提供“保存”和“另存”。“保存”更新当前已保存轴；只有当前已加载保存轴且标题与其最后保存标题不同时，“另存”才启用，并以当前标题创建新的私有轴。
- 未保存工作区首次切换角色时提示该操作会清除不兼容动作；玩家确认后，紧接着连续切换其他角色不重复提示，直到工作区再次保存或载入为干净状态。
- “我的排轴”卡片提供分享按钮，成功生成链接后自动复制到剪切板。分享链接固定进入 `/shaft/rotation`；若浏览器已有未保存工作区，打开前必须提供“放弃更改 / 保存 / 另存 / 不打开分享”四种选择。未登录访客可以直接读取分享内容，但排轴、配装、标题和备注均为只读，且分享内容不写入或覆盖原有本地草稿；登录接收方载入后清除所有者轴 ID，后续保存只能生成自己的轴，不能写回分享源。
- 角色访问分为 `public`、`invited`、`test` 三级。正式用户只能使用公开角色；`Player.shaft_invited` 受邀用户可额外使用半开放角色；`Player.shaft_test_whitelisted` 测试用户可使用全部受限角色。含受限角色的公开轴只对权限级别足够的账号可见，限制由服务端统一应用于市场列表、收藏列表和公开轴详情；权限不足时直接访问轴 ID 按不存在处理，且不能发布对应私有轴。
- 角色访问级别保存在共享数据库的 `ShaftCharacterPublication.access_level` 中，网站与机器人插件使用相同表结构但不互相导入代码。NoneBot `SUPERUSERS` 可通过私聊命令 `公开角色 <角色名>` 将角色全局提升为公开；操作同步写库，重启后继续生效。残虹当前为公开角色，灵可为测试角色。
- 随机分享链接属于私有轴的显式持有者访问入口，不套用公开市场的测试角色可见性过滤；未登录访客仍只能只读查看，不能借此保存、发布或获得测试角色构筑权限。

## 前后端计算边界

参考项目的排轴体验要求编辑器在本地即时响应，不能把后端当作实时布局引擎。因此本模块采用“本地编辑投影 + 低频权威计算”的架构：

- 排轴编辑、拖拽、多选、复制粘贴、撤销重做、插入动作、切换前后台、敌人和配装输入，全部先修改浏览器内的 axis draft，并立即写入 `localStorage`。
- 前端本地投影只负责时间线显示、0 秒动作最小宽度、动作自动位移后的预览、前台背景、选择状态、动作详情的静态字段和草稿持久化。
- 公式计算代码只有一份，位于 `app/modules/shaft/static/js/shaft_engine.js`。浏览器直接调用这份引擎；Node 包装脚本 `scripts/shaft_compute.js` 只用于离线回归和诊断。
- 前端本地计算伤害公式、buff 结算、DPS、资源曲线、环合曲线和动作详情；编辑后可以 debounce 本地重算，但不能请求后端试算。
- 不再提供公开 `/api/shaft/simulate` 接口。所有排轴试算都在浏览器内完成。
- 保存私有轴时，前端若结果已过期则先完成本地重算，再把最新 `result` 与轴一起提交；后端只做结构和数值边界校验后入库。上传公开轴复制私有轴的结果快照，保存与上传链路均不要求服务器具备 Node。

## 计算器分层

参考 EndfieldToolbox 的分层，但将公式引擎统一为一份 JS 真源并由浏览器直接调用：

| 层 | 输入 | 输出 | 职责 |
| --- | --- | --- | --- |
| Data Catalog | 静态 JSON | 规范化定义 | 加载角色、动作、装备、buff、常量 |
| Local Editor Projection | axis draft | 本地时间线和脏状态 | 完成布局预览、选择、拖拽、撤销重做和草稿保存 |
| JS Calculation Engine | catalog + axis draft | `SimulationResult` | 常驻面板、时间线编译、buff、伤害、资源、DPS 和动作详情的唯一公式实现 |
| Backend Persistence Adapter | axis draft + client result | DB rows | 校验轴与结果结构、写入结果及市场字段、计算 hash 和角色索引 |

### 失谐与破鞘（2026-09-18）

普通敌人倾陷上限70，轨外之境50。每次新施加黯星或浊燃时，若另一状态仍有效，触发1次失谐；黑羽续生黯星同样参与，单纯浊燃加层不重复触发。每次失谐削条量为当时倾陷上限×15%。敌人等级高于触发角色且等级差不超过5时，该削条减半；等级差大于5时，削条只有基础的20%。敌人等级不高于角色时保持完整15%。2026-09-24 起按用户口径替换此前的 20%÷(等级差+1)。不改变既有单次倾陷伤害基数与其他环合伤害公式。

达芙蒂尔「破鞘」在每次失谐额外削减初始倾陷上限的10%，该额外削条不受等级差影响，即使已有2层也生效；随后将倾陷上限降低初始上限的10%，最多2层（普通最低56、轨外最低40），持续30秒、再次触发刷新。先按触发前上限结算本次失谐，再更新上限。降低倾陷上限只影响削条与倾陷频率，不降低单次倾陷伤害；伤害基数与可变倾陷上限独立。上限削减机制来自Everness核实的「破鞘」，叠满仍额外削条及不受等级差影响来自本次补充。

排轴仍按整轴倾陷频率估算伤害，不模拟敌人实时倒地：动作和失谐分别按发生时有效上限折算为等效削条量，频率使用「初始上限÷等效削条量＋恢复时间÷轴长」的倒数。`total_stagger`记录实际削条总量，`effective_stagger`用于频率；`dissonance_events`列出每次失谐、破鞘额外削条、层数与上限前后值。循环预热仅继承仍有效的破鞘上限削减，不重复计入上一轮削条量。安魂曲400%「失谐强化」仍按原有手工后台动作处理。

验证：`python3 -m unittest tests.test_shaft_dissonance`，以及完整排轴回归。

破鞘的倾陷上限削减同时等比缩短恢复时间：0/1/2层为基础恢复时间的100%/90%/80%，默认10/9/8秒；最后一朵玫瑰固定加算3秒且不被缩短，最终为13/12/11秒。整轴频率使用各状态在真实轴长中的时间加权平均基础恢复时间，再加算玫瑰的3秒，计入30秒到期恢复和循环继承；单次倾陷伤害不变。此恢复比例来自本次补充口径。

### 六属性同频退役与旧轴兼容（2026-09-18）

### 灵可前台命中协频Buff（2026-09-19，覆盖此前按动作相邻关系推断窗口的实现）

按用户本次明确口径，灵可E在命中结算时仍处于前台，且实际命中段数大于0，才触发持续0.1秒的「协频判定」Buff。E使用聚合动作的命中结算点（时停覆盖时按压缩后的实际结束点），以 `action_hit` 的 `timing=end` 区分通常在开始点处理的命中事件；`source_foreground_at_hit` 检查命中时的前台。新普通动作在同一边界接入不会反向取消已完成命中；灵可自己的0秒时停选人在该边界先确认前台归属。0段打断或命中时已在后台不生成窗口。

### 卡厄斯延滞自动结算（2026-09-19）

### 配置化延时伤害与环合重施（2026-09-21）

明音凛使用通用配置扩展，未在主流程分支写角色ID：`initial_personal_resources_by_awakening_count` 只在非循环入场按觉醒数量授予资源；`activation.personal_resource_gain_per_hit` 根据实际保留命中段数获取资源；`personal_resource_cost_on_hit` 使0段打断不支付指定动作的资源成本。`activation.heal_base_atk_ratio` 输出基于角色和弧盘基础攻击的回复事件。
