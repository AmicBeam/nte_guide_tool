# 五套 Gumbel 搜索学习的策略恢复方案

状态：2026-09-24 阶段一已在本机归档对局上跑完，**未续训、未替换网站模型**。现行规则与实际运行顺序仍以[训练手册](duel-v2-public-training.md)和[完整报告规范](duel-v2-full-training-report-spec.md)为准。本方案针对五套 `cross_five_grounded_wdl_v1` 的 P0 退化；数值来自已归档的 [`five-cross-20260924`](../artifacts/rl-evals/five-cross-20260924/formal/report.md)，不是通用训练阈值。用户已指定的硬截止仅约束原运行，不自动授权新任务延长或重启。

阶段一记录在 `artifacts/rl-evals/policy-recovery-20260924/`。366 局训练 episode 按根种子整对划分，163 个种子都含双方先手，标签错位 0。真红策略梯度进入 `cand_net`、`score` 和 `state_net`，范数有限且非零。同一迁入起点上：A（`3e-5`、67 次混合更新）留出出牌 top-1 仍是 0；B 把策略行遍历提到 8 次后 top-1 到 6.9%，交叉熵下降 0.05，未过预检；C 在 4 次遍历下 `1e-4` 为 11.0%，`3e-4` 和 `1e-3` 跳到约 62%，超过目标 37.3% 的 ±10 个百分点。D 在同样 `3e-5`、4 次遍历下，无论把候选网络恢复正常幅度还是加原始类别／卡牌残差，都未过预检。

随后只在 1e-4 与 3e-4 之间再取 4 个学习率，选择集仍是原来的留出种子。唯一进预检带的是 `1.8e-4`、4 次策略遍历（出牌 top-1 47.2%，交叉熵下降 0.107）。确认种子在选择之前就从拟合里拿开，没有参与这次挑选。同一设置在确认集上五套都未过闸：真红 49.6% 对目标 39.4%，交叉熵只降 0.084；创生 13.0% 对目标 49.1%；覆纹 84.6% 对目标 61.2%；快攻 97.6%、浊燃 98.4%，已经贴着「永远出牌」。因此这组学习率不能写入正式训练。五套脚本已接入首批、中段、末段闸门和 P0／`best` 回退，但正式 `--run` 在没有实测吞吐排进这些闸门时直接拒绝。没有新的自博弈。

接着用同一批归档对局、同样 4 遍策略行，以及预先写明的 `1.5e-4` 和 `1.8e-4`，把动作类别与类别内的牌或行动者拆开打分，并和原耦合打分对照。放行要求同一个学习率上创生、覆纹、真红同时减少「攻击被改判成出牌」和「结束回合被改判成出牌」，并提高目标出牌时同一张牌的命中；总体出牌比例不算通过。两个学习率都没有满足。同一张牌命中上升的对照，两类误判也在上升。快攻和浊燃仍然没有原选择集的行。这个分层头不接入训练器，也不为它采集确认对局。记录在 `artifacts/rl-evals/policy-recovery-20260924/offline-diagnosis/factored-score/`。尚无新的独立确认数据。CUDA 短测和正式长训继续关闭。

## 决策：保留 Gumbel，也保留可学习的基础策略

保留「公开信息 → 网络给出合法动作先验与 WDL 价值 → Gumbel 搜索选动作 → 完整终局回传 → 网络学习搜索改进策略与真实胜负」的链路。当前是网络没学会排序，不能把 Gumbel 当成不需要基础策略的独立 AI。它依赖网络先验选择有限根候选，也依赖价值估计处理没有搜到终局的分支；本项目根候选上限 16、预算 32，错误先验可能排除关键牌，错误价值也会误导搜索。DeepMind 的 [Mctx 官方说明](https://github.com/google-deepmind/mctx#search-in-reinforcement-learning)同样将策略先验和价值估计作为有限预算搜索的输入，并把搜索权重作为学习目标；其改进保证以动作价值正确估计为条件，不能照搬成这款不完全信息游戏的保证。

「纯网络 argmax」不一定要成为最终上线动作模式：若网站真的能承受每次搜索，可以让 Gumbel 负责最终选动作。但纯网络仍是搜索的先验、模拟中的对手策略和低延迟回退能力；必须持续测其排序质量，并按训练手册同时报告纯网络与带搜索两张表。当前网站高级人机是 CPU 数值推理，尚未验证 Gumbel 32 的单次操作延迟；不能把离线搜索成绩直接当网站服务能力。

## 已确认的失败位置

- 真红在 3508 个有合法出牌动作的训练根中，搜索实际选牌 1543 次；策略目标给牌约 44% 总质量。随机抽查 350 根，目标 148 次将牌排第一，最终网络 0 次。目标熵 1.324，最终网络熵 2.01971，几乎等于均匀分布 2.01971。
- 同一批最终候选表示上，仅重新拟合最后线性层，即使加大本机隔离拟合步数，留出根的出牌 top-1 仍为 0。增加一个只在隔离探针中使用的原始动作特征线性头，留出根的出牌 top-1 达到约 32.6%（学习率 0.001）或 60.3%（0.01）；后者高于目标约 40.2%，并非可用策略。这说明原始动作编码含信号，而本轮候选网络没有把它稳定传到排序。该探针冻结了状态／候选网络，不是全网络消融或胜率结论。
- 真红完成 67 次 Adam 更新，学习率 `3e-5`。归档 4608 条策略标签，训练实际抽取 4153 次策略行，但只覆盖 **2342 条独立标签（50.8%）**，2266 条一次没抽到。创生、覆纹、快攻、浊燃的独立策略标签覆盖率也仅约 49%–53%。当前 `EpisodePool` 把策略行和价值行一起均匀抽样，每次 128 行真红平均只有约 62 行含策略目标，时间到即停。
- 对仓库旧三套权重的同构筑研究对照中，新模型纯网络分别 0/128、0/128、19/128；真红和浊燃没有仓库旧权重。旧 `fixed_ten_v1` 模型的规则身份已过期，研究比较采用具名列映射，**不继承服务授权**。这批五套 `latest` 权重为 P0，冻结为失败证据，不作为下一轮默认起点或网站候选。

上述定位是「策略蒸馏失败、候选表示弱、策略样本利用不足」。具体由初始化、学习率、主干结构、目标噪声各占多少，需用下面的同数据消融确认，不能看见一次本机线性探针就直接重写正式训练。

## 阶段一：离线复现与训练接线检查（Windows 离线时可准备）

1. 固定当前失败运行的源码清单、规则／观察／候选指纹、五套构筑及数值 SHA；把冻结评估及用户录像永久排除梯度。按**配对根种子整体**划分归档训练 episode 的拟合与留出；成对先后手不得跨集合。旧结果只供诊断，不自动与下一轮数据混合。
2. 在一批真实 `pi` 行上逐项核对：候选与标签逐列对齐、实际选中动作索引、策略目标和 WDL 终局标签；Torch 与 NumPy 的出牌 logits／WDL 对拍；确认策略梯度进入 `cand_net`、`score`、`state_net`，有限且非零。记录每层梯度范数、输出跨度、类型概率、交叉熵及目标熵。只看总 `loss` 或参数 SHA 变化不算通过。
3. 用同一训练／留出 episode 做有界全网络消融，不改环境奖励：A 复现现有初始化与 `3e-5`；B 只增加策略行的有效遍历与优化步；C 在 B 基础上分别试经预检的学习率；D 若 B/C 仍无法拟合，再比较候选网络正常幅度初始化与原始动作类别／卡牌特征的残差路径。每次只改变一项，网络或特征变更另立 schema 与数值身份，不回写旧权重。
4. 工程通过口径须在启动前写入配置。建议先以本轮留出根为基准：相对近乎均匀的交叉熵至少下降 0.10 nats，出牌 top-1 比例接近目标比例（初始可设 ±10 个百分点），且不同阵容、先后手和选择阶段均无单一「永远结束回合／永远出牌」坍缩。该数值是本项目的**预检门槛提案**，不是论文保证；正式强度仍靠未见对局。总体出牌比例接近目标本身不够：2026-09-24 的离线重放里，出牌类别的总概率几乎不变，交叉熵只平滑下降，argmax 却因为「最好的牌」相对「最好的非出牌」成批跨过 0.05，连目标第一名是攻击或结束回合的决策也被改判成出牌，同一张牌的一致率下降。预检必须同时报告这个分数差、类别一致率和具体卡牌一致率。已看过的确认种子不能再用于挑选后仍称独立确认。诊断见 `artifacts/rl-evals/policy-recovery-20260924/offline-diagnosis/report.md`。

如果全网络在同数据上也拟合不了，先修动作表示或损失接线；禁止靠再跑几小时自博弈掩盖。若 B/C 可以拟合而 A 不行，优先保留原表示、修正样本覆盖与优化量；若只有 D 可拟合，才引入新网络结构。2026-09-24 已用分层动作打分做过这项对照：类别头与卡牌／行动者头分开之后，留出的创生、覆纹、真红没有同时减少误判并提高同一张牌命中，不能换上这个头再开长训。

## 阶段二：保留搜索，改正样本与更新节奏

- 每轮完成的 Gumbel 搜索仍选择实际动作，同时保存 `pi_gumbel`、真实 `selected`、访问分布、根候选覆盖和完整终局 WDL。策略损失优先拟合改进策略，价值损失只用真实完成局的胜／平／负；搜索 Q、过程计数和「打出一张牌」不直接伪装成胜负标签。真红前置／被动人工奖励默认维持 0；不增加「主动出牌奖」。
- 将策略行和价值行分开计数、分别采样。新完整局的每条**有效策略行**先至少参加一次策略更新，再进入有界按局回放；之后按预定的有效遍历次数和最大单局复用量继续优化。建议先比较 1、4、8 次有效策略遍历，连同新增完整局数、独立标签数、重复抽样率与梯度步数报告。不能把反复训练少数胜局算成更多新经验。稀有胜局保留、按局分层抽样与重分析只在对照证明改善后逐项加入；重分析不得读取对手真实暗牌。
- 候选行动的类别/卡牌特征必须在网络数值上分得开；每个冻结检查点都测「有牌可出时出牌 top-1、按类别概率质量、与搜索目标的差异」以及一组新种子完整对局。任一核心队纯网络不再主动出牌、或相对迁入起点/已验证参考显著退化，按训练手册的 **P0** 立即停学并保留恢复点，不继续导出 `latest` 当候选。
- 保持五套 10 个配对每对双先手、内战与每第四轮冻结历史方的计划；一批内权重冻结。训练历史对手只取未被废弃且身份可核验的快照，冻结方不收梯度。不同训练／选择／独立评估种子持续使用共享账本。

## 阶段三：验证「网络学会」与「搜索额外收益」

1. 预先保存 `initial`、阶段 `best`、`latest`，选择集只用于择优，审计集不回灌。先按同规则、同配牌、同推理预算对初始与候选做配对；纯网络出牌机会和胜率不能退化。失败保留初始／阶段最佳，不因参数更新或镜像胜率接近 50% 而晋级。
2. 冻结后分别测 **纯网络 argmax**、**同权重 Gumbel 32**。若要归因于训练，还须让同架构未训练起点也跑相同 Gumbel 预算；「新模型＋搜索」与「旧模型纯网络」是产品组合对照，不能归因为权重提升。五套主表按先手行／后手列逐格执行，真实内战在对角线；逐卡、角色、终结、环合、真红准备→启动→收割和公开录像仍按完整报告规范交付。
3. 仓库当前旧服务模型属于不同 schema 且旧规则指纹不匹配。可以保留具名列研究对照，但只有经过合法规则兼容、网站推理一致性及用户授权的模型才可作为线上基线／发布对象；不能编辑清单的旧验证字段冒充通过。
4. 若产品最终选择在线每步 Gumbel，需在网站目标 CPU 上测换牌、普通回合、选择面板等根的 p50/p95 时延、吞吐与超时降级，给出可接受的等待时间；本轮离线六进程 32 模拟六局约 156 秒，**不是**单次网页动作时延证据。不能只因离线搜索会出牌就把它直接放入网页。超时要可控，不把部分搜索结果标为完整预算。

## 预算与停止

### 同一个 09:00 截止内分段验证

不采用「一波学到 09:00，再第一次看模型」的日程。下一轮一旦获授权，所有阶段共享**同一个**已解析的北京时间 09:00 进程树硬截止，不因某个阶段通过、失败或恢复而顺延。流程为：

```text
规则／CUDA／同数据拟合预检
  → 完整轮转首批与闸门 1
  → 扩展学习与闸门 2
  → 有界巩固与闸门 3
  → 停止梯度、冻结 best、独立完整评估、回传
  → 09:00 硬截止
```

启动前根据**本轮规则、Gumbel 32、根候选 16、相同并行数**实测完整对局吞吐，算出预计可完成的完整轮转批次数。先从总窗口预留 25 格双推理矩阵、详细原始记录／录像、数值模型回传与 SHA 校验的实测耗时，再给评估保留至少 25% 吞吐余量；回传／校验再单留至少 15 分钟。剩余才是含三个闸门的学习窗口。若不足以完成预检、首轮、至少一个中段检查和独立终评，**不启动正式长训**；缩小任务目标需要重新显式标为有界研究，不能叫完整交付。每次启动重新计算实际日期、种子段、截止 epoch 与预计批次数，不沿用上一次的 09:00 日期或八局／格样本数。

| 闸门 | 触发点 | 只使用的证据 | 通过后动作；失败时动作 |
| --- | --- | --- | --- |
| 预检 | 首个正式自博弈批次前 | 冻结规则与权重身份、Torch／NumPy对拍、同数据的**全网络**拟合和独立 episode 留出、梯度及数值健康 | 拟合通过才开始采样；否则修表示／损失，不进入长训。 |
| 1：行为防退化 | 完成首个「10 对各双先手＋镜像」的冻结采样批次并完成更新后 | 专用选择种子的合法出牌根、动作类型／熵／标签交叉熵、每套纯网络配对与能力保持；另核对本批新策略行的独立覆盖率 | 任何核心队仍几乎不出牌、纯网络大幅退化或策略标签未进入梯度，按 **P0** 立即停学、保存根局面和恢复点；不等下一次定时检查。 |
| 2：搜索是否真实受益 | 按启动前预计批次的约三分之一、且至少再完成一个整批后 | 与闸门 1 不重叠的选择种子；先做纯网络配对，合格后才对少量预声明的代表性对手／先后手做**同预算** Gumbel 搜索检查。阶段冻结模型与 `best` 分开统计 | 证据充分且能力保持才晋级 `best`；仅有搜索领先、纯网络仍坍缩则拒绝。弱势但未证实退化可保留原 `best`，在原学习截止内继续一个有界阶段。 |
| 3：是否值得继续学 | 按预计批次的约三分之二，或学习截止前预留的最后一次选择窗口，以先到者为准 | 新选择种子上的初始／`best`／候选纯网络与搜索、真红准备→延滞→盈蓄→后续出击、五套对手覆盖、已见/新策略样本比 | 明显改善才保留候选；退化回退到已验证 `best` 并清除陈旧策略标签。连续两个有效检查没有实质改善时提前停学，转入只评估，不为用满时间而继续采样。 |
| 最终独立验收 | 学习截止时，早于完整评估保留窗口 | 从未用于梯度和上述阶段选择的种子，执行两张 5×5 表、同配牌新旧/镜像/变化对手、逐卡与角色机制、重放隐私、实际权重与 SHA 回传 | 仅按实测全项状态报告；缺局、缺对照或预算到点即写未完成，不能以 `best` 指针或 `full_matrix=true` 代替质量批准。 |

以上「约三分之一／三分之二」按**启动前冻结的预计完整批次数**定位，实际执行只在批次边界切换；若整批耗时比容量预估更长，就提前停学，不抢最终评估预算。三个闸门各有最大墙钟预算与专用种子，不能把中间选择局重复算作最终独立证据。便宜的纯网络检查先做，带搜索的小样本只给通过前置闸门的候选；不在每个阶段重复完整 25 格矩阵而挤光学习与终评时间。`latest`、候选 `best`、旧参考权重各保留实际 SHA 和配牌身份；回退后须重新导出数值并确认下一批确实加载回退版本。

Windows 恢复后先做阶段一的短时拟合预检，再按上述分段日程执行。任何 P0、非有限梯度、标签错位、信息泄漏或无正常终局都立即停止并保存证据；硬截止同时由墙钟与单调时钟守护进程树。单轮产物放 `artifacts/rl-evals/<run-id>/`，不提交 Git；本方案和手册仅记录长期口径。
