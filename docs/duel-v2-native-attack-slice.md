# 无 VM 的普通出击数值样例

`rl/batched_duel/native_attack_slice.py` 是独立 CUDA 实验组件，不接入正式对局、搜索或训练。它使用固定字段数组和直接 C++ 算术，不读取规则字节码，不创建 VM 堆、调用帧或动态属性表，也不提高 CUDA 栈上限。仅复用通用 CUDA 编译缓存与加载器。

## 当前支持边界

输入为双方均使用娜娜莉、伊洛伊、零、九原及该编队顺序的正常行动快照。双方手牌必须为空，角色没有武备、终结状态、持续修正或额外标记，不存在区域效果、待选择或延后动作。入口核验整批后才上传；未知字段和未覆盖状态明确拒绝，不调用 Python 规则代算。

- 对受理输入，GPU 完整生成认输、结束回合、普通出击和终结候选，保持正式引擎的顺序、能量门槛、白热化上限和逐角色终结限次。列出结束回合或终结不表示支持执行它们。
- 出击数值阶段支持支付行动力和机会、无环合入场及换人清盾、前排优先、护盾、同时攻守伤害、双方倒地、玩家生命终局、存活进攻者环合与全队分享能量，以及娜娜莉主动／反击击退后的生牌计数。
- 会实际支付入场环合的出击返回 `UNSUPPORTED_HARMONY`，非法出击返回 `ILLEGAL_ACTION`；失败行保留输入的全部数值。设备另行检查阵营、槽位和整数范围，非法地址返回 `INVALID_STATE`，不进行越界访问。
- 普通出击不给零额外环合。零当前的战斗牌使用后回满机制不属于这个空手牌样例。

输出只包含声明的战斗字段：双方玩家生命、护盾、行动力、普通出击机会、前排和残留来源、家族壮大计数与手牌数量，以及八名异能者的生命、护盾、能量、环合和倒地回合。生牌实体内容、实体分配器、操作身份、事件和回放尚未原生化，不能将数值输出当成完整后继状态。`supports_full_duel_rules` 始终为 false。

## 验证方式

`python -m unittest tests.test_duel_v2_native_attack_slice` 使用同一 C++ 数值函数的本机编译版本，与正式 `legal_actions` 和 `simulate_action` 逐行对拍。覆盖多种白热化阶段、先后双方、护盾、同时倒地、击退生牌计数、自然胜负、资源上限、倒地队友不分享、输入纯度以及拒绝路径。它不代替实机 CUDA 验证。

GPU 验证分别记录首次编译／缓存加载、入口打包、上传、驻留执行、下载及转换；驻留重复执行必须使用相同的不可变输入，避免把逐次耗尽机会的空操作当作吞吐。CPU 正式规则还执行完整状态与事件，因此其整步耗时与本数值样例不是相同工作量，不能直接宣称端到端加速倍数。单轮实测报告留在 `artifacts/rl-evals/`。

## 接入完整搜索前的缺口

Mctx 风格的搜索需要完整且可重复的后继状态。该样例尚缺实体／事件队列、环合、卡牌与响应、终结、回合推进，以及其余队伍的真实角色回调。必须逐项补齐并通过完整状态和搜索轨迹对拍，才可接入联合训练。当前样例只回答直接数值内核的成本，不提供完整对局时间预测，也不证明 400 路 Gumbel 一小时目标已达到。
