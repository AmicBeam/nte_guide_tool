## 1. 范围与文档关系

- 覆盖本轮用户指定的策略与预组，各自训练与报告。文中的创生／覆纹双预组表格是展开示例，实际按本轮策略数生成完整矩阵。
- 使用本轮允许的角色及其合法卡池，角色／卡牌范围和观察编码在启动前固定；衍生牌单独统计。
- 用户指定每套队伍的四名角色及顺序，模型不得选择、替换或重排角色。自身构筑调整只允许更换配牌：每角色 8 张、同名最多 2 张、全队 32 张，始终通过正式构筑校验。
- 首回合抽牌、白热化、终结、环合及其他战斗规则，以[完整手册](everness-item-chain-card-design.md)和对应版本的正式引擎为准。本文不新增游戏规则或卡牌效果。
- 现有命令和依赖见[公开卡池训练](duel-v2-public-training.md)；训练停止口径见[训练结束标准](duel-v2-training-stop-criteria.md)。不增加固定总体胜率达标线，也不把同模型镜像接近 50% 视为收敛证据。
- 具体时间预算、样本预算、停止条件及模型选择方法在实际运行前写入配置；历史任务的时长、截止时间和样本数不得自动沿用。
- 本文指定的完整任务需要在训练后交付分析报告；此前“只保留日志、不自动分析单卡”的默认方式不满足本任务交付要求。

## 2. 训练目标与阶段

具体搜索学习、阶段选择、只评估切换、详细采集和回传步骤统一见[训练手册完整链路](duel-v2-public-training.md#当前训练链路与报告落点)。本节定义必须交付的阶段和矩阵，不把旧双预组PPO实现自动升级为现行完整链路。

| 阶段 | 目标 | 约束与产物 |
| --- | --- | --- |
| A：规则与执行器预检 | 确认规则、公开观察、合法动作、CPU/CUDA 和数值导出一致 | 覆盖公开卡池、首回合抽牌和白热化；失败时不得跳过检查继续训练 |
| B：固定预组出牌训练 | 学习出击、出牌、目标选择、终结、换牌和结束回合 | 两套分别训练；对手包含规则 AI 和冻结历史模型，变化公开角色组合与合法配牌 |
| C：固定角色配牌学习 | 用实际终局结果寻找更合适的配牌 | 冻结出牌策略与评估对手，只更新配牌策略；保留候选变更与评分过程 |
| D：候选配牌下继续学习打法 | 让出牌策略适应选出的合法候选配牌 | 固定该阶段配牌，再更新出牌模型；和原始预组对照，避免把换牌收益与模型变化混淆 |
| E：冻结独立评估 | 判断模型、配牌和先后手表现 | 固定模型、构筑、规则身份和评估配置，不更新参数；生成完整报告及可选录像 |

B–D 可按预先规定的预算交替迭代。训练样本、候选筛选样本与最终独立评估样本分开；不能用最终验收集反复挑选候选后，再把同一批结果称为独立验证。

记录探索策略、动作选择方式（采样或最大分数）、历史对手池组成与更新时机。冻结快照在单段采样期间不更新；如历史池在跨段时发生变化，记录其版本，不能把整轮称为对同一份权重的镜像互搏。

### 2.1 候选构筑以预组阵容为重点（2026-09-16 用户补充）

这里“全部预组”限定为当前公开预组：创生与覆纹快攻。每套预组的四名角色及顺序固定，卡牌允许变化；不因本条将测试角色预组加入公开训练。新增公开预组后应显式扩展采样配置和验收矩阵。

- 候选训练的主要对手按预组阵容均衡分配，覆盖官方原始配牌、当前高级人机实际配牌、显式提供的历史优选配牌，以及该阵容内的随机合法配牌。另保留少量任意公开四人组合检查泛化；默认目标比例为预组阵容 80%、任意公开组合 20%。
- 冻结模型对手为主，规则 AI 为辅；默认目标比例为模型 80%、规则 AI 20%。先完成两套基础出牌策略，再将两者纳入配牌搜索，避免创生搜索期间没有快攻模型。缺少对手模型时必须如实报告，不得把自身模型冒充快攻模型。
- 记录对手模型身份与实际角色阵容、配牌身份两个维度。快攻模型操控随机角色队伍，不等于固定快攻阵容对战；包含快攻四人也不自动等于其实际高级人机配牌。
- 每批候选与原始基线使用共同的对手构筑和配对种子，先后手等量。配对方式须说明是否仅互换位置，不能把相邻种子称为完全相同牌序。
- 训练仅新增按阵容、对手类型、先后手分组的计数与候选评分摘要，不记录逐动作日志。

完整模式采用分级样本预算，而非所有候选都只打 8 场：

| 层级 | 每个候选、每个预组阵容的对局数 | 目的 |
| --- | ---: | --- |
| 搜索／初筛 | 8–16 | 低成本探索，不据此认定最优 |
| 入围复评 | 64–128 | 比较原始基线与去重后的历史候选 |
| 最终候选比较 | 至少 256 | 以足够样本选择少数候选；仍属于筛选集 |
| 独立留出验收 | 单独配置，使用不重叠种子 | 验证已选结果，不再用于挑选候选 |

短测可使用明确标注的小预算，只证明链路可执行。配置与报告必须同时列出计划样本、实际完成样本及预算截断；“最终候选比较”不能称为独立留出验证。

2026-09-17 按用户要求，配牌学习与筛选按四种「预组阵容×先后手」胜率等权平均计分；不另加最差项权重，不设单项回退硬门槛。允许局部退步换取综合得分提升；同分、样本不足或评估不完整时保留基线。指标、门槛与淘汰规则在运行前固定，并保留可复算的分组胜负分子分母。

整轮时限仍约束全部训练阶段及其中候选筛选，不因增加复评而突破用户的总预算。应先预留筛选预算再分配训练时间；预算不足时明确停止或保留基线，不将少量完成的样本冒充完整验收。最终额外评估若单独运行，须单独声明预算和阶段。

### 2.2 起手换牌与针对阵容的开局（用户补充）

- 新训练把起手换牌作为真实策略动作。模型输入为自己的五张起手、双方公开角色与先后手，不读取对方暗牌或牌库顺序；可保留全部，或选择至多三张换掉。
- 换牌发生在首回合通常抽牌和开局异能给牌之前；先暂存换出实例、从剩余牌库抽补，再放回并洗牌，不能立即抽回刚换出的同一实例。双方完成后才开始先手回合。
- 换牌与出牌共享对局结果训练，不使用固定“对快攻一律留某卡”的规则冒充学习。角色输入可见和策略已经学会针对是两回事，后者必须经对照评估。
- 出牌训练也采用预组阵容优先、阵容内变化配牌的对手分布，保留少量任意公开队伍；固定对手模型与自身历史快照分别记录。适应阶段接入另一套基础模型，固定外部模型不得因历史队列轮换而被挤掉。
- 新的换牌 schema 与旧全留模型分开标记。旧权重不会因增加接口而自动学会换牌；转换旧输入权重时新候选特征置零、优化器重建，原训练身份保留。
- 正常训练只保存按对手池和先后手聚合的换牌张数、首动作及胜负计数；具体起手、留换卡牌和逐操作序列只在额外评估中记录。

新增独立开局对照：两套实际构筑各对两套实际预组模型，学习方分别使用“学习换牌”和“全部保留”，共八个单元。两种模式使用相同模型、构筑、种子和先后手安排，对手策略不变；实际角色阵容与权重身份均须记录。至少报告留牌/换出倾向与样本数、首动作、首回合结束按钮前的资源和生命、总第 1–6 回合局势及最终胜率。留牌胜率属于关联，不直接认定卡牌因果强度；未提供校准模型时不生成预测胜率。

新模型的完整报告必须包含此对照，缺少或截断则报告未完成。公开录像不包含私有起手记录。短测仅验证流程；是否优于全留、能否对快攻形成有效开局，仍须新训练与充分样本证明。

## 3. 测试矩阵与“互搏”的定义

下列测试覆盖两套原始预组和最终选定配牌。独立评估使用冻结权重、独立种子和先后手交换；每个测试单元分别报告，不能仅汇总成一个总胜率。

| 测试 | 配对方式 | 必须回答的问题 |
| --- | --- | --- |
| 对固定规则 AI | 两套学习方分别对战使用两套官方预组的规则 AI，形成 2×2 配对 | 固定对手下的先后手胜率与平均回合数 |
| 对变化规则 AI | 规则 AI 使用公开角色组合与变化的合法配牌 | 是否适应变化构筑；按角色组合及构筑分组的结果 |
| 对变化模型对手 | 多个冻结历史 checkpoint，配合变化的合法构筑 | 是否只针对某种策略；按对手权重、队伍和配牌分组 |
| 训练期间互搏 | 学习方持续更新，对战冻结历史模型池 | 两套学习方随训练进度变化的先后手胜率；规则 AI 样本另列 |
| 同模型镜像互搏 | **双方权重 SHA 完全相同、构筑及角色顺序完全相同**；每套各自测试 | 实际先手方、后手方的胜率，观察座位差异 |
| 交叉互搏 | 创生模型与覆纹快攻模型分别使用自身构筑 | 创生先手/后手、覆纹快攻先手/后手的胜率与回合数 |
| 配牌替换对照 | 原始配牌与候选配牌使用相同出牌模型、对手集合及配对种子 | 更换卡牌本身带来的差异 |
| 新旧模型对照 | 新旧权重使用相同构筑和评估条件 | 出牌策略是否改善或退化。相对仓库已有同契约策略大幅变差，或纯网络在有牌可出时不再出牌，按训练手册记为 P0，报告不得把该权重写成改进或可交付 |

同模型镜像不得用“最新模型对历史模型池”代替。镜像报告根据每局实际 `first_side` 与胜者统计先手方获胜，不能把固定玩家 A 的胜率当成先手方胜率。交叉报告标注套牌和先后手两个维度，同一局从双方展示时不得重复计入独立对局总数。

变化对手测试至少覆盖当前公开角色中全部 15 种无序四人组合；角色顺序与配牌版本另作维度。不能把同一组合的不同排列当成新增角色组合。

配对记录包括种子、模型/构筑版本和先后手安排。相同数值种子不保证 Python 与编译执行器获得相同随机序列；编译配牌评估中相邻偶/奇种子也不等于相同洗牌。报告必须写明实际配对方式。

## 4. 最终报告必含内容

### 4.1 摘要、身份与胜率总表

- 两套最终出牌模型、原始预组、选定候选配牌及各自版本/哈希。
- 规则哈希、观察 schema、奖励配置、训练起点、更新次数、运行预算、停止原因和编译档位。
- 第 3 节每个测试单元的总胜率、先手/后手胜率、胜负平局数、异常数、截断数与平均回合数。
- 训练内统计与冻结独立评估分别展示；先后手胜率随更新次数或训练时间的变化分套牌、分对手类型绘制。
- 区分“正常终局”“预算截止”“失败停止”“平台期”；无数据的项目写明原因和待补项，不以 0 代替缺失。

### 4.1.1 必须提供先手×后手二维胜率表

完整报告必须提供本轮各套牌直接对战的 **N×N胜率矩阵**，包括对角线内战。N为本轮实际套牌数。创生、覆纹、快攻、真红四套为16格；本轮明确包含浊燃且采用统一观察契约时为25格。娜白零伊不进入现行主表；旧标量五套表不能混作本轮五套表。纯网络和带搜索分别成表。

- 对每套实际权重逐张量与本轮初始权重比较并记录结果；未变化或无法核验的策略不得仅因输出目录名而标为新模型。存在此类策略时明确标记主表身份限制，不能称为全套新模型互搏完成。
- **主表双方均为本轮新模型**，使用预先选定并冻结的checkpoint及配套构筑。旧陪练／历史模型的对照成绩只列附录，不混入主表，也不抵扣新版互搏的N×N覆盖。新版交叉对战或内战缺失时，主表明确标记未完成，不交付旧陪练矩阵作为替代。
- **行＝先手套牌，列＝后手套牌；每格一律显示行方（先手方）胜率。** 标题明确写“先手胜率”，格内显示 `胜率%（先手胜局数/正常完成局数）`。
- 非对角线 `(A,B)` 是A先手对B后手；`(B,A)` 是B先手对A后手，是交换先后的另一批对局。两格不要求相加等于100%，不得用 `1−(A,B)` 填写 `(B,A)`。
- 对角线 `(A,A)` 是同模型、同构筑、同角色顺序的内战，显示实际先手方胜率。必须真实测试，不能固定填50%，也不能用新模型对旧模型的结果代替。
- 同一张矩阵内，每套牌固定自身模型SHA、构筑SHA和规则版本。需要比较原方案、候选或不同搜索预算时分别给矩阵，不在一张表内混合版本或推理模式。主表采用网页实际使用的推理模式，搜索模式另表展示。

格式示例（仅说明读法，非实测数据）：

| 先手＼后手 | 套牌A | 套牌B | 套牌C |
| --- | --- | --- | --- |
| 套牌A | A内战先手胜率 | A先手对B的胜率 | A先手对C的胜率 |
| 套牌B | B先手对A的胜率 | B内战先手胜率 | B先手对C的胜率 |
| 套牌C | C先手对A的胜率 | C先手对B的胜率 | C内战先手胜率 |

每局根据真实 `first_side` 解析行方和列方，不把引擎固定A侧当成先手。先手胜率＝`winner == first_side` 的正常终局数／该格全部正常终局数；平局进入分母但不算胜，平局率另记。每局只进入一个单元格、只计一次，内战也不能同时按两个视角重复累计。

在运行前配置每格样本和先后交换的配对种子。对角线同样轮换引擎座位与先手标记，检查座位偏差。未执行、零正常完成或未达到预定覆盖的格子明确标为“未评估／未完成”，不能填0%或50%冒充结果；截断、异常与排除数单列。

同时保存机器可读的 `first-second-winrates.csv` 或同等JSON：行／列套牌ID、模型／构筑SHA、推理模式、计划局数、尝试数、完成数、先手胜／后手胜／平局、异常／截断数和先手胜率，能从逐局记录复算。矩阵与原始记录一起放在 `artifacts/rl-evals/<run-id>/`。

### 4.2 构筑调整过程与理由

每个候选版本保留：

| 字段 | 要求 |
| --- | --- |
| 版本关系 | 候选 ID、父版本 ID、迭代/更新时间、固定角色及完整卡牌数量表 |
| 变更 | 换出和换入的卡牌 ID、名称、数量；相对父版本和原始预组的差异 |
| 条件 | 出牌模型、对手模型/构筑集合、规则版本、配对方式、评分集身份 |
| 结果 | 调整前后先后手胜率、样本量、平均回合数、异常/截断及各类对手的退化情况 |
| 决定 | 保留、淘汰或证据不足；关联评分、对照报告与典型对局 ID |
| 理由 | 数据支持的解释及其限制，不能编造模型的内心推理 |

“该卡打出后胜率较低”只能作为候选调整线索。劣势时更常使用某张牌、长局有更多机会抽到/使用某张牌等因素会影响关联统计。主要依据应是相同条件下的替换对照，辅助参考抽到率、使用率、效果与对局样例。

按实际保存的数据展示已评估候选；不得把未保存的搜索过程事后补写成完整轨迹。最终称为“本轮评估中表现最佳的套牌”，不宣称全局最优。最终测试集不得参与候选筛选。

### 4.3 最终选定套牌的逐卡分析

主逐卡胜率必须来自模型互搏，不能使用规则 AI 对局代替。最终同模型、同构筑镜像为主表来源，校验双方模型 SHA 和完整构筑一致；交叉互搏按对手单列，规则 AI 只作独立诊断，不混入主表。镜像统计双方，按实际先后手归组：64 场有 64 个先手与 64 个后手观测，但仍是 64 场（配对种子时为 32 对），不能当作 128 场独立样本。未携带或未使用的卡标为无对应样本，不能声称覆盖全部候选卡池。

两套分别以原始预组作对照，按先手、后手拆分每张卡的数据：

- 携带张数、抽到率、成功打出率、平均成功打出次数。
- 抽到该卡的对局胜率、成功打出该卡的对局胜率，各自的分子、分母及样本量。
- 首次成功打出的平均回合；成功使用该卡的对局平均结束回合数，并给出套牌整体平均回合数。
- 可明确归因的效果、常见配合、使用时机和典型对局索引。
- 主牌组卡、起手牌、正常抽取、检索/回收、自动响应、生成牌和临时复制分别标记来源；不能将生成或复制使用混成原卡的抽到率。

“卡牌参与”须明确是携带、见到/抽到还是成功打出，不能只给一个没有分母说明的胜率。相同卡在同局多次使用时，胜率按 `game_id + 出牌方 + card_id` 去重，使用次数另计。

### 4.4 每回合预测胜率曲线（有可靠预测能力时）

- 原始价值网络分数及经过过程奖励训练的回报估计，不直接映射或标注为胜率百分比。
- 若提供胜率预测，须在独立数据上验证概率校准，并记录预测模型身份、目标定义及评估结果。训练/筛选数据不得冒充校准验证数据。
- 在统一的回合边界采样，例如回合开始规则结算完成、玩家尚未行动时；从被预测玩家的合法可见信息计算。
- 两套牌分别提供先手、后手每个全局回合的平均预测胜率；可另分最终胜局、负局展示。
- 每个回合显示仍在进行的对局数及不确定性。结束的对局不能随意填值延长曲线；晚回合仅剩长局，须标明样本构成变化。
- 若尚无可靠概率预测，明确写“未提供经校准的预测胜率”；可替代展示玩家生命、资源等局势指标，不伪造概率曲线。

### 4.5 终结技能与环合专题

按套牌、角色、先后手和对手类别分别统计：

- 达到使用条件的情况、实际发动次数/使用率、首次使用回合及每局平均次数。
- 达到条件但未使用的情况；“可使用机会”的计数单位预先固定，不能按每个决策帧重复累计机会而不说明。
- 终结的发动者、实际效果、持续状态及其结束情况。
- 环合类型、提供者、受益角色、触发次数及效果。
- 能明确关联到来源事件的伤害、治疗、护盾、资源等直接收益；延迟效果按来源追踪，不能重复计入多个来源。
- 使用后的胜负关联，以及典型成功、失败、机会浪费的对局。

直接效果、胜负关联与因果收益分开表述。要声称“使用终结/环合提升了多少胜率”，需要额外设计对照；没有对照时不作该结论。

### 4.6 对局索引与录像

报告关联模型、构筑、对阵类别、先后手、结果、回合数和 `game_id`。用户可从报告选择一局，将该局已记录的公开事件导出为网站可播放录像，不重新随机模拟另一局。

公开录像隐藏双方未公开手牌、牌库顺序、私有检视候选和随机种子；完整私有记录留在分析产物中，不写入公开录像。

## 5. 统一统计与解释规则

1. 胜率默认 `胜局数 / 正常完成局数`，正常完成局数包含平局。另报平局率；如采用平局计半分，必须另列为不同指标。
2. 异常、非法动作、崩溃和预算截断不算正常终局，不进入胜率分母；必须同时展示尝试总数、完成数及排除数，避免选择性展示。
3. 平均回合数按双方交替的**全局回合**计算，以正常终局为样本；若另报各方行动回合数，应使用不同名称。截断局另报停止时回合。
4. 每张表注明模型、构筑、规则、策略动作选择方式、种子/样本集与计数单位。低样本标记证据不足，不仅展示百分比。
5. 样本量、配对方式、对手比例、停止条件、候选选择规则和统计方法在运行前固定。差异不明确时按预定方案补样本；不能只追加到获得期望结论为止。
6. 配对局、同一历史模型及同一训练阶段的样本有相关性；报告不确定性时说明方法，不能把重复关联样本都视作完全独立证据。
7. 训练内胜率对应正在变化的策略和采样分布；独立评估对应冻结策略。两者不得混算或直接当作同条件的提升幅度。
8. 未达到某张牌或机制的使用覆盖，不意味着该牌/机制弱；功能覆盖、实际使用与策略强度分别验收。

## 6. 记录开销、输出与交付

### 正常训练

只保留训练标量、按套牌/对手类型/先后手分组的终局胜负计数、完成/截断/异常数、构筑候选变更与评分摘要、checkpoint 和进程状态。计数跨采样段保持一致，逐局只记一次终局，避免重复 reset 或跨段遗漏。

训练期间不常驻记录逐步操作、完整局面或生成录像。构筑变更记录是每个候选的轻量记录，不是对局动作日志；新增统计需测量开销，避免逐动作同步 CPU/GPU 或同步磁盘写入。

### 指定评估轮

### 必交付文件

- 人类可读的 Markdown 总报告：两套结果、完整测试矩阵、构筑调整、逐卡分析、机制专题、曲线可用性和限制。
- 机器可读的汇总表及候选变更记录，附字段含义、分母和去重规则。
- 两套选定出牌模型、合法候选配牌、原始预组对照和完整版本/哈希清单。
- 私有原始评估记录、公开对局索引和可按需导出的录像。
- 未完成项目、异常、证据不足项及下一步验证重点；不能在缺项时将整份报告标为完整。

**交付位置要求：最终报告、选定数值模型及原始评估资料必须实际传回 Mac 的 `artifacts/rl-evals/<run-id>/`，仅留在 Windows 不算交付完成。逐文件核验SHA，并注明实际保存位置；不能以模型清单替代权重回传。**

权重、优化器、完整训练/评估产物留在 `artifacts/` 或对应远端任务目录，不纳入 Git。只提交长期规范与实现文档，不提交单次运行报告或其汇总。模型训练完毕或报告生成不自动批准发布，也不自动覆盖网站高级人机和玩家保存的构筑。
