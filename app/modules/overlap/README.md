# 合轴收益表

第四个独立工具模块，入口 `/overlap`，按用户要求仅通过直达链接访问，不在工具主页提供入口卡片。首版支持安魂曲远程、残虹现实/幻境、黑羽魔女形态与明音凛；主要统计普攻、重击，黑羽额外统计魔E衔接，安魂曲额外统计普通E衔接。角色按用户指定时间顺序展示：安魂曲、残虹、黑羽、明音凛，不按属性排序。

用户2026-10-12要求只显示至少两个动作的路线，离线生成通过 `min_route_actions=2` 排除所有单动作候选（包括单动作切人和基准），动作衔接目录仍保留。下拉选项与计数只反映保留的路线，不提供“单动作”筛选。

原收益表分页读取已生成的静态 JSON，只做角色选择、筛选、排序与展开，默认按“倍率 / 占轴最高”从高到低排序。“首个动作”“收尾动作”通过下拉框精确筛选路线中实际的第一个/最后一个动作，选项只从当前角色已生成的合法路线提取；选择首个动作后，收尾选项联动为该起手可到达的合法收尾，切换角色时更新选项并清除不再合法的选择。“是否回场”可查看全部、回场、不回场，并可进一步筛选“回场（两人合轴）”或“回场（需三人合轴）”，与路线类型、闪替代和排序组合，不再提供自由文本动作搜索。展开明细显示在对应操作行下方的独立跨列行，覆盖整张收益表宽度，不改变第一列宽度；可分别展开、收起多条路线，支持键盘操作。路线使用紧凑动作气泡，前台起手实线、后台释放虚线；只在切走前负责预输入下一段的动作气泡上标“预”，正常前后台连段不重复标注。动作气泡不显示“自动”标记，自动衔接动作也只展示动作名；输入明细与离线衔接规则保持不变。末段本身主动正常切人或脱手切人时，末气泡使用原名加“切”（如魔a5切）；预输入后在后台完成的尾段不加“切”。闪以 `魔a3闪` 等原动作名加闪表示。前后台标记由离线生成的前排区间投影，网页不计算规则。页面不提供“统计口径”卡片，也不在展开明细中展示维护来源列表；计算口径与来源保留在本文和静态数据中。没有计算 API、方案写库、训练依赖；网页请求和网站启动均不运行生成脚本。

“包含动作”提供当前角色已生成路线中实际动作的多选勾选项；多选按同时包含全部已选动作匹配，不限动作位置或前后台，并与首尾动作、回场、路线类型及闪替代筛选组合。不选择时不限动作，支持一键清空。动作按实际名称精确匹配，例如魔a3与魔a3闪分别选择，闪跳过的魔a3不算实际包含魔a3。切换角色后更新选项并清除该角色没有的选择。

## 目录与生成

- `data/rules.json`：角色范围、动作白名单、衔接图、预输入例外与来源。
- `generator.py`：离线枚举、时间安排与裸收益加总。
- `static/data/tables.json`：随网站发布的静态结果，附输入 SHA-256。
- `templates/overlap/index.html`、`static/js/overlap.js`、`static/css/overlap.css`：独立展示页面。
- 动作衔接卡片从静态合法衔接关系和已生成路线列出具体前置动作；多个来源及合法的闪替代来源全部列出，不使用“前段”等泛称，不在网页推测新衔接。
- `scripts/generate_overlap_tables.py`：生成入口，不导入 Flask 应用、不初始化数据库。

只读取排轴的 `actions.json` / `characters.json` 数据文件，不依赖排轴领域服务；不修改排轴动作或权限。更新动作数值或合轴配置后显式运行：

```bash
python3 scripts/generate_overlap_tables.py
python3 -m unittest tests.test_overlap_tables tests.test_module_routes -v
node --check app/modules/overlap/static/js/overlap.js
```

`--rules PATH --output PATH` 可生成临时版本。输入缺时长时输出 `null`，不把占位0秒算作真实免费动作；不认识的角色、动作、没有来源的衔接或超出枚举边界均报错。生成文件必须一起提交，不能在请求时自动重算。

## 现行合轴口径

由用户2026-10-12最新确认：普攻默认顺序衔接；预输入合轴在前一个动作开始0.4秒后输入下一动作并切人，当前动作与已输入的下一动作在后台完整释放，覆盖此前0.3秒预输入口径。操作名使用 `a3预a4`，起手段在完整路线中展示；输入时刻与实际释放时刻分开记录。明音不支持 `a3预a4` 合轴，只保留完整顺接。

正常切人作为独立候选：动作开始0.2秒后结束前排占轴，当前动作完整伤害与资源继续在后台结算，不按打断缩减收益、不额外自动放出下一段。用户2026-10-12最新明确所有已纳入的动作均支持正常切人，`normal_switch_actions`覆盖全部动作（含E、重击和普攻末段），`normal_switch_seconds`固定该节点。用户2026-10-12最新更正：安魂曲远程普攻支持预输入合轴，因此a1–a4同时枚举0.2秒正常切人和0.4秒预输入下一段切人；不生成a4孤立起手候选，a5也支持正常切人，并保留完整连段基准。正常切人也可作为多轮合轴的收尾；明音在当前0.4秒预输入与1.0秒a3耗时下，a2预a3的后台窗口仅1.1秒，不足1.2秒，不再生成这条回场路线。

末段没有当前上下文下的合法衔接，或其合法衔接包含本路线首个动作时，额外生成末段不切走的“xx打满”候选，并支持回场后的打满收尾。打满按完整释放时间计算前台耗时，完整收益保持一致，末气泡不加任何后缀；技能、重击与闪等中间分支仍在标题保留。资格仅按已记录的衔接图判断，不因枚举使用次数耗尽而伪装成没有后续，用户2026-10-12确认普攻末段默认完整释放后可接回本形态a1，以 `basic_chain_restart_source` 记录来源并按同形态连续普攻自动补边；该衔接不增加预输入点，不实际执行下一轮。原完整连招基准仍保留；“末段打满（不切走）”可单独筛选这些候选；“可循环打满”进一步只筛选末段能衔接回本路线起手的打满路线（`hold_reason=cycle_to_start`），包括回场后的打满收尾，其标题统一显示为淡黄色。筛选与颜色直接读取离线字段，不在网页推导循环规则。

用户本轮进一步确认：所有z重击（含幻z、魔z1/魔z2）不能被预输入，必须前一个动作完整释放结束后才直接输入z。`preinput_forbidden_actions`按动作记录禁止预输入的来源，并覆盖所有指向该动作的衔接；不生成a1预z等候选。z释放后能否预输入后续普攻仍按对应衔接配置执行。

路线只从 `start_actions` 配置的合法起手枚举，后段动作仅在衔接目录展示，不生成孤立起手或孤立脱手方案。起手通常为a1/E/Q；当前动作范围内安魂曲为a1远/普通E、残虹为a1/幻a1、明音为a1、黑羽为魔a1/已激活的魔E，不额外扩展既定动作范围。

安魂曲普攻仅远程、不支持闪避保留连段；其他三人的所列形态均支持。只尝试把超过0.7秒的中间普攻替换为0.7秒的闪，首末段不替换；跳过动作的倍率、环合、回能和个人资源全为0。只有前台实线动作可加闪，最终投影落在后台虚线的闪候选会排除。闪不能被预输入，也不能在闪中预输入下一段；必须前段打完再闪、闪完整0.7秒后再输入下一段，替换自动衔接动作时闪仍为手动输入。不用排轴通用0.5秒闪覆盖这个模块的用户指定0.7秒规则。魔a5之后要接魔E的路线必须实际打出魔a5，不能以闪跳过激活前置。

衔接动作合轴：在预输入尾段结束时切回来继续下一段。窗口1为首次切走到尾段释放结束；窗口不足1.2秒不生成。允许回场范围为 `[首次切走+1.2秒, 尾段结束]`，结果选尾段结束时回场，累计两段前台时间。窗口只描述可供其他角色使用的时间，不编造队友操作与收益，也不添加未知的连段宽限期。

用户2026-10-13补充：对回场路线逐段检查前台耗时，首段豁免；非首段前台小于1.2秒且该段以切人结束时，标记为需三人合轴。恰好1.2秒不标记，末段打满不切走也不标记；若未来有多次回场，中间切走的短前台段仍需要三人，即使最终打满。离线输出 `requires_three_characters` 和 `three_character_segments`，网页只按字段筛选。未展开的标题、气泡、时长列与颜色不增加人数差异，人数和触发段仅在展开明细中说明。

多轮路线标题保留两次切人的简称，同时列出回场后到最终切人前的完整中间衔接，含技能、重击、闪替代与脱手；第一次切人前若含这些特殊分支，也列出相应前缀。标题从实际动作列表生成，不按角色硬编码，避免含魔E回接的长路线与普通两段路线共用一个省略关键动作的标题。

“前台合计 / 动作结束”合并为一列两行：第一行突出累计前台耗时，第二行以灰色字显示整条路线的动作结束时刻；“合轴窗口时长”按实际时序罗列每次前台耗时和回场后台窗口，每行一个纯时长气泡，前台实线、后台虚线。离线生成 `foreground_segments`，分别记录每次上前台的起止时刻与耗时。`overlap_windows`只记录切走到下次回场续连段的后台空档，标明时长、起止时刻及满足1.2秒冷却后的可切回时段；最后一次切走后不回场的后台尾段不生成窗口，也不展示包含该尾段的“脱离前排”总列。时间只在对应列及展开明细展示，操作路线保留动作气泡和切走/回场提示。这些字段由离线脚本生成，网页不做时长或冷却计算。

用户2026-10-12新增安魂曲普通E→a5远，以及a4远脱手→普通E；E可作为起手。普通E完整0.8秒、a4远脱手0.5秒及动作收益读取当前actions.json；用户最新要求本模块取消E脱手候选，只保留a4远脱手接E，不改动排轴原始E脱手数据。a4远→E直接衔接，不预输入E；E→a5远按用户最新通用规则，须E完整结束后直接输入a5，不生成e预a5。a4远与普通E仍支持0.2秒正常切人；`normal_replaces_detach_actions`对这两个动作抑制独立脱手候选，a4远→E的脱手衔接不受影响。新增衔接来自用户确认，不修改排轴动作配置。

黑羽魔a5接魔E时改用现有脱手版本0.6秒，伤害与资源完整保留。用户2026-10-12最新更正：魔E不支持预输入，但可开始0.2秒后正常切人，完整伤害与资源继续后台结算，不要求前台打完；魔a5→魔E仅直接顺接，魔E→魔z2须等魔E完整结束后直接输入，不能预输入魔z2。魔E可作为收尾，末气泡显示“魔e切”，支持回场后的魔E收尾。用户2026-10-13补充：魔z2支持预输入魔a3，按动作开始0.4秒后输入并切人，魔z2与魔a3完整收益在后台结算；覆盖此前仅按自动接续处理、漏掉预输入候选的配置。魔z2本身仍不可被预输入，魔E也仍不可预输入后续动作。只有这些显式回接路线允许按 `max_uses` 再走一次魔a3–魔a5，魔E仍最多一次；不是无限连段或技能CD搜索。

用户2026-10-12最新确认：所有E动作都不能预输入后续动作。生成器按动作类型E统一禁用其出边预输入，不按角色硬编码；后续动作须等E完整释放结束后直接输入。此规则独立于正常切人，E仍可开始0.2秒后切走、在后台完整结算。

魔z2也可单独作为路线收尾，枚举完整释放与开始0.2秒后正常切人；收尾动作下拉提供魔z2，不再强制追加魔a3。只有选择魔z2预魔a3时才计入魔a3收益。

用户2026-10-13补充：新增魔z1→魔a3，可在魔z1开始0.4秒后预输入，但须等到开始后0.8秒才切人（输入后额外等待0.4秒）。魔z1的合轴完整时长覆写为1.4秒，魔a3在魔z1完整结束后释放；原魔z1→魔z2顺接继续保留。特殊输入／切人时刻在动作衔接卡片分开显示，回场窗口也从实际0.8秒切人节点计算。此次按合轴范围在rules.json记录用户补充覆写，不改变排轴原始动作数据，不表述为解包或实测耗时。

衔接配置可写 `input_delay_seconds`（从前动作开始到输入的延迟）、`switch_delay_seconds`（输入后额外等待）、`can_preinput=false`（前动作结束时直接输入，不提前排队）、`detach_previous=true`（前动作必须脱手）、`automatic=true`（自动衔接，无再次手动输入）、`requires_previous` / `requires_prefix`（上下文约束）；动作覆写 `locks_foreground_switch=true` 要求完整释放区间由前台覆盖，现有四名角色的动作均未配置此锁定。`start_actions`与`character_order`分别维护合法起手和展示顺序。这些属性分别记录输入、合轴与释放时刻，避免把延后合轴误算为丢伤害。

## 双角色合轴分页（2026-10-15）

入口 `/overlap?page=pair`，与原收益表通过顶部导航切换，匿名可访问。选择原表中的两位不同角色后自动匹配，中间交换按钮可对调角色一／二并自动重新匹配，计算在浏览器 Web Worker 中运行；重新选择会终止旧计算。原表与生成脚本不变，网站请求和启动不运行方案计算，不新增服务端计算 API、持久化或跨模块领域依赖。

### 匹配范围与条件

- 用户2026-10-15最新确认：每轮每位角色最多执行两组动作，可以相同或不同；排除双方都将各自同一种动作组重复两次的方案。单方重复、另一方一组或两种不同动作组均可保留。动作组按完整有序动作序列区分，闪替代属于不同组，预输入／正常切人等时刻变体不另算一种组。每组保留原表已有的合法起手、组内衔接与回场。
- 排除 `requires_three_characters` 和未知时长路线。按动作目录中的状态条件、冷却、能量消耗和个人资源消耗排除不可自由释放的动作，因而残虹幻境动作、安魂曲普通 E 不出现在结果里。
- **黑羽采用用户2026-10-15本页指定口径**：只存在魔 E 的前置条件，其上一个黑羽动作必须是魔 a5。允许穿插队友动作；如果魔 E 是本轮首动作，检查上一轮黑羽末动作。忽略导入排轴数据中的魔女形态及恶意门槛，仅作用于本页，不修改排轴、原表与数据源。
- 用户2026-10-15补充：下一动作是普攻（不含重击和 E）且不满足已有衔接图时，须在该角色上一动作完整结束后至少等待 0.5 秒；循环首尾同样检查，即使中途穿插队友动作也不豁免。例如安魂曲 a4远→a1远须加等待，而 a5远→a1远已有末段回接记录，不加等待。重击／E起手不加此等待，但仍检查各自既有前置条件。匹配器把等待纳入最短周期，再计算倍率/秒和去冗余；只有放宽某角色的0.5秒重启约束就能缩短当前周期时，才用黄字说明须等待至少0.5秒，不重复附加“本方案0.5s”；周期本来就由切人冷却或队友动作撑长、天然留足间隔时不提示。本条为用户指定的合轴页面口径，不修改排轴动作数据。
- 每组的完整释放、与下一组的衔接等待（含首尾）单独检查；黑羽魔 E 的前置按上一个黑羽动作跨组、跨轮检查，不要求在同一个动作组内。跨组的魔a5→魔E复用原表已记录的0.6秒脱手释放耗时，倍率完整保留，不回退为完整魔a5时长；组身份保持独立，不改排轴数据。上一组未结束时不能启动下一组。
- 同一角色的本轮动作必须在该角色下一轮起手前全部释放完。首尾不同角色时周期边界也是切人；所有切人相邻间隔，包括跨周期间隔，均不少于 1.2 秒。首尾同角色时必须在周期边界前完整释放末组；不属于已有衔接的普攻起手继续按0.5秒重启等待处理。

### 时序与去冗余

`static/js/pair_multi_engine.js` 是当前网页匹配入口。每个动作组有独立起手变量，组内输入与释放时序来自原表；枚举保留双方各自组序的前台安排。同一角色相邻的动作组可以留在前台连续操作，组内既有回场仍检查实际切人。每次实际切入前台（包括异角色循环接缝）必须在该角色有动作正在释放的区间内，或正好在该节点开始释放新动作，不能先切入空等再起手；动作结束时刻不算仍在释放。允许回场接住当前组、上一组或上一轮的后台尾段。同角色首尾留场衔接不是一次切人。每次手动输入必须由该角色前台覆盖，前台区间不重叠；各组之间不得与自身后台释放重叠。

计算采用整数毫秒差分约束。先用常量路径与最小平均环求周期下界，再枚举切入时的合法动作释放／输入区间，用带正负周期系数的负环约束逐步收紧下界，精确求最短合法周期（前一轮尾段会同时引入周期上界，不能直接假设单调二分），避免将第一组最早结束时刻硬拼成第二组起点。每个候选都包含完整循环接缝、1.2秒切回冷却、组间／跨轮的0.5秒重启条件，以及魔 E 前置。相同输入／释放时序且前台段数相同的路线，只在强制占轴包含关系成立时去除较差变体，不按单组倍率排名截断候选。

包含动作组和动作组种类条件在去冗余前生效：包含按完整组精确匹配，不能用一个更长动作组中的子序列冒充所选组。先按双方各自携带的完整动作组集合保留最短周期，再去除同等或更短周期内实际动作更多的子集；动作数、顺序和闪替代都参与比较。相同动作和周期但组边界不同的方案不因身份合并而丢失。筛选后的方案仍须满足每人最多执行两组；种类按完整动作序列去重计数，重复两次仍算一种。

同一方案的离散滑块在该组显示时才由 Worker 准备，避免为未展示的数万候选同时生成时间轴。滑块在保留的最短时序结构中分别求两人前台占轴最大的端点，分别在每个合法切入区间的约束结构内生成不超过0.1秒间隔的代表档位；不跨越无动作的空档插值，不在不同结构之间插值，不声称列出连续时间的无限解。方案摘要交给页面，完整时序保留在 Worker 中，排序和“显示更多”时按需获取。重新匹配会终止旧 Worker。

### 展示与文件

- `static/js/pair_engine.js`：差分约束／最小费用流工具与旧单组匹配回归基线。
- `static/js/pair_multi_engine.js`：一／两组候选、跨组条件、最短周期、去冗余和延迟生成滑块；不依赖排轴领域服务。
- `static/js/pair_worker.js`：独立计算，进度与错误回传。
- `templates/overlap/pair.html`、`static/js/pair.js`：角色选择、排序、闪替代过滤、分批展示和缩放。两位角色各有一个“包含动作组”下拉；“动作组种类”可选全部（每人最多两种）、每人一种、至少一人两种、两人都用两种；筛选按不同动作组数计算，不按执行次数计算。交换角色时所选动作组跟随角色交换；闪避筛选或角色改变后清除已不可用的选项。默认按双人总攻击倍率除以循环时间降序；另提供角色一秒均倍率最高、角色二秒均倍率最高、循环最短与动作最多排序；单人秒均倍率同样使用双人循环时间作为分母，同值时先按双人秒均倍率、再按循环时间排序。右侧按角色列出每轮倍率，并在其下用白色小字显示该角色倍率除以双人循环时间的秒均倍率；卡片汇总双人总倍率及每秒倍率，只计一轮，当前四位角色均为攻击基准，不把预览的下一轮重复加总。
- 方案组内存在不同解时显示独立离散滑块，只有一个解则隐藏。滑块同时更新动作位置、输入、切人、前台色带、前台总时长及等待说明；动作收益、循环周期和列表排序保持不变。展开明细按角色列出组1／组2，避免将组间重启误读为组内连段。每组选择在排序、缩放和显示更多时保留，重算时重置；滑动只更新当前组，不重算全表。右侧同时显示每人的前台时长。
- 每位角色独立一行、独立颜色；动作气泡宽度对应完整释放时长，位置对应实际释放起点，菱形单独标出输入时刻，色带标出前台占轴，竖线标出切人。默认显示连续两轮及开头上一轮的后台残留，便于查看循环接缝；延后切人另列说明。窄屏横向滚动，悬停可查看精确输入／释放时刻。
