# 配牌确认与交付协议

本协议规定配牌确认和回退，不替代[训练手册](duel-v2-public-training.md#当前训练链路与报告落点)规定的搜索学习与完整评估链路。每次运行报告及原始资料放在 `artifacts/rl-evals/<run-id>/`，不提交Git。

本协议用于后续三套公开阵容全流程，规则仍以完整手册为准。框架实现不自动启动训练；旧双预组脚本和已有冻结夜间脚本仅用于历史复现，不再作为本协议的交付入口。

入口：`scripts/train_duel_v2_full_cycle.py`。默认只打印计划；显式`--run`才冻结源码与数值模型、预约不可复用的种子区间并启动有硬截止的监督进程。导入模块不训练。例：

```sh
.venv/bin/python scripts/train_duel_v2_full_cycle.py --output artifacts/full-cycle-next
# 单独获得本轮训练授权后才追加 --run；最长 --seconds 21600。
```

当前服务模型若与当前规则身份不匹配，正式运行明确拒绝；只看计划不等于来源模型已通过验证。历史模型作为研究热启动必须显式`--research-warm-start`。被废弃实验还必须同时提供`--baseline-builds`，不能默认继承其被废弃配牌。此标志只允许研究初始化，不授予发布批准。

## 构筑规范化

保留角色及顺序，卡牌列表按ID稳定排序。配牌身份是角色顺序＋每个牌名的数量，忽略构筑名称、ID和牌列顺序；单换、双换及随机候选统一去重。新流程在实际开局前使用同一规范化构筑，相同配牌、种子和先后手不再因导入顺序产生不同牌序。没有修改网站原规则或旧服务模型的既有构筑哈希语义。

## 预算与数据隔离

预算先分配并写入计划：基础学习25%、候选搜索15%、原配牌适应15%、候选适应15%、独立确认12%、最终审计15%、收尾3%。每个阶段有绝对截止，另由单调时钟和绝对时间共同约束进程树；总时间600～21600秒，不能通过重启重新获得预算。

`artifacts/rl-seed-ledger.json`持久记录每次运行的七个不重叠的根对局种子区间：基础学习、合成能力检查、检查点选择、配牌搜索、公平适应、独立确认、最终审计。登记采用排他锁，失败运行也不归还种子。重复输出目录或同一运行再次预约会拒绝；不要删除种子账本来重复使用确认/审计集。数字种子相同的配对局属于同一抽样簇，不能当独立观测。

搜索按8/32/128对每对手逐级筛选（两对手×两座位，合计32/128/512局每候选），原配牌始终保留；初筛只缩小候选，不作为交付证据。最终仅锁定每策略一个提案，再进入确认，不能查看确认结果后重新挑第二个候选。固定公开战术夹具是回归检查，不冒充新抽样的独立对局集。

## 公平适应

原配牌和提案从同一基础择优权重启动，Adam均重置，冻结相同的参考对手与其配牌，使用同一段适应种子。默认每个策略每个方案32个优化步骤，单轮至多4步；实际次数和起点SHA全部记录。任一方未完成相同预定步骤、起点不一致或预算截止，就不能通过候选确认。适应不按各自收集标签数给不同更新步数，不把“各运行若干分钟”当作同等训练量。

## 接受、审计与回退

仍用两种对手阵容×先后手四个场景等权胜率，没有额外最差对阵权重。默认独立确认512个种子，各在全部场景下运行原配牌适应策略和候选适应策略。按每个种子四场景平均的配对胜负差构造[-1,1]观测，使用预先固定的、有界经验Bernstein区间，并对三个提案作家族校正；不按每次中途领先反复窥看和晋级。整轮默认alpha=.05，确认与审计各分配.025，再分别对三个提案作家族校正；确认下界须大于+.02才接受提案。该保守下界可能要求更多样本；不能因为预算不足而降低门槛。

- 证据不足、相同配牌、任一缺局/重复局/非法结果、适应预算不等：保留原配牌与初始策略。
- 确认通过后锁定提案，用未接触的审计种子重新与原始策略＋原配牌比较；这样原配牌适应变差不能使差候选蒙混过关。
- 审计必须完整，平均配对差不得为负，且下界须高于预声明的-.05非劣界；固定战术回归也须通过。任一失败则回退。非劣界不是允许观察到退步后仍替换：点估计负值也直接阻止交付。
- 审计只具有否决权，不用它改牌、选另一份权重或追加到赢为止。后续新实验领取新的确认/审计种子。
- 最终报告不完整，也回退到原始方案；已审计模型保存在独立不可改写目录，不覆盖评估引用文件。推荐目录另行物化，不能以生成报告时的文件替换改写历史模型身份。

`delivery-decision.json`分别记录提案、确认、审计、原因、推荐构筑和数值SHA；`status.json`区分`workflow_complete`与`quality_approved`。`retained_baseline`不是失败造假，也不是要求必有新方案。所有导出模型仍默认不批准网站使用，流程与统计接受不替代用户发布授权。smoke永不产生质量批准。

验证：`python -m unittest tests.test_duel_v2_build_acceptance`。覆盖真实引擎下同配牌同洗牌、候选多重集去重、持久种子隔离、预算预留、配对缺失/重复拒绝、等权评分、确认与审计冲突回退、公平适应编排及废弃产物阻止默认复用。框架改造时没有启动新一轮长期训练；完整CUDA训练表现需下一轮显式授权后验证，不预先承诺提高强度。

本次实现验证：新协议、历史候选筛选和局部搜索共25项测试，23通过、2项旧Torch依赖测试因本机无Torch跳过。新协议测试包含真实NumPy模型驱动的两场相同种子对局，验证牌序规范化后的动作序列一致；公平训练／确认／审计回退的端到端编排使用确定性适配器，不据此声称已跑完整CUDA训练。CLI默认计划检查确认没有创建输出目录、预约种子或启动进程。当前服务模型若存在既有规则身份不匹配，`--run`仍拒绝，不能把计划检查通过写成模型来源已经可执行。

确认区间以不同种子簇近似独立为统计前提，属于预声明的保守接受规则，不是价值网络的校准胜率。仅策略变化、配牌不变的方案保留研究记录，需走独立策略验收，不由本配牌门槛自动批准。

区间依据：[Maurer与Pontil（2009），Theorem 4](https://arxiv.org/pdf/0907.3740)。将观测区间从[0,1]缩放至[-1,1]，双侧及每阶段三个候选校正后，半径为`sqrt(2 * sample_variance * log(4 * family_size / stage_alpha) / n) + 14 * log(4 * family_size / stage_alpha) / (3 * (n-1))`。确认和审计各使用总alpha的一半，不重复花费同一整体误差预算。
