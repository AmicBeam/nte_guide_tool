# 无 VM 的七队 GPU 搜索方案

## 目标与执行边界

目标为单卡上 400 个独立真实对局，保持 Gumbel32、根候选 cap16、covered_value H3、逐模拟隐藏世界采样及固定观察者 WDL，全部自然结束的墙钟不超过一小时。性能对照可先各运行半小时，但未完成批次只能报告实际推进量，不能认定一小时目标通过。

采用 Windows 已有 PyTorch/CUDA。JAX/Mctx 仅作独立算法参考，不进入运行依赖。搜索热路径不使用 VM、Python 字节码、解释器、通用装箱对象图或逐根 CPU 规则回调；也不将原 VM 改名为 native/SoA 后继续使用。

业务阶段和事件队列是显式规则流程，不是解释执行任意指令。卡效通过所属内容对应的直接领域处理器实现，公共驱动只负责批处理、顺序和错误传播。禁止预录搜索树查表、简化卡效或减少 H3 来取得速度成绩。

## 数据与计算

1. **权威状态列**：玩家、角色、卡实例、区域顺序、效果、选择、续步和随机状态使用具名整数／布尔／浮点列。模板数据共享，实体身份独立；未知字段和超容量拒绝，不能混同缺失、null、false、0。
2. **分支状态池**：物理根与假想分支持有 slot／owner／generation。复制只读取已验证父状态，子分支独立可写；重复写、过期租约和跨根访问拒绝。无需给每个节点保存全套稠密候选特征。
3. **紧凑动作**：保存动作种类、实体／目标引用、选择参数、原始 ordinal 和完整合法掩码。GPU 队列按领域处理器分组执行，再按原 ordinal 回填，不改变候选顺序或同分选择。
4. **直接规则内核**：伤害、护盾、资源、区域移动、到期等公共操作直接读写字段。出击、入场环合、响应、倒地连锁、使用／释放及选择续接按正式引擎顺序组合；不能把已准备数值的伤害算术当作完整战斗。
5. **公开投影与采样**：从同一状态列产生合法动作与可见观察；世界采样只使用行动方信息集，并保留既有完整 RNG、牌数约束、生成牌和回收规则。采样后核对完整观察与候选，不以真实暗牌约束样本。
6. **H3 教师**：公开候选预演在独立分支上批量执行，完整预演返回后按原评分与顺序选点，最多续行三步，再使用独立、已验证的辅助价值模型。不能替换成手写近似伤害评分或主价值头。
7. **搜索与推理**：复用不依赖规则 VM 的 `DeviceStatisticsPool`、GPU 数值模型及 Gumbel 算法。`DeviceGumbelSearch` 通过领域规则接口绑定新后端；现有强制 `DeviceSoARules` 类型的工厂须另作适配与验证，不能绕过资格检查。
8. **设备调度**：固定容量缓冲区、活动掩码、设备队列与 CUDA Graph 管理重复工作。CPU 只负责准备、整批启动、外部截止和批后核验，不逐根读取动作或估值来推进搜索。

## 显存预算

当前候选特征维度为 1576，完整合法容量为 800。400 根的一份 FP32 稠密候选矩阵为 2,017,280,000 字节，约 1.88 GiB；若每根 33 个搜索节点都缓存该矩阵，约需 62 GiB。因此持久保存紧凑动作，编码和网络工作区按显式 tile 分配、循环复用。

现有 `DeviceStatisticsPool` 在 400×33 个节点、800 动作下的持久张量约 212 MiB；这不包含规则状态、工作区、模型、临时算子、图内存池和轨迹。容量验收必须另核所有实际存储与整卡峰值，不根据这一个数值宣布 16GB 足够。

完整轨迹使用有界追加存储，错误／超时不能写入终局标签。分段只在安全边界保存；操作者提前停止时保留已完成对局和未完成前缀，不把停止变成输或平局。

## 当前实现边界

`domain_soa_codec.py` 已支持可精确表达的换牌、正常行动、选择与终局状态，保留实体、别名、区域顺序、随机种子和已覆盖效果；缺少专用列的权威字段仍明确拒绝。入站逐字段／类型与别名核验、出站规范化复编码核验属于宿主准备与核对，不进入搜索热路径。`domain_soa_rules/effects/transition` 仍是有限条件和准备后数值切片。完整正常行动、所有卡效、选择续步、合法动作、隐藏世界采样与 H3 的领域后端尚未完成；观察列已有独立拼接组件，尚未接入完整后端。

角色字典中的存储身份与当前阵容分列：`player_character_count` 包含仍需保留身份的消失召唤物，`player_order_slot` 映射当前阵容到存储槽。前排、行动者及续步引用都指向存储槽；进出阵容不改变对象身份。编解码保留角色字典次序、阵容次序和本回合出击次序。空阵容列表按正式 `team_order` 回退到角色字典次序。公开投影仅按当前有效阵容呈现，保留身份不意味着仍出现在场上。

运行字段已有独立列与存在标记：伤害来源、灵可连用记录、兽牙、额外基础数值、消失标记、援护回合、效果序号、排牌／牌库选择标记及续步空列表。新增专用列不意味着完整卡效或完整公开观察已实现；条件载荷、若干特殊续步等剩余边界仍严格拒绝。

`domain_soa_projection.py` 从具名设备列生成部分公开特征和完整换牌候选（最多 800），保持原始候选次序；原始候选容量独立于搜索 cap16。静态模板默认字段在设备上展开，洞察伤害按正式投影计算。默认动作模式拒绝正常行动方和所有选择阶段，非行动方只返回认输；`observation_only` 模式不提供动作资格。该模块仍是部分特征，不准补零作为完整模型输入。400 行图重放对拍覆盖的是这组特征与换牌候选。

`domain_soa_cuda_damage.py` 将 `damage_fields` 的已解析伤害算术融合为一个直接 CUDA 内核，保留免伤、护盾、上限、生命锁定、最低生命、错误及未激活行行为。调用方必须先完成抗性、响应、重定向等规则。它不提供完整出击、后继实体状态或训练资格。

`domain_soa_state_pool.py` 按数值类型把具名字段放入共享存储，字段仍为独立视图。GPU 分支先批量 gather 源快照，再用 `domain_soa_cuda_copy.py` 直接复制原始字节；不逐字段调用原子加减，不改变 NaN、负零或整数位模式。张量复制保留为显式 `fused_cuda_copy=False` 对照，CPU 仅作显式 oracle。关闭状态池前必须停止使用其捕获图。

`domain_soa_action_batch.py` 保留完整 800 候选容量，区分物理单选与多候选预演。回执核对 arena、设备 issuance epoch、owner／generation、动作索引与原候选 ordinal，迟到、重复、外来或不完整结果拒绝。`domain_soa_zones.py` 在设备上保持实体索引和区域顺序，支持移除后插入及同区调整；它不替调用者执行满手重定向、抽空胜负和卡效。

`domain_soa_random.py` 支持预先分配洗牌输出，再在调用方流中启动或捕获 CUDA Graph。重放读取当前种子和牌序，逐位保持正式 Python Random 洗牌与后继 63 位种子；拒绝预算耗尽则保留输入。准备阶段与执行阶段分离，不在捕获时分配输出，也不在设备失败后回退 CPU。

`domain_soa_choices.py` 直接生成已解析选择的合法动作：逐张选择、弃换手牌的组合、固定数量组合，以及排牌的排列／顶部与底部分配。候选次序与正式 `legal_actions` 一致；选择载荷保存原候选 ordinal，逐张选择另保存实例索引，二者都不是卡模板 ID。完整动作上限为 800，单个选择载荷上限为 64；超容量整体拒绝，不截掉尾部。排牌规格须先由实际角色规则解析，未解析规格拒绝。该阶段不执行选择结果，不生成完整观察，也不接替正常行动阶段的合法性判断。

其 `prepare_from_fields` 绑定具名状态列、观察者与活动掩码；每次 `launch` 都从当前列更新输入，因此捕获图重放不会复用旧的选择方或卡实例引用。非法／失效实例拒绝，非选择方只得认输，隐藏选择载荷不影响该结果。CPU 显式参考只编译相同直接算术源码；设备路径没有 CPU 回退。应先释放捕获图并同步设备，再关闭执行器。

`domain_soa_sampler.py` 实现具名列上的公开计数采样数值路径，包括原牌／生成牌分配、恢复机会、强制手牌放置、已知己方牌库排序与洗牌、实例重建和正式 MT19937 随机序列。生成牌种类按首次分配次序进入候选池；恢复预算按真实全局回合和先后手边界计算。选择中的牌与正在结算的牌即使不在普通区域，也保留其身份与引用，并参与新实例序号上界。

采样预备对象为全部状态列分配独立输出；重放刷新稳定的输入快照与输出，不借用母状态作为可写子状态。活动行保留已有错误，校验模板绑定和容量；失败时除错误码外整行回滚，错误张量不更换地址。当前数值路径限制为 `max_zone<=128`、`max_cards<=512`，超界拒绝。

完整 3479 观察与候选的信息集校验尚未实现。因此默认 `guard=True` 对活动采样返回 `PUBLIC_GUARD_UNAVAILABLE`，不接受部分投影或两组零特征作为证明。显式 `guard=False` 只供与正式 `seven_sampler` 的数值诊断，不授予搜索／训练资格。schema 已保留揭示手牌与牌库可见回合，但数值采样尚未实现这些可见性约束，相关活动根明确拒绝。卡表空洞的规范化导出仍需完成；当前不得接入正式 H3 训练。验证：`python -m unittest tests.test_duel_v2_domain_soa_sampler -v`。

状态池与动作队列的独立实现及验证必须保持 `supports_full_duel_rules=False`，直到全部规则接口和真实完整局证据齐备。任何组件加速比都不能写作七队整局加速比。

## 实施与放行顺序

1. 完成全状态编解码与存储隔离，覆盖正常行动、双方选择、生成／复制、武备、效果、召唤、续步和随机状态。
2. 完成正式动作和七队实际卡表的直接领域处理器；机制覆盖还须包含完整公开范围的规则边界。
3. 完成合法动作、公开观察、逐模拟信息集采样及完整 H3 教师；统一原始动作和数值接口。
4. 接入既有 GPU 搜索与冻结网络，完成 8 个独立真实根的 Gumbel32/H3、自然终局、动作重放与数值对拍。
5. 同一路径按 8→32→128→400 扩容，记录实际活跃根、完整模拟、错误、显存、准备／执行／保存／核验耗时。
6. 冻结同模型、同牌组、同种子和同搜索条件，对混合与无 VM 后端各作半小时对照。分别报告完整局数、已提交决策、模拟数、尾部对局、每局决策数和实际工作区；不以局部外推代替完整 400 局一小时验收。

完整训练、梯度更新、恢复和强度验收继续采用训练手册；本方案本身不授予模型上线或完整训练批准。

## 组件检查

`python -m unittest tests.test_duel_v2_domain_state_pool tests.test_duel_v2_domain_action_batch tests.test_duel_v2_domain_cuda_damage tests.test_duel_v2_domain_soa_zones -v`

CPU C++ shim 检查同一直接 CUDA 算术源码与既有张量参考；实际 CUDA 用例另外检查混合错误／活动行、输出精确相等、输入不变及 CUDA Graph 重放。CUDA skip 不计入设备通过。

组件计时入口 `python scripts/benchmark_duel_v2_direct_gpu.py` 默认只输出计划；显式 `--run --roots 400 --copy-backend direct --output NEW_DIR` 测量合成字段状态的分支、完整候选队列、准备后伤害和区域移动。`--copy-backend tensor` 为匹配的复制对照。该入口不创建完整游戏、加载模型或优化器，最多使用 120 秒组件预算；结果始终保留 `full_game_benchmark=false` 和 `full_duel_qualified=false`，不能替代半小时真实整局对照。

选择阶段验证：`python -m unittest tests.test_duel_v2_domain_soa_choices -v`。测试将实际正式引擎的完整候选列表逐项对拍，包含组合边界、顶部／底部及多底部顺序、全选、空选择、容量拒绝和 400 行设备图的状态变更。CUDA 跳过不计为设备通过。

换牌的直接设备阶段位于 `domain_soa_turns.py`。它只返回换牌所需字段增量，要求调用者先校验完整合法动作；选中牌按手牌顺序移出、先抽替换牌再归还洗牌，使用正式 CPython 随机序列。第二次起手换牌返回 `begin_turn` 续步，手牌调度返回 `finish_operation` 续步；这些下游规则尚未执行。小吱终结抽牌钩子、空牌库等未覆盖情况在提交前拒绝，既有错误、过期内容绑定和失败行保留原状态。稳定缓冲区每次读取当前具名列，支持非连续状态池视图与设备图重放。该组件不维护完整动作标识和公开事件，也不授予完整整局或训练资格。验证：`python -m unittest tests.test_duel_v2_domain_soa_turns -v`；CPU 编译器对拍与实际 CUDA 检查分别计数。

域编解码保留效果条件的有序列表、条件 ID、逐键参数及数值／布尔／字符串类型，空条件、空清理列表和空持续状态字典也与字段缺省分别编码。已登记的条件与清理时机超出枚举时拒绝；条件数量和参数列固定有界。战斗目标区分玩家与角色，真红计数、达芙蒂尔削减映射及黑羽检视后续步使用独立字段。当前仍拒绝未建模的战斗续步规格与未知状态；更深轨迹通过不等于完整 17 角色规则通过。验证：`python -m unittest tests.test_duel_v2_domain_soa_codec -v`，自然轨迹的候选池排除认输。

暂停出击可保存空规格或仅整数 `bonus` 的规格以及 `stay_bench`，区分空规格与零奖励；其他规格键明确拒绝。它只负责状态保存，不执行恢复出击或省略后续卡效。

临时牌视图通过独立标记和表内物理牌引用保存，视图与原牌共享实体及实例身份，实际区域只允许物理牌。嵌套／循环视图和身份不一致拒绝；解码恢复实际别名。采样器尚未实现这类视图的重采样，包含视图的活动行即使在数值诊断模式也拒绝并回滚。

公开字段投影读取源行错误及内容绑定；失败来源不能产生可用动作回执。个人能量上限按正式角色模板的覆盖规则和第 13 回合节奏计算，结算牌头部只在存在选择时编码；操作中的空牌合法保留。400 行设备图检查还须变更来源错误、绑定和节奏回合，分别核验保护及正式观察数值。该模块仍只输出已声明的部分特征，不能补零形成完整网络输入。

只读角色数值查询位于 `domain_soa_character_queries.py`。直接设备代码按条件、范围、来源与层级归约效果，计算武备面板、当前面板攻击、能量／环合上限、倾陷阈值、免伤与伤害上限，并保留兼容攻击增益、持续攻击及双方玩家／角色的属性减伤投影。当前查询上下文不带具体攻击参数，不能代替攻击命中结算。召唤物空属性按正式规则处理，数值绝对值超出 2147483647 或已识别的非法字段／容量会报错，来源失败和内容绑定错误不返回可用数值。准备阶段冻结公共静态表；设备执行不调用逐行 CPU 规则，CPU 编译模式只作显式对拍。该模块不是完整观察、动作执行器或 H3。验证：`python -m unittest tests.test_duel_v2_domain_soa_character_queries -v`。

`domain_soa_observation.py` 将已支持域状态拼成七队模型的全部 3479 个观察特征，覆盖公开手牌／复制与变换牌面、标记、选择、角色数值、持续状态、复制异能与回合计数。每个字段按原编码定义计算，不用未实现字段补零；终局停止被动牌面替换和面板回调，召唤物的新旧区块按冻结编码器各自的 ID 映射处理。准备后重读当前列、观察者和错误，失败行不提供可用向量。它仍不产生 1576 维动作特征、不执行物理动作，也不授予 H3、信息集守卫或完整训练资格。验证：`python -m unittest tests.test_duel_v2_domain_soa_observation -v`，需分别核验 CPU 正式编码对拍和实际 400 行设备图。

schema 同时保留揭示实例列表的缺省／空／null／次序、牌库可见回合、布尔与整数类型的 `used` 值，以及复制异能字典的 ID 变体。只读面板查询使用实际复制的面板被动，并遵循终局回调停止规则；相关字段不会自动解除采样器的默认拒绝保护。

`domain_soa_candidates.py` 根据显式公共数值牌表与动作描述生成全部 1576 个候选特征，包含旧区块、标记、出牌选项、复制／到期／派生差异、物理牌面、有序顶部／底部牌、组合选择和额外行动力。输入使用表内引用，不把实体 ID 编入网络；未知类型、不可见牌引用、非法范围、列表空洞、重复引用和非有限数值拒绝。准备后的稳定缓冲区重读输入，支持非连续视图和 CUDA Graph。组合牌袋使用有界散射累加，避免将每个选择位置展开为完整卡种维度。该模块要求调用者已经得到公共牌表和动作描述，目前不从原始私有状态投影牌表，也不生成或核验完整合法动作，不能据此解除信息集采样保护。CPU 模式必须显式启用对拍；CUDA 不可用时不回退。验证：`python -m unittest tests.test_duel_v2_domain_soa_candidates -v`。候选特征容量与完整 H3 整局容量分别验收。

候选编码可按 `action_start`／`action_width` 输出连续窗口，保持完整动作描述的原序号与总容量；调用者必须遍历实际计数所覆盖的全部窗口后，才能取得完整候选评分。窗口不删候选，也不修改搜索的 cap16。输入刷新、来源错误和窗口内无效引用的检查在每次执行重新进行；同一输出缓冲区在下次执行时覆盖，需保留旧结果时由调用者复制。窗口模式只减少特征临时区，不证明完整规则／网络／H3 的总显存能够容纳 400 根。

公共候选牌表由 `domain_soa_public_cards.py` 从具名设备状态投影。表仅开放当前观察者自己的手牌和其可见的待选牌，二者使用独立表段，即使引用同一物理实例也不混淆牌面。复制、到期、金固标记、派生差异、额外行动力、物理原牌和动态瞬发按正式展示规则计算；真红替换与灵可 K03 回能视图保留各自明确的字段继承规则。K03 回能视图为战术瞬发，即使原牌同为 K03 也不能直接沿用武备模板。当前原始 schema 不接受的投资字段等状态仍拒绝，并未通过牌表投影获得规则支持。

手牌瞬发综合零的武备能力、娜娜莉／海月／翳的条件、原所属角色和当前声明效果；声明效果按条件、范围、层级和操作顺序计算。正式展示只在有效瞬发时将字段设为真，不清除原已印有的瞬发字段，此行为按现有接口保留。完整观察所需的只读角色查询额外提供两种布尔基值下的瞬发归约，六属性减伤仍固定为原六列。`DomainSoAObservation` 默认不返回 `_private_card_fields`；只有设备公共牌表投影显式启用内部标志时读取这些中间量。它们含非公开牌的数据，禁止作为公开投影或网络输入；只允许经上述可见性筛选后使用。

`domain_soa_rule_queries.py` 提供固定具名属性的只读设备归约，供费用、普通出击瞬发和目标标记等规则接线使用。调用者明确提供当前实体存储槽、属性、基础值及是否存在基础值；无基础值与数值零分别处理。支持字段已有的效果来源、期限、条件、作用范围、层级、操作顺序、兼容效果与相关当前光环；它只对应修正器求值，不代替完整面板回调、支付、出击、伤害或动作执行，也不授予完整合法动作资格。验证：`python -m unittest tests.test_duel_v2_domain_soa_public_cards tests.test_duel_v2_domain_soa_rule_queries -v`；CPU 显式编译对拍与实际 CUDA 图分别计数。

候选特征窗口的网络接线还须保留全候选范围内的旧教师兼容门控及相同候选别名规则，不能将每个窗口独立前向的结果直接拼接后宣称与冻结策略一致。

域状态以可空字符串保留 `seal_normal_attack`，区分缺省、null、空串与具体运行时召唤物引用。编解码不擅自清除封锁；施加封锁、普通出击支付检查和召唤物离场清理仍须由完整物理规则接线分别执行。

公共牌表与候选编码的联合 CUDA 图检查使用共享设备牌表、手牌引用和错误缓冲区，逐项对照冻结的 NumPy 编码，并在重放时检查来源错误／绑定失败是否传到候选输出。测试动作描述由独立正式规则在准备阶段提供，仅验证数据链；未实现的设备合法动作生成、物理推进和 H3 仍不能由该检查替代。

`domain_soa_targets.py` 按具名状态和显式公开牌面查询返回有序目标描述，区分无需目标、玩家、存储中的角色和弃牌实例，保留正式 `team_order` 与弃牌顺序。已声明的目标规则、存活／倒地／倾陷／前排、双方召唤物、成员排除以及残虹 C08 的持续状态叠层与复制被动覆盖分别处理。战斗牌覆盖为空列表时保留零目标；普通出击的 `normal_attacks` 模式按正式列表展开逻辑，在无覆盖或空覆盖时返回一次无需目标。该模式仍不校验能否支付或能否出击。

目标查询只接受公开角色所属席位，生成召唤物作为牌主的查询明确拒绝；生成召唤物仍可正常成为目标。未知目标规则、非法容量／输入／来源失败会清空相应查询，不返回半份成功列表。它尚未组合支付、用牌限制和出牌选项，不是完整合法动作表或物理规则后端。验证：`python -m unittest tests.test_duel_v2_domain_soa_targets -v`；400 行设备图同时检查普通出击／战斗牌目标、复制与叠层、输入变更、来源错误和内容绑定。

区域状态的数值与阵营子列按实际存在的键紧密存储；观察和目标查询按存在掩码计算子列位置。缺省的 `left` 或 `tick_side` 不得导致后续 `stacks`、`slow`、`by` 读错列。稀疏状态与正常完整状态都须对照正式编码。

`domain_soa_playing_actions.py` 在行动阶段组合不含认输的完整候选顺序：结束回合、按队伍顺序逐角色的出击与终结、按物理手牌顺序逐目标逐选项出牌。组合包含实际费用／瞬发／额外费用、普通出击封锁与资源替代、终结额度和退出、用牌条件及公开角色的相关覆盖；上限不足时整行拒绝，不能先截断为搜索 cap16。非行动方和终局返回空网络行动表，自己的换牌／选择阶段目前要求其他枚举器接入。

公共牌表仅在显式内部标志下提供自己的手牌规则元数据；实际瞬发与展示瞬发分开，基础费用与派生牌面的字段继承分别处理。行动结果同时返回网络描述与独立物理载荷：后者保留存储槽和目标种类，不能用网络的角色模板席位代替实例身份。结果缓冲区在下次执行覆写，执行器还须绑定对应状态版本／租约。此组合器是只读的，不执行支付、卡效或回合，不自动开放信息集采样、H3 或训练。验证：`python -m unittest tests.test_duel_v2_domain_soa_playing_actions -v`。

`domain_soa_actions.py` 合并行动阶段与换牌／选择枚举，统一输出不含认输的候选、实例载荷、组合选择及顶部／底部牌序。黑羽检视约束按实际选择角色、操作牌和复制被动解析；底部单牌／多牌形式分别保留。已完成换牌或正在观察对手选择时不产生可执行候选，容量不足仍整行拒绝。固定设备缓冲区须覆盖阶段切换后的新状态和新引用，不能只按准备时的阶段缓存分支。验证：`python -m unittest tests.test_duel_v2_domain_soa_actions -v`。这完成的是只读枚举接线，完整物理卡效、逐模拟采样资格、H3 与真实整局仍单独验收。
