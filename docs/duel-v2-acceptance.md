# 四人轮替 V2 实现验收

日期：2026-09-09。规则唯一真源为 [完整手册 V2.4](everness-item-chain-card-design.md)，接口见 [实现契约](duel-v2-implementation-contract.md)。本记录是功能验收，不是平衡报告。

## 已接入范围

- 默认 `/card-game`、`/build`、`/codex`、`/table` 使用 V2。置顶娜娜莉、零、九原、浔；每人八种命名牌，主牌组 32 张，每人八张，同名最多两张。
- 角色被动、终结、全部 32 张牌、完整轮替、玩家生命、备战/单人前排、环合、创生花、倒地恢复、弧盘、记录与临时复制均由纯规则引擎计算。
- 新版人机使用确定性规则策略；1v1 使用创建/加入/准备/房主开局。双方完整回合轮替，确认动作立即结算。
- 构筑、房间、成员和快照使用独立四表。普通快照先更新进程内最新态，再异步写库；结束状态同步持久化。动作携带 room_code、expected_version、request_id，阻止跨房间、过期与重复执行。
- 旧接口、旧构筑和旧快照保留，旧牌桌经 `/table?legacy=1` 恢复。旧教程、旧对局数据页和旧平衡看板未迁移。
- Grok 完成目录与页面初稿、RL 框架主体；主任务完成规则引擎、接口、存档与页面修正，协作任务“评估轻量强化学习模型”完成 RL 接口修正与框架验证。没有提交、推送或部署。

使用独立本地测试账号，不修改玩家已有账号密码。桌面使用 Codex 内嵌浏览器；触屏使用独立临时 Chrome 上下文，直接操作真实页面。

## 保留限制

- 生命、费用、资源阈值与卡牌数值仍是原创试玩参数，尚未完成先后手互换的镜像平衡测试。
- 当前只提供固定四人的完整卡池；其他属性组合是规则预留，没有对应预组。
- 最新态缓存与房间锁按单进程服务工作；跨进程部署需要集中状态协调。异常退出只保证恢复到已落库中间态，正式终局同步保存。
- RL 配置检查可运行，训练入口硬禁用；实际 Gym/SB3 集成因可选依赖未安装而未验证。
