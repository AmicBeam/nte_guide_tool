# 异象对决：从规则原型到可上线成品

日期：2026-09-12。状态：计划稿，尚未实施。本文不覆盖 [V2.4 规则真源](everness-item-chain-card-design.md)，不表示已经完成产品验收。本轮只做规则资料核对、只读审视与计划，不修改运行代码，不启动强化学习。

## 1. 本轮结论与百闻牌规则核对

当前 V2 是能够完成对局的规则原型。现有测试证明部分功能正确，不证明牌桌交互、战斗演出、教学、平衡和生产部署已经达到成品要求。

基础教学明确说明：通常每回合有两点鬼火，先手首回合一点；拖动式神出击需要一点鬼火。迅捷、瞬发及明确免火的卡牌属于例外，不能把例外理解为普通出击免费。[狸猫会《鬼火机制详解》，2019-10-14](https://www.taptap.cn/moment/15218467082862993)

每回合有一次基础出击机会，战斗牌可提供额外攻击。应区分基础出击与使用战斗牌，不把后者重复收取两次费用。[新手试炼战斗说明](https://m.ali213.net/news/gl1912/391487.html)、[狸猫会姑获鸟实战示例](https://www.taptap.cn/moment/15218508828771357)

卡组以四名式神为核心；战斗牌、法术牌和形态牌具有不同用途，不能把所有手牌理解为向战斗区部署单位。[开发者发布的游戏介绍](https://apps.apple.com/cn/app/阴阳师-百闻牌/id1445013013)

以上核对的是基础机制，资料包含历史教学，不作为 2026 年全部特殊卡牌的完整裁定。原客户端不同版本的精确拖拽热区未逐一验证；下文是本项目的交互方案，不冒充百闻牌客户端操作规范。

推荐暂时保留以下规则，先修正表达和交互：

| 动作 | 本项目费用与结果 |
| --- | --- |
| 开局角色在备战区 | 不收费，不抽取角色牌 |
| 普通出击 | 1 行动力；若在备战区则换入并攻击，消耗普通出击机会 |
| 战斗牌 | 只付牌面费用，再按效果换入/攻击，不额外扣 1 行动力 |
| 战术牌 | 付牌面费用，执行效果；不会仅因打牌而换人 |
| 弧盘牌 | 付牌面费用，给所属角色挂上弧盘；不自动出击 |
| 终结 | 1 行动力＋本人满槽能量，备战区也可使用，不消耗手牌 |

“留在前排”不持续收费，“战斗牌导致的入场”不单独收费；这些都不等于普通出击免费。若以后增加免费独立换人，必须重新设计次数、可否攻击、是否触发环合和站场保护收益，不能只删除扣费代码。

保留用户确定的个人环合、个人能量和浔独立 2 费兑现。百闻牌的式神升级等系统不在本轮自动引入，现有两费牌的节奏单独试玩验证。

## 3. 专业牌桌与美术方向

参考百闻牌的空间关系与交互层级，使用异环都市幻想的视觉语言。角色立绘和卡面承担主要识别作用，数值为第二层，完整规则文字进入悬浮/长按详情。

```text
  对手头像/生命       对手手牌背面         连接状态/菜单
                对手四人编队固定位置
                        对手前排
  最近出牌记录       中央交战与特效区       回合状态/结束回合
                        我方前排
                我方四人编队固定位置
  我方头像/生命       我方手牌             行动力
```

编队位置用于保持识别：角色进入前排后，原位置只留不可操作的占位提示，不复制出第五名角色。每方仍只有一个实际前排。

- 前排沿中央战斗轴相对摆放；生命、攻击、护盾醒目，环合与能量各自独立，不能混成一条资源。
- 卡面统一版式：立绘/插画、牌名、费用、类型、所属角色；复制和到期用清晰标记。完整效果可以放大查看。
- 日志收进可展开的历史栏，最近打出的卡保留缩略记录；认输放入菜单，不与主要行动争抢视觉注意力。
- 适配桌面与手机横屏：双方前排、玩家生命、行动力和结束回合必须同屏；不再通过滚动整块战场才能看到另一方。
- 手机手牌可横向浏览、点按放大，拖牌与横向滚动有明确的手势识别；竖屏提供可读布局或横屏引导，不能直接裁切桌面。
- 美术交付包含卡框、场景、属性/状态图标、按钮各状态、卡背、胜负界面与音效风格；资源来源记录随素材保留。

第一步先交付桌面和手机横屏的高保真牌桌原型，同时展示空场、双方站场、十张手牌、倒地、选择目标和对手出牌等状态；视觉方向确认后接入真实规则。

## 4. 按卡牌类型设计操作

“施放区”是举牌时出现的交互热区，不是新的规则区域，更不是角色战斗区。

| 对象 | 拖动/点击行为 | 取消和确认 |
| --- | --- | --- |
| 角色 | 拖到我方前排确认普通出击；点击查看并提供明确的出击按钮 | 放回原位或松在非法位置不扣费 |
| 无指定目标的战斗牌 | 拖到施放区或点使用；角色自动执行该牌战斗流程 | 不要求把卡当成前排单位摆放 |
| 指定目标的战术牌 | 指向后端列出的合法目标，显示连线与预览；点按操作只选一次目标 | 未确认可取消，非法目标不能消耗费用 |
| 无目标战术牌 | 施放区或使用按钮确认 | 不要求先换人 |
| 弧盘牌 | 所属角色或施放区确认；高亮实际生效角色 | 角色在备战区也可按规则使用 |
| 觉醒 | 本人资源满时显示角色上的觉醒入口 | 明示 1 行动力和本人的能量，不与角色查看混同 |

服务器继续决定所有费用、合法目标与结算；前端只表达选择。已提交的抽牌、检视和伤害不能撤销；后续选择仍由 pending_choice 分步产生。

## 5. 双方共用的战斗演出系统

不能只在最终 DOM 上补闪光。规则引擎需要发出结构化步骤，客户端按顺序播放，最后与权威快照对齐。

动作信封建议增加独立 presentation_version、action_id、事件序号区间和公开步骤。每步按需要提供来源/目标实体 ID、已公开的卡牌信息、区域变化、生命/护盾/资源前后值、同时结算分组。规则时机仍使用统一 GameEvent，演出数据经过投影层按玩家过滤。

建议事件流程：

```text
卡牌离开手牌 → 公开展示与扣费 → 目标指示
→ 换人（若发生）→ 环合/创生花（若发生）
→ 攻击与反击 → 受击/护盾/生命变化 → 倒地或恢复
→ 被动/弧盘/记录/复制 → 个人资源变化 → 动作结束
```

- 我方和对手共用播放器。对手出牌必须看得到卡背移出、翻面、卡名/费用/使用者、目标与结果。
- 同时伤害保持同一结算分组；先播放一方倒地不能在表现上取消另一方已经成立的反击。
- 连击分段展示；浔首击击倒前排后，第二击应清楚改打玩家。创生花、觉醒、弧盘、复制各有可识别表现。
- 对手抽牌只播放牌背；只有已经公开的卡牌可以翻面。私有检视候选不得进入另一方动画数据。
- 用 action_id/event_seq 去重；重连从已消费的游标继续，缺失事件则明确同步快照，不凭文字猜中间过程。
- 人机计算可以迅速完成，演出仍逐动作播放；不靠服务端 sleep 制造“思考”。
- 动画支持静音、减弱动态、加速和跳过。输入即时反馈；非关键尾动画可快速收束，展示版本与可执行动作版本必须一致，不向过时画面提交动作。

前端建议拆为输入、状态同步、稳定节点渲染、事件播放、音效与资源加载模块，逐步替换单体 v2_table.js。没有必要为了动画重写已经验证的纯规则引擎。

## 6. 可上线首版的其他必要实现

| 领域 | 首发必须完成 | 后续扩展 |
| --- | --- | --- |
| 产品流程 | 大厅、构筑、房间准备、起手、对局、胜负、再来一局、战绩/问题定位 | 天梯、赛季、观战和分享回放 |
| 构筑 | 多套保存、清晰数量与合法性、检索筛选、预组复制、对局绑定确定版本 | 更多角色和流派；每次扩展同步规则/编码版本 |
| 新手引导 | 实操出击/出牌/换人/觉醒教程、关键字解释、首次出牌提示 | 角色进阶关卡、复杂连招挑战 |
| 人机与平衡 | 可解释的规则 AI 难度、四人镜像先后手试玩、卡手与角色参与度数据 | 有单独授权后训练与评测 RL；不作为首发门槛 |
| 联机 | 服务器权威、动作确认与去重、可靠事件增量、重连、连接状态、回合/选择计时和超时规则 | 扩容与更复杂匹配 |
| 数据可靠性 | 可恢复已确认动作、版本化存档、迁移/备份/回滚、房间清理策略 | 跨进程集中协调 |
| 部署 | 明确容量的单进程生产服务或完整多进程协调、HTTPS、进程守护、健康检查、限流与运行指标 | 按真实负载横向扩容 |

不能把内存房间锁直接当成多进程一致性方案。小规模首发可以限定单进程并验证容量；需要多进程时再引入集中房间归属或事务协调，不要求无依据地先上复杂基础设施。

保留异步快照策略，同时建议同步持久化小型动作/结果日志，恢复时从快照重放已确认动作；不得向玩家确认成功后无声丢失该动作。上线迁移必须明确处理 app/db.py 中“不兼容则删除旧快照表”的开发期逻辑，不能把它直接带入生产更新流程。账号、凭据存储和接口滥用防护也要单独做上线审查，而不是因为对局单测通过就视为完成。

计时、断线宽限和超时处理属于规则决策，在第一阶段给出方案并同步手册后再实现。首版按非商业化的小规模在线成品规划，不默认增加商城、抽卡或付费系统。

## 7. 实施顺序与验收关口

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| 1：规则/交互/视觉定稿 | 费用与动作对照表、类型操作规范、桌面/横屏高保真原型、计时方案 | 玩家能分清出击/施放/觉醒，核心对局信息同屏 |
| 2：一条完整演出链路 | 一次对手战斗牌从公开展示到资源结算；同步完成事件协议和播放器 | 能看懂谁用了什么牌、打了谁、为什么扣血；最终状态与后端一致 |
| 3：四人全量交互与演出 | 32 张牌的类型化交互，创生/成长/觉醒/复制/倒地/连击全覆盖，音效与设置 | 不误触、不重复扣费、不泄露信息；触屏与鼠标都可完成整局 |
| 4：成品流程与试玩 | 教学、构筑、大厅、战绩、规则 AI、先后手镜像数据 | 新玩家无需旁人解释完成第一局；能定位节奏和卡手问题，不预先宣称平衡 |
| 5：线上可靠性与发布 | 重连/超时/恢复测试、数据迁移、部署与回滚、限定规模试运行 | 无已确认动作丢失或重复，异常有反馈，数据可恢复，真实设备验收通过 |

每阶段补相应自动化与真实页面测试，不用静态语法检查替代动画验收。重点场景包含：双方同时换牌、同归于尽、空前排、两段攻击改目标、浔零环合兑现、复制到期/倒地清理、刷新中的私有选择、演出中掉线、重复/乱序事件与跨房间旧请求。

阶段 1、2 是下一轮优先工作；先交付可评审的专业牌桌和一条有完整对手演出的战斗链路，再扩展到全部卡牌。新增计划尚未执行，现有手册规则与运行代码保持原样。
