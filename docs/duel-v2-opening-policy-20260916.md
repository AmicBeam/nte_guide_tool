# 起手策略与针对阵容训练：框架验收

日期：2026-09-16。本文记录框架实现与验证，不代表新模型的对战强度。

## 已完成

- 新训练默认使用 `resident_public_v3`，把开局换 0～3 张牌作为可学习动作，与后续出牌共同训练。输入包含公开对手角色、自身手牌和先后手，不读取对手隐藏手牌或牌序。
- 编译引擎支持完整换牌阶段；双方各完成一次后才开始首回合，先手首回合抽牌正常执行。网站推理、构筑评估和数值导出接入相同动作语义。
- 对手分布优先覆盖两套预组的固定角色配置，牌张可变，默认保留 20% 随机公开阵容与 20% 规则策略。可固定加入另一套牌的模型；历史快照轮换不移除这些固定对手。
- 分别记录按实际对手阵容和对手策略划分的先后手统计，不能把两种分组相加当成更多对局。
- 训练只记录汇总计数。独立分析轮记录换牌、首回合行为与资源，并比较两套模型分别对两套固定模型构筑的“学习换牌／全部保留”，共 8 个单元。对照双方权重、构筑、种子与先后手样本一致。
- 修复对手换牌事件泄露卡牌实例 ID 的问题；玩家仍可查看自己的换牌，公开录像不包含双方隐藏换牌内容。

## 验证

- 相关自动化回归：142 项通过。
- CPU 原生编译预检：两种先后手各 26 个换牌候选，共 52 个候选通过，覆盖观测编码、动作顺序和状态转移。
- API 测试实际调度模型更换 3 张牌，并核对对手视角与录像隐私。
- 使用确定性测试策略在真实规则引擎运行 16 局，生成完整 8 单元分析报告。这验证报告链路，不是训练所得胜率。
- 原有两套 v2 权重未变；本次 128 局兼容验证仅用于当前规则下的加载准入。其对手使用随机公开构筑，不能充当创生对快攻固定构筑的胜率结论。
- 本机没有 CUDA，GPU 预检尚未执行；训练入口会在优化器开始训练前执行 CUDA 规则与换牌预检，失败即停止。

## 今晚继续训练的边界

按用户最新决定，今晚先完成卡效更新，再以最终规则版本预检和训练，不随每次卡效修改反复适配旧模型。旧 v2 模型仍然全部保留起手牌；框架升级不代表旧权重已学会换牌或针对快攻的起手策略。新能力需通过新训练和独立对照报告确认。

命令与参数见 [公开角色训练说明](duel-v2-public-training.md)，完整产物要求见 [综合训练报告规范](duel-v2-full-training-report-spec.md)。
