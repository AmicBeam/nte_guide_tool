# V2 统一效果与属性计算

2026-09-21，按用户确认落地。攻击力为首批迁移对象，同时提供费用、伤害数值和能量获取许可的统一查询入口。效果的数值和触发条件沿用当前卡牌定义；本次用户额外确定：回合计时效果按绝对回合编号过期，计时方进入新回合后先到期，再执行回合开始效果。自然到期统一发出扳机，主动移除不发出该扳机。

## 模块职责

- `engine/duel_v2/modifiers.py`：纯数据效果实例、条件注册、叠加、属性查询、到期筛选与兼容投影，不访问持久化或网页。
- `engine/duel_v2/attack_modifiers.py`：将角色面板和本次操作修正汇入同一个按层计算器，返回攻击值与来源明细。
- `engine/duel_v2/effect_lifecycle.py`：回合时钟迁移、自然到期通知及持续终结生命周期；协调内容回调与既有额外行动队列。
- `content/duel_v2/characters/*.py`：注册触发效果和 `aura_effects`，决定具体卡牌条件与数值。内容通过 `EffectContext.apply_effect` 施加效果。
- 公开投影、回放和历史只使用后端计算结果；前端不判断光环条件或效果是否到期。

## 实例与来源

效果保存在持有者 `effects` 数组，`effect_seq` 为持有者的实例序号。每条记录包括 `effect_id`、`definition_id`、`source_entity_id`、`source_key`、`kind`、`property`、`op`、`value`、`layer`、`scope`、`label`、`clear_on`、`visibility`；可选 `expiry`、`conditions`、`consume_on`、`stack_key`。

实例身份使用实体 ID，不用角色模板 ID 区分双方同名角色。`source_key` 区分来源卡牌或能力。效果数据只含 JSON 数据，不保存函数、表达式或代码。条件采用已注册 ID 与参数；未知条件拒绝处理。动态数值由注册的角色内容函数计算，返回同一格式的只读修正，不写回快照。

叠加方式：`independent` 分别保存；`refresh` 保留原强度、刷新描述的期限；`max` 取较大强度并采用本次期限；`replace` 替换。默认按定义、来源实体、来源键、属性和范围匹配；显式 `stack_key` 可让规则要求共享上限的不同来源使用同一组；`max_stacks` 限制独立实例数，超出时替换最早实例，保留各自截止时间。下次攻击加成沿用原本的跨来源取较大值，不改成相加。

持续效果默认独立于施加者存活，目标倒地时清除；光环默认随来源状态休眠，来源恢复后可重新生效。是否在离场、倒地、终结结束或来源武备移除时删除，由 `clear_on` 明确声明。换武备只移除绑定该实体和旧武备、声明 `source_removed` 的效果，不移除其余来源。

## 统一到期与自然到期扳机

`expiry` 记录 `side`、`turn`、`phase`。回合持续效果使用 `turn_start`，截止为施加时计时方回合号加持续回合数；“本回合结束”使用当前回合号及 `turn_end`。新效果不保存逐回合递减的剩余值。

新回合先导入旧存档计时，再推进回合号；回合提示事件只用于演出，不执行业务效果。第一项规则结算是批量摘除全部到期效果，再派发 `GameEvent.V2_EFFECT_EXPIRED`（内容函数 `on_effect_expired`）。完成自然到期扳机后，才执行通常恢复、回合开始效果、区域结算及其他流程。所有到期修正先被摘除，因此一个到期扳机不会读到同一批中尚未清除的攻击增益。

扳机向双方存活角色广播已到期的效果实例及持有者实体 ID，监听内容通过来源／持有者实体 ID 筛选。真红只响应自己的终结实例，不能响应队友或对方终结。每个实例自然到期只通知一次。`leave`、`down`、`source_removed`、`ultimate_end` 和刷新替换属于提前移除，不通知自然到期。后端也产生公开 `effect_expired` 记录；私有效果不公开其定义或来源。

持续终结的截止也记录为 `status.ultimate` 效果。真红只在自己的该效果自然到期时追加攻击，主动换下或倒地不追加。到期批次先移除数值修正并完成持续终结退出，再广播自然到期扳机。真红的末次攻击携带仅限该操作的能量获取限制，保留既定不回能规则，操作结束即清除；无需让已经到期的终结继续保持激活。此扳机属于到期阶段，不是普通回合开始效果。

此顺序按用户最新口径替代旧的“开始效果后递减”：真红加攻、翳减攻均在到期回合开始效果前失效；哈尼娅到期回合的通常光环获取不再翻倍；埃德嘉到期回合不再执行终结的通常开始治疗。倒地恢复、战斗区周期伤害和兽牙个人计数仍由既有专用规则处理，本次不改其计数含义或数值。

## 属性与动作查询

`evaluate(state, side, subject, property, base, query=...)` 汇总持有效果与实时光环，返回 `value` 和 `contributions`。查询不修改快照，不消耗次数、层数或资源，也不递归读取自己计算中的最终属性。`self / allies / other_allies / enemies / all` 决定对象；条件可检查来源存活、前排、武备、终结、当前回合及资源阈值。动态光环条件在每次查询时检查，不通过反复给目标加减属性维持。

每个计算层按设置值、加减、倍率、允许、禁止处理；同操作按稳定提供顺序。属性之间分开：

| 属性入口 | 集成位置 |
| --- | --- |
| `attack.panel` | 持续与限时攻击增减益 |
| `attack.override` | 薄荷对方回合面板覆盖 |
| `attack.hit` | 本次攻击、战斗牌、下次攻击及小吱／残虹／早雾条件加成 |
| `card.cost` | 后端出牌费用查询，随后应用通常瞬发支付规则 |
| `damage.resistance` | 匹配属性的受伤抗性修正；小吱本回合一次性减抗已迁移 |
| `damage.amount` | 入射伤害数值修正；其后仍执行既有免伤、抗性、护盾和生命结算 |
| `rule.damage_immune` | 真红限时免伤，和加攻使用同一绝对时钟 |
| `rule.gain_energy` | 能量获取许可；真红条件限制已迁移 |

攻击顺序固定：角色面板 → 战斗准备修正（含伊洛伊与哈尼娅） → 战斗牌覆写 → 本次攻击各项加成 → 战斗区减攻 → 最低零。小吱覆写不吞掉后层明确的攻击加成；薄荷面板归零不吞掉战斗牌本次加攻。最终数值转为整数，非有限数值禁止进入实例。当前生命、当前资源的变化仍使用伤害、治疗、回能等明确操作，不在查询中顺带修改。

本次攻击修正随操作产生，不作为跨回合状态保存；`consume_on=attack` 的预备加成仅在真正发动攻击时消费，面板和预览查询不消费。永久成长现由独立 `permanent_growth` 保存，与 `base_stats` 和当前武备基础面板共同形成输入；详见 [武备与永久成长分层](duel-v2-equipment-layers.md)。

## 存档、公开信息与迁移

`atk_buff`、`atk_buff_expiring`、`atk_debuff`、`form_attack`、`timed_attack`、`next_attack`、`damage_immunity_until` 的旧快照可读取。查询只读适配；写入新效果或推进时钟时导入实例，移除对应旧字段。临时加攻是旧 `atk_buff` 的一部分，导入时拆分，不重复计算。旧相对时间先换算截止回合号，再推进时钟。

公开卡面保持 `attack`，增加 `attack_breakdown` 和允许公开的 `effects`；攻击事件含 `attack_modifiers`。私有效果的定义、来源和条件不进入这些公开字段。原 `atk_buff` 等公开兼容字段由效果实例派生，不写回角色状态，避免出现两份可变真源。回放使用同样的公开数据；旧回放不追补无法还原的来源。

独立旧编译执行器不自动获得新效果解释能力；已训练模型的观察兼容字段继续提供，但本次不训练、不修改权重、不绕过规则身份或启用授权校验。
