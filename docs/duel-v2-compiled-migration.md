# 创生 / 覆纹快攻常驻编译引擎验收（2026-09-15）

## 范围与结论

Grok 最初交付的 frozen starter C 引擎只在 Mac 跑过 native 对拍，CUDA/torch 跳过，且每步仍逐局转换列表。接手后完成 Windows NVRTC 接口、GPU 常驻状态、PPO 分派、两套预组覆盖及连续整局对拍。长训入口是 `scripts/train_duel_v2_session.py`，旧默认张量/网站编码器路径保留，不将旧路径称为完整 GPU 训练。

支持精确的创生、覆纹快攻镜像构筑；不支持自选卡、cross 或其他预组。每个预组单独编译相同规则源加其构筑表，单独训练并保存权重。牌局、合法动作、重置、策略推理和 PPO 更新使用 CUDA；native 使用同一 C 源做 oracle 验证和训练后评估的候选映射。没有 Python/tensor 规则 fallback。

## 本次修复

- NVRTC 使用正确的三参数 step/reset ABI，设备函数/常量加 CUDA 注解，提供列表验证接口并正确释放模块。
- GpuState 字段绑定连续 int32 批次的视图，热路径不再每行 `int(tensor)` / 列表 pack/unpack / 整局 CPU↔GPU 复制；重置只作用于终局行。
- PPO 起始合法动作与规则对手推进走所选后端。学习方座位与先手独立分配，修复两者都由种子奇偶决定、导致学习方总是先手的问题。
- 补齐覆纹、反击覆纹、薄荷穿透/响应溢出/无视护盾/自动出击/终结免伤、白藏自伤叠攻/条件攻击/斩杀/致命前治疗、伊洛伊按倒地人数伤害与倒地回调。
- 连续整局对拍修复：娜娜莉终结追击不得套给其他角色；援护技免反击及倾陷；终局后停止弃牌、回合和资源结算；九原追加创生锁定原目标；伊洛伊回能先于薄荷自动出击；复活候选按正式引擎倒地状态筛选；忽略护盾也覆盖直接攻击玩家。
- 正式 Python 引擎的 `on_damage_dealt` 改为角色本人回调，白藏不能用队友造成的伤害触发斩杀；本人/队友伤害回归已补。`on_damage_taken` 当前也使用本人回调。
- `resident_public_v1` 张量编码保留自己的完整手牌和双方公开状态，隐私回归验证对手手牌、牌库内容和 RNG 不影响策略输入。不与网站 V2Encoder 权重兼容。
- 规则哈希纳入实际 C 生成源、布局、IR、lowering 和卡池锁，而非只哈希支持名称列表。

## 端到端性能

完整 resident 公开编码，hidden=128、PPO epochs=2、minibatch=1024，horizon=16。下表取预热后的两次更新范围；包含采样、对手行动和优化器，不是单独空 CUDA kernel 的速度。

| 并发局数 | 创生学习步/秒 | 快攻学习步/秒 | PyTorch 峰值显存 |
| ---: | ---: | ---: | ---: |
| 1024 | 17,493–18,008 | 19,216–19,224 | 约 936 MiB |
| 2048 | 21,602 | 22,169–22,966 | 约 1,421 MiB |
| 4096 | 23,797–23,854 | 24,495–24,728 | 约 2,767 MiB |

4096 局创生每次更新约 2.75 秒，其中采样约 0.70–0.72 秒；快攻约 2.65–2.68 秒，其中采样约 0.65 秒。剩余主要时间在 PPO 更新，未观察到旧版逐局 CPU 装箱导致的严重供数阻塞。不是“GPU 利用率必须 100%”或无任何 CPU 同步的保证。

复现：`python scripts/benchmark_duel_v2_resident.py --n 1024 2048 4096 --output DIR/scaling.json`。基准模型不作为训练权重交付。
