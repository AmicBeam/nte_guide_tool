# 排轴计算模块

### 觉醒共鸣手动开关（2026-09-22）

按用户要求，配装中三觉、六觉共鸣可分别手动点亮或熄灭，不反向修改A–F。每次修改任一A–F节点后，两个共鸣重新按当前激活数量自动更新：至少3个点亮三觉，6个点亮六觉。其他配装修改、切换角色、刷新和保存加载保留手动状态。

`team`与`character_builds`中的可选 `awakening_resonances` 数组只保存3、6，空数组表示全部关闭；缺失时沿用旧轴按节点数量推导。技能等级、共鸣Buff、入场资源与机制展示均读取该状态，A–F节点和觉醒数量仍独立。既有 `awakening_count_min` 的3/6门槛及 `awakening_count_max` 的2/5反向门槛用于共鸣，优先读取手动状态，其他数量门槛不变。共鸣属于练度，不加入广场去重hash。本文其他按数量触发共鸣的表述均为默认自动联动口径，手动配置按本节覆盖。

验证：`python3 -m unittest tests.test_shaft_resonance`、完整排轴回归，以及配装页手动开关、A–F联动和刷新检查。


按用户2026-09-11最新口径，通用「无」配置 `switch_gap_after_ticks=1`，其后的其他角色前台动作允许间隔0.1秒；若轴配置的间隔更小则沿用更小值。前台与后台放置的「无」均适用；自身仍为0秒，不开启时停、冻结区间或动作遮罩，并列动作保持原耗时。此属性只调整动作开始间隔，不豁免角色切回的1.2秒自检。

排轴计算是独立的配装与伤害模拟工具，页面入口为 `/shaft`。它提供队伍配装、0.1 秒动作轴、伤害结果和方案广场。

## 模块范围

- `/shaft/build`：角色、弧盘、弧盘精炼、卡带、觉醒、副词条与敌人配置。
- 配装页右侧总览底部可计算副词条贡献度：基准临时将每位角色的通伤、暴击、暴伤、环合、倾陷、攻击%、生命%、防御%各设为15条，将小攻击、小生命、小防御设为0；随后对上述11类词条逐个角色、逐个词条额外增加5条重算全队总伤。结果以“角色 × 词条”二维表格只显示归一化贡献度，全队最高提升为100%，无正提升的格子显示—。每个角色行内收益最高的4个词条按第1至第4名使用四档颜色、浅色背景和描边高亮，其余非零值弱化显示。分析只读取前端内存中的轴和数据目录，不访问后端接口，也不修改当前配装、本地草稿或主动保存的对比快照。
- 倾陷强度只提高角色贡献的倾陷伤害，不提高动作削减的倾陷值，也不改变全轴总倾陷或倾陷触发频率。
- 卡带下拉框完整展示当前目录并允许跨属性装备；两件套直接提供10%卡面指定属性伤害，不再按装备者属性筛选。属性伤害使用光/灵/咒/暗/魂/相六个独立字段；卡带主词条和属伤空幕自动写入当前角色自身属性字段。
- 弧盘下拉框按适应类型筛选后保留 `arcs.json` 中的相对顺序；每次新增弧盘都插在同适应类型现有弧盘之前，使最新录入的弧盘成为该类型第一项。当前等离子弧盘第一项为「远行者之声」。
- 配装页角色自身伤害占比不包含环合与倾陷伤害；环合、倾陷与角色共用贡献占比列表的行式布局和“分析详情”入口，两类伤害分别打开独立弹窗；环合弹窗可继续拆分到创生、浊燃、黯星等来源，创生复制体的伤害在占比展示中并入创生。
- `/shaft/rotation`：动作轴编辑、前后台状态与伤害明细。
- 动作右侧实时面板只显示该动作伤害属性对应的“X属性伤害”；配装页角色面板只汇总角色自身属性的“X属性伤害”。
- 排轴自检会把所有“前台放置、实际时长为0、且不是极轨终结”的动作报告为“该动作的时长未实装”；原生后台动作、手动放到后台的普攻、专用“无/切人”节点，以及通过 `duration_implemented` 明确声明真实耗时就是0秒的动作不触发该提示。
- 排轴自检会检查角色离开前台后再次切回的间隔；若使其离场的其他角色动作或离场至回场之间没有具备遮罩能力的0秒前台Q或专用遮罩动作，两次前台变更节点必须至少间隔1.2秒。角色离场前自己的遮罩和回场动作自身的遮罩不提供豁免；Q类型但原始耗时大于0的动作（例如真红「穿梭」）也不豁免。灵可「时停选人」是0秒无效果专用遮罩，不视为Q且不触发Q类效果。
- 循环轴会把上一轮动作产生的技能 CD 结转到本轮轴头；若轴尾到下一轮同技能或共享冷却技能的间隔不足，自检沿用“动作 CD 尚未结束”提示。
- 动作轴预览的时间刻度按真实计算时间绘制；0秒Q为可读性插入的虚拟展示宽度不会增加刻度时间，轨道网格线与尺子使用同一时间映射。
- 时间轴可视范围取前台动作与后台动作显示终点的较晚者，末尾仍留 1 秒。超出前台终点的后台动作因此完整画出。总轴长、DPS 分母和循环轴实际时间仍只按前台动作计算。
- 拖动动作时，红色时刻线始终对齐动作卡片投影后的显示起点；即使轴中存在多个时停0秒区间，后台动作的原始计算 tick 与显示 tick 不同，也不会出现卡片与时刻线横向错位。
- 在已有轴中插入0秒前台Q时，编辑器会先为该动作统一腾出一段虚拟展示宽度，并等量后移插入点及其后的所有前台、后台动作；这段位移不增加真实轴长，且不会打乱后续动作的相对顺序。
- 专用「无」节点可在前台与后台轨道间拖拽；放到后台时不占用前台动作轨道，但仍会在该节点开始时把对应角色切为当前前台，并正常触发离场、入场与切回间隔自检。
- 非本人在线轴保存到本地后，后续预览会识别对应本地副本并把按钮改为“更新到本地”；更新复用原本地轴，不重复创建。旧版按“在线标题 - 作者”保存且尚未记录来源的本地轴也会被识别，并在首次更新时补写来源关系。
- 撤销、重做、复制、粘贴、删除、时间光标移动和动作键盘移动等排轴快捷键只在 `/shaft/rotation` 生效，不拦截配装页或广场页按键；Escape 仍可用于关闭当前弹窗。
- 排轴工具栏在“撤销”左侧提供“前移”按钮，与 `Ctrl/⌘ + Backspace` 功能一致：当前动作及其后的动作会整体前移到保持既有动作顺序、同角色占位、前台锁定与切人最小间隔所允许的最早位置，不必等待其他角色的完整动作结束。
- 动作级 `can_background_override` 可让任意显式配置的动作从前台手动放到后台；灵可「小贞同频」默认前台、可后台，保留1.5秒耗时、援护伤害分类与技能等级来源。动作级 `locks_foreground_switch` 可显式控制前台锁定：残虹「幻e」在完整2.2秒动作期间禁止其他前台动作开始；小贞同频放在前台时也显式不锁定前台。
- 删除一个或多个动作时，只回收本次删除直接释放的连续占位；开启时间晚于全部被删除动作的尾部动作使用同一个前移量，尽可能保持彼此的相对时间位置，不再优先拉近当前角色的下一个动作。玩家主动留下的其他空白继续保留。
- 四号位的周期伤害标记悬浮说明向鼠标上方展开，避免末行 tooltip 撑出时间轴纵向滚动条；其他伤害标记保持原有方向。
- 时间轴伤害标记的 tooltip 不展示计算后的“乘区”：普通周期伤害展示实时攻击/生命/防御、倍率、层数、增伤、暴击暴伤与敌人减益；环合伤害展示基础值、环合强度、频率与敌人减益，并统一给出最终增伤和最终伤害。
- 动作详情的“生效增益”按提供者所在的队伍槽位分组展示，同一角色自身、弧盘和卡带提供的增益保持相邻；同一角色组内保留引擎原有顺序，无法归属角色的手动增益排在角色分组之后。
- 时间轴动作可双击打开编辑框；当前安魂曲 `a4远` 与 `e` 可勾选“脱手”并占用0.5秒，黑羽 `魔a5` 可勾选“脱手”并占用0.6秒并以不同字体颜色标识。有效耗时大于0、类型不是“援护”且未显式禁用的动作还可勾选“打断”；援护技、前后台0秒动作、真红 `龙e` 及海月 `水母弹/水母闪反` 均不显示也不接受打断。编辑框用0.1秒精度的滑条把占用时间缩短到当前普通/脱手时长以内，并选择0至原动作段数；按“倍率、回能、环合、倾陷”顺序实时预览截取结果。当前所有可打断伤害动作均已有逐段配置（黑羽使用用户提供的工作簿，其余使用腾讯表），不再使用聚合均分兜底。已打断动作使用优先于Q遮罩等样式的红色边框。每名角色都有无效果、0.5 秒、仅前台的通用「闪」，动作库中位于「无」之前。旧安魂曲 `a4脱手` 与 `a4闪` 会分别迁移为新版脱手步骤，以及“脱手步骤 + 闪”。
- 援护技的前台角色环合不足100时，自检继续报告当前值和不足值，但援护仍按角色属性触发环合，并把该前台角色现有环合值清零；属性组合无效、没有可用前台角色等其他非法条件仍不会生成环合。
- 循环轴设置可按当前队伍角色配置起始能量、起始环合值、个人资源和一个起始环合效果；环合效果使用单选下拉框，默认“不携带”，仅展示持续时间大于0的环合。每名角色最多携带一个。残虹还可分别输入自带蚀心、鸩火层数，范围为0–10层，0层表示不携带。关闭循环轴时保留配置但不参与结算。
- 按用户 2026-08-11 补充口径，循环轴自检只检查循环配置的自带环合所导致的冲突：创生最多同时存在3个独立实例，其他环合最多1个实例；自带实例与轴内产生实例合计超限时告警，纯轴内的正常实例冲突不告警。所有环合每次触发都会正常生成新实例；达到容量时挤掉开始时间最早的旧实例。实例上限不会因角色具备刷新、加层或延长能力而放宽；例如残虹轴内已产生浊燃时，再携带浊燃仍视为冲突。黯星旧实例被挤掉时立即结算其伤害，再保留新实例，不等待旧黯星自然结束。
- 循环起始环合会先在上一轮负 tick 预热；若状态跨过轴尾，则在本轮 0 tick 继承剩余持续时间、层数、频率和下一次伤害节拍。继承实例不会重新按完整持续时间生成，0 秒 Q 的冻结区间也只影响显示时间映射，不重置环合结算相位。
- `/shaft/plaza`：公开方案浏览、按名称或备注关键字及角色筛选、排序、赞、踩和收藏；同一账号对同一方案的赞、踩互斥。
- 广场名称/备注搜索会等待用户停止输入、完成本轮编辑后再请求后端，不在每次按键时立即搜索；带关键字的请求按账号或访客限制为 3 秒一次，编辑完成时若仍处于冷却期，页面显示“搜索中”，并在冷却结束后自动执行最新搜索。
- 登录用户可以保存、更新、另存、备份和删除自己的方案；已保存轴需要先把标题改为不同名称再另存，未改名时点击“另存”会提示填写新轴名并聚焦标题输入框；同名保存时可改名、覆盖或取消。
- 每个账号最多创建 50 个私有排轴，更新现有轴和上传公开快照不占用新的私有轴名额；“我的排轴”区域只展示私有轴总数，不展示限制数。
- “我的排轴”卡片支持生成稳定的分享链接并自动复制。分享链接读取原轴的最新已保存版本；打开后位于 `/shaft/rotation`。未登录访客可以直接查看，但处于只读状态且分享内容不覆盖浏览器原有本地草稿；登录用户按独立工作区编辑，不会写回分享者的原轴。若当前工作区有未保存更改，必须先选择放弃、更改后保存、另存或不打开分享。
- 上传从“我的排轴”卡片发起，并创建关联的独立公开快照。上传成功后原卡片的“上传”改为“更新 / 下架”：更新以私有原轴的最新保存版本覆盖同一公开快照并保留互动计数；下架只删除公开快照并保留“我的排轴”中的私有原轴。
- “我的排轴”与收藏列表均支持按名称或备注关键字、角色筛选，并可按最新、DPS、点赞或收藏排序。
- 我的排轴、收藏和广场卡片均显示队伍角色头像与名称，头像右下角以小号角标显示已激活觉醒数；备注固定占一行并以省略号截断，前端最多读取 64 个字符生成预览，完整备注保留在悬停提示和详情中。
- 卡片版本号表示该轴最近一次保存或生成公开快照时使用的数据版本；应用启动和后续版本发布不会批量改写历史轴版本，用户再次保存私有轴时才更新。
- 点击广场排轴卡片先打开只读时间轴预览，不直接覆盖当前工作区。预览弹窗可以取消或保存到自己的私有排轴；保存副本时标题自动变为“原标题 - 作者名”，并保留原轴的备注、配置和计算结果。
- 动作轴预览底部展示 DPS、轴长，以及与排轴页右侧贡献列表同口径的各角色、环合伤害和倾陷伤害整数占比；连续动作以空格分隔，动作条空间不足时优先保留动作名、隐藏时长。
- 角色权限分为正式、受邀和测试三级：正式用户只能使用公开角色；受邀用户还可使用半开放角色；测试用户可使用全部未公开角色。测试权限沿用 `Player.shaft_test_whitelisted`，受邀权限保存在 `Player.shaft_invited`。使用
  `python3 scripts/manage_shaft_test_whitelist.py add <玩家账号>` 加入白名单，
  `remove` 移出，`status` 查询单个账号，`list` 查看全部白名单账号。
  使用 `invite <玩家账号>` 设置受邀用户，`uninvite` 取消，`list-invited` 查看全部受邀用户。
  Windows 服务器也可以编辑 `scripts/add_shaft_test_whitelist.bat` 顶部的
  `PLAYER_UID` 后双击运行，脚本会自动加入白名单并再次查询状态。
- 机器人管理员可以私聊发送 `公开角色 <角色名>`（别名：`解除角色未公开`），将角色持久化提升为完全公开。管理员身份读取 NoneBot 的 `SUPERUSERS` 配置；灵可、残虹与伊洛伊均为公开角色，黑羽按用户 2026-10-08 要求改为公开角色。历史数据库启动时会自动迁移对应访问级别。
- 含受限角色的公开轴只对权限级别足够的账号可见。服务端会从权限不足账号和未登录访客的广场、收藏列表中排除这些轴，直接访问对应公开轴 ID 时也按不存在处理；私有轴仍遵循仅所有者可见。
- 持有随机分享链接的访客可以匿名只读查看对应私有轴，包括含测试角色的分享轴；只读加载与重算时保留原队伍的测试角色和对应动作，不按目录的不可选择状态替换角色或删除动作；该能力不授予保存、发布或测试角色构筑权限。

详细公式、数据模型和交互设计见 [排轴模块设计](../../../docs/shaft-module-design.md)。角色动作资料见 [角色动作说明](../../../docs/shaft-character-actions.md)。

## 代码边界

- `app/modules/shaft/domain/`：数据加载、buff 注册和领域计算支持。
- `app/modules/shaft/service.py`：页面 API 的应用服务与持久化协调。
- `app/modules/shaft/templates/shaft/index.html`：页面模板。
- `app/modules/shaft/static/`：前端、计算引擎与静态数据。
- `scripts/shaft_compute.js`：供离线回归与诊断使用的 Node 计算包装；保存和上传链路不调用它。
- `scripts/import_shaft_xlsx.py`：离线数据导入。
- `tests/test_shaft_*.py`：公式、数据、布局和自检测试。

排轴是独立工具，不进入异象对决规则层。运行时只读取仓库内维护的数据，不依赖用户本地 xlsx。

## 永久 Buff 约定

- 需要画在角色时间轴上的永久状态统一配置为 `duration.type = time`、`ticks = 9990`、`loop_carry = true`，即以 999 秒 Buff 线表达“本轴内永久持续”；时间轴只绘制当前可视范围内的线段，不改变其实际 999 秒持续时间。
- 仅提供常驻数值、无需画 Buff 线的被动使用 `trigger.event = passive` 与 `duration.type = permanent`，默认进入动作详情的生效增益但不绘制时间轴 Buff 线。
- 不为单个角色另设永久状态或超长时长展示逻辑。伊洛伊长e的“退行（3名队友）”、白藏言灵等可见永久状态复用同一套 999 秒 Buff 线机制。

弧盘精炼的 1–5 档数据来自 Nanoka 1.2，生成文件为
`static/data/arc_refinements.json`。每张弧盘按原有录入数值映射默认
精炼等级，玩家只能在精炼 1–5 中选择；旧配装没有精炼字段时自动
补为该弧盘的默认等级。面板与已实现的弧盘 buff 使用对应 Nanoka 档位。

### 失谐与破鞘（2026-09-18）

普通敌人倾陷上限70，轨外之境50。每次新施加黯星或浊燃时，若另一状态仍有效，触发1次失谐；黑羽续生黯星同样参与，单纯浊燃加层不重复触发。每次失谐削条量为当时倾陷上限×15%。敌人等级高于触发角色且等级差不超过5时，该削条减半；等级差大于5时，削条只有基础的20%。敌人等级不高于角色时保持完整15%。2026-09-24 起按用户口径替换此前的 20%÷(等级差+1)。不改变既有单次倾陷伤害基数与其他环合伤害公式。

达芙蒂尔「破鞘」在每次失谐额外削减初始倾陷上限的10%，该额外削条不受等级差影响，即使已有2层也生效；随后将倾陷上限降低初始上限的10%，最多2层（普通最低56、轨外最低40），持续30秒、再次触发刷新。先按触发前上限结算本次失谐，再更新上限。降低倾陷上限只影响削条与倾陷频率，不降低单次倾陷伤害；伤害基数与可变倾陷上限独立。上限削减机制来自Everness核实的「破鞘」，叠满仍额外削条及不受等级差影响来自本次补充。

排轴仍按整轴倾陷频率估算伤害，不模拟敌人实时倒地：动作和失谐分别按发生时有效上限折算为等效削条量，频率使用「初始上限÷等效削条量＋恢复时间÷轴长」的倒数。`total_stagger`记录实际削条总量，`effective_stagger`用于频率；`dissonance_events`列出每次失谐、破鞘额外削条、层数与上限前后值。循环预热仅继承仍有效的破鞘上限削减，不重复计入上一轮削条量。安魂曲400%「失谐强化」仍按原有手工后台动作处理。
