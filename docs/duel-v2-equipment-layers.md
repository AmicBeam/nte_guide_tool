# V2 武备与永久成长分层

2026-09-21 按用户要求进行结构调整，保持现有武备数值、永久成长保留、装备回满与倒地规则。正式实现位于 `engine/duel_v2/equipment.py`。

## 三层数据

- `base_stats.attack/max_hp`：开局角色基础面板，不混入永久成长。
- `permanent_growth.attack/max_hp`：永久成长量；换武备、返回备战区、倒地后保留。
- `effects`：其他持续增减益、条件光环与一次性修正，继续使用统一效果机制。

武备基础面板由当前武备定义提供。通常攻击为武备基础攻击加永久攻击成长，再进入统一增减益／面板覆盖／本次战斗计算；没有武备则使用角色基础面板。旧版单属性武备及旧 `growth/gaze` 快照保留原有兼容计算，不改变历史数据语义。当前完整武备面板对负永久差值的旧零下限也保持不变。

`stat_layers` 与 `attack_breakdown.layers` 提供来源分层，查询不修改快照。原公开策略字段 `base_attack/base_max_hp` 仍提供“角色基础＋永久成长”的派生值；存档内的新权威数据是上述独立两层，不反复从武备面板扣回成长。

## 装备操作

`equip_weapon` 负责导入旧字段、卸下旧来源、分配本次装备身份、安装新武备及更新生命上限；它不主动治疗。`refill_after_equipping` 单独执行既有装备回满规则。`EffectContext.set_shape` 显式按顺序调用两者，再发布装备事件。

装备回满保持原行为，不改为普通治疗，不额外触发“受到治疗”类异能。永久生命成长仍同时使当前生命和生命上限增加同样数值，保留原有缺血量；更换武备时再按装备规则回满。

倒地卸下武备，清除相应临时效果；生命上限恢复为角色基础生命加永久成长，不清空永久成长。当前生命仍为 0，之后按通常恢复规则恢复。

## 来源与扳机

每次装备记录独立 `equipment_id`，同名武备重打也产生新身份。内部可记录来源牌实体，公开投影仅显示武备 ID 与装备身份，不额外公开牌实例 ID。

旧 `shape` 字段保留为槽位选择器，服务旧存档、既有规则查询和前端时装映射；它不保存最终攻击／生命。旧快照缺少装备实例时使用稳定的兼容来源键，下一次真实装备分配新身份。

现有 `shape_events` 自动以武备来源上下文执行；新增 `weapon_hooks[card_id][timing]` 由注册表选择当前装备后派发。零 Z06/Z07/Z08 的回合结束效果已迁入此入口。角色异能回调仍先执行，随后执行当前武备回调；不重置每回合次数。

`for_weapon`/`weapon_source` 提供当前装备来源键，`apply_effect` 自动使用绑定来源。需要随武备移除的效果声明 `source_removed`，统一按来源实体＋装备身份清除；普通已给予的攻击增益默认独立保留，不因来源武备卸下而扣回。复杂条件和具体卡效继续由角色内容定义，不在引擎硬编码角色 ID。

## 旧存档与导出

旧 `base_attack/base_max_hp` 字段仍可读取，在首次修改永久成长或装备时按原角色基础值导入 `permanent_growth` 并删除旧字段。读取本身不回满生命、不改变伤势，也不会重复累计。旧工具写入的聚合字段仍作为兼容输入处理。

观察、公开回放和策略元数据增加 `stat_layers` 与 `equipment`。旧数值观察字段和武备 `shape_id` 不变。GPU／IR 打包适配器改用派生基础面板读取函数，防止新存档缺少旧字段时导出为零；本次不运行训练或改动模型授权，也不据此声明旧独立编译执行器已覆盖全部新效果。

## 验证

`tests.test_duel_v2_equipment` 覆盖换装前后成长、受伤时装备与独立回满、旧快照反复导入、同名换装来源、定向效果移除、倒地与永久成长、武备扳机切换、JSON／公开投影。另回归原有角色、武备、预览、回放和教学测试。

本次相关回归 179 项通过，包含新属性层的 IR 数值导出检查。另跑含旧引擎综合用例的 135 项回归时，仍有既有伊洛伊倒地链及娜娜莉追击预期的 5 个方法失败，不计为通过。浏览器使用真实牌桌模板与渲染器的隔离局面确认武备面板、永久成长及增益叠加：娜娜莉装备预备备后显示攻击 5、生命 7/7，角色大图一致。临时页面已移除。
