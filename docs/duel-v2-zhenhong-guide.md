# 真红展开辅助规则策略

用户于2026-10-07最终指定优先组合：零战斗牌蓄满环合→翳战斗牌同时获得兽牙与延滞→光系积累环合→创生触发盈蓄。此为人工推理指导方向，不新增卡牌规则，不是模型训练奖励。现行效果和资源仍以完整手册及正式引擎为准。

## 当前接口与边界

`engine/ai/zhenhong_guide.py:recommend` 接收当前状态、行动方及模型搜索动作，返回建议、原因、原／新规则排序、阶段、实际检查计划数和耗时。当前是离线可调用的实验组件；默认网站高级人机仍走原模型及搜索，不自动启用本组件。单轮数据不进入文档，见对应 artifacts 报告。

每次真实决策重新判断，默认至多24个一／两动作计划、3个独立信息集采样世界、0.75秒软截止。每个计划可能完成当前3个世界检查后才检查时间，实际时间如实记录；不把该预算算成原32次神经搜索模拟。行动阶段采样失败、预算不足、非行动方、选择阶段、真红倒地或终结中保留模型动作。起手换牌使用独立的零采样留牌约束。函数不写快照、日志、数据库或模型参数。

## 展开与例外

- 先检查完整的零战斗牌→翳战斗牌组合；能同回合完成时不先单铺兽牙。组合不可行时，再考虑 I04 真正零费、I03 瞬发等替代准备；已有兽牙不因为计数更大而自动重复铺设。
- 兽牙仅暂停延滞，不能凭空施加延滞。光／相衔接才产生延滞；相／灵没有环合。第一位出战者、同属性交换、留场再攻不能被当作入场环合。
- 延滞已有时转向当前可支付的光系来源。资源逐角色独立，需存活、最近前排及足够环合；使用引擎当前 `harmony_cap`，不写死所有阶段都是2点。
- 通过光／灵创生兑现盈蓄。已有延滞且立即能兑现时，不强制先补兽牙；兽牙存在但翳倒地时，按实际剩余状态继续判断。
- 先比较正常终局胜利与真红存活，再检查未限伤的真红是否会被公开面板的单次攻击击倒，然后比较实际盈蓄增量与准备阶段。前排威胁只是一项保守启发式，不保证能预测多段连锁、手牌加攻或持续伤害。
- 不为凑链牺牲已验证的取胜动作；模型动作在三个采样世界均直接获胜时保留。没有穷举全部隐藏世界，不称为必胜证明。

排序是明确的人工字典序：终局结果、真红存活、单击安全、实际盈蓄增量、稳定准备阶段、最近合格来源的环合进度、双方玩家生命、己方存活人数和剩余行动力。它不是WDL或校准胜率。相同排序优先保留模型首动作；可以指导准备顺序，但可能因短视启发式拒绝有收益的牺牲，需实战对照。

## 信息边界与验证

仅通过现有 `sample_world`／恢复采样器生成世界，不直接使用真实对手手牌、牌序选动作；后续动作须在三个世界均合法，仅落地计划首动作，未来抽牌后重新判断。模型和引导的胜负仍由真实正式引擎完整对局产生。

针对性测试：`.venv/bin/python -m unittest tests.test_duel_v2_zhenhong_guide`。覆盖兽牙准备、光转相延滞、已有延滞直接兑现、两动作中先产生延滞并补真红环合、立即获胜、致死反击、隐藏牌置换不影响建议，以及倒地／终结／预算例外。

离线比较须使用当前同一合法配牌、同模型SHA、共同新种子及等量先后手，基线与指导单列；指导额外算力与策略先验变化的效果分别解释。已看过的反事实胜线仅用于诊断，不充当独立样本。小批结果不自动批准质量、训练权重或网站部署。

## 已知适用限制

首轮冻结验证未涵盖后续新增的「独行」回血、R06独行计数和终结到期群伤；新规则须重新冻结并验证。准备阶段及真红单击安全的人工优先级可能压过残局玩家生命和终结收割，需要比较仅准备／首次启动时介入、启动后退场的更窄候选。该候选尚未实现或验收；当前原型继续离线、默认不启用。

## 完整准备组合优先（v3）

在缺少己方延滞时，先为零战斗牌→翳I01／I02战斗牌的完整两动作组合预留检查预算。三个采样世界均须满足：零打完后存活、确实能为翳入场支付延滞环合、第二张牌仍合法且行动力足够；第二步后两人均存活、己方兽牙与延滞都实际存在，才登记为可用完整准备组合。若零已可付款，单独检查翳战斗牌完成后半段。

这些检查在通用单步短名单与贪心后续展开之前进行，避免先铺兽牙的单步分数耗尽两步预算。仍只提交首动作，下次操作重新核验；不在对方行动或未知抽牌之后盲目执行旧计划。同等人工排序优先更短路线，再保留模型首动作，避免已有可用翳战斗牌时还先打冗余兽牙战术。直接取胜、存活和合法性仍优先；没有足够行动力或付款人倒地时不强排该组合。

旧v1/v2录像及胜率不追改，不能据此声称v3强度改善。当前仍是离线组件。
