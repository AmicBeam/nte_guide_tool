# 线上房间取证

先取证，再判断后端规则、持久化、页面交互还是连接问题。用户指定房间的排查授权涵盖该房间必要的只读查询，不自动授权部署、重启服务器、修改 SSH 配置或修复数据库。制作本 skill 或只询问用法时，不连接服务器。

## 生成查询

从仓库根目录运行（替换房间和服务器日志日期）：

```bash
python3 .agents/skills/online-room-forensics/scripts/prepare_query.py 26F33E --date 2026-09-16 --errors
```

脚本只生成本机临时目录中的 `query.sh`、`query.py`，打印下一条执行命令和 `evidence.json` 路径，不自动联网。证据目录必须在仓库外；已有输出不覆盖。准备后无需把长命令复制到 Windows 控制台。

- 默认只解析 `scripts/deploy_windows_app.local.env` 的字面量 `NTE_DEPLOY_HOST`、`NTE_DEPLOY_PROJECT`，不执行该文件，也不读取服务器 `.env`。不要把生产地址硬编码进 skill。配置缺失时提供 `--host SSH目标 --project Windows项目路径`，或向用户确认实际部署目标。
- 数据库默认项目根 `nte_board_game.db`，日志默认 `logs/YYYY-MM-DD.log`。使用自定义路径时显式传 `--database`、`--log-dir`；不要通过导入 `app` 来发现配置，导入可能初始化数据库和日志。
- 默认保留指定日期日志最后 5000 行；需要更早时间可调整 `--tail-lines`（最多 20000），或针对已明确的日期/时间范围扩展采集器。结果中的 `log_scope` 明确记录不存在或截断。
- `--errors` 额外提取保留范围内最近 V2 异常及有界堆栈；字段名 `unattributed_recent_v2_errors` 表示**尚未关联房间**。按房间、时间、log_id、操作等证据建立关联，不能自动归给指定房间。
- 要核对线上实现，可重复指定 `--source app/modules/card_game/engine/duel_v2/state.py` 等相关文件。仅采集需要的普通源码；脚本限制目录、后缀、大小并拒绝越界符号链接，返回内容和 SHA-256。不要指定密钥、认证配置或已知含秘密的文件。

## 连接与认证

优先复用已经验证的部署目标和认证方式。需要探测时至多先做一次有界只读连接；不要把部署脚本的 `--deploy` 当连接测试。

- **握手超时**：未收到 SSH banner，与密码失败不同。说明卡在哪个阶段；连接成立只证明 TCP 可达。不要直接宣布服务器故障、密码错误或本机 IP 被封。
- **Permission denied**：已经到认证阶段。`BatchMode=yes` 不接受交互密码；用户在另一终端输入过密码不会自动共享给 agent。
- 密钥认证不可用时，把生成的 `bash /绝对路径/query.sh` 交给用户在本机终端运行，密码由 SSH 的终端提示读取。不要索取聊天中的密码，不用 `sshpass`，不把密码写到脚本或命令参数。用户回复完成后直接读取已知结果路径。
- 生成脚本只有一次 SSH 尝试（30 秒连接超时），没有重试循环。失败后先看错误；只有用户确认恢复、目标参数纠正等新证据出现，才再次连接。避免连续重试加重未认证连接占用或触发防护。
- 用户提出 SSH 恢复需求时再检查服务状态、监听 PID、日志及实际安装路径；Running 和 Listen 均不证明握手正常。Windows 可能没有 `OpenSSH/Operational` 通道，不能因此认定服务未安装。重启 SSH/改防护另按当前授权处理，不自动重启整机。

传输使用短 PowerShell `-EncodedCommand` 选择远端 Python，然后 `python -` 从 SSH 标准输入接收查询代码。**不要把完整查询再次嵌入编码命令**：2026-09-16 的长查询曾触发 Windows 命令长度问题，错误因控制台编码显示为乱码。

## 证据读取顺序

1. 检查 `room`、`revision`、`updated_at`、`game.version/phase/turn/active_side/operation/pending_choice`。`room=null` 表示指定数据库未找到该房间，不意味着网站不存在此房间。
2. 查看各角色 `hp/down_turns/shape/flags` 与双方 `front/ap`。普通服务日志只记请求路径/状态，不一定包含房间码或动作参数。
3. 从 `replay_views` 的 `opening_board` 和带 patch 的完整事件，按 `seq`、`action_id`、`action_version` 追踪异常窗口。`game.events` 可能只有末尾窗口。展示双方时明确 a/b 与玩家视角，区分总回合和第几个己方回合。
4. 对伤害、回血、倒地、恢复、武备变化记录 `before/after` 及事件顺序。用采集的服务器源码判断当时实现；本机 HEAD 和当前卡表可能已经改变，不能拿新数值解释旧局面。
5. 写出已确认、候选原因、证据缺口。没有动作事件不能单独证明网络故障；可能是拖拽未提交、请求失败、日志范围不足或未持久化。成功认输只说明那次操作成功，不证明此前没有卡顿。

SQLite 查询使用 `mode=ro`、`query_only` 和一个读事务，不导出整库或查询账号、密码、token 表。数据库只代表最后落库状态，可能落后于服务进程的缓存；快照和回放也未必是相同 revision，需按事件号比对。

**证据含隐藏手牌、牌序、随机种子、玩家标签或其他房间异常。** 留在主 agent 与本机任务目录，不交给 Grok/其他外部研究服务，不提交 Git，不直接发布完整 JSON。给用户的结论只引用必要事件；回归用合成局面，报告不附认证信息或玩家个人资料。

## 本地复原与交付

用户要求复原时，使用独立临时数据库和仅本机监听的临时端口，调用现有规则/API 和真实页面验证。保留取证原文件，派生新场景文件。若撤去最后的认输恢复行动阶段，同步处理版本、事件序号、结尾事件和公开投影缓存；更早历史局面不能仅靠改 `phase` 倒推，需按证据重建并注明推断字段。

先直接执行用户明确的动作，再用 `browser-testing-workflow` 从页面复验拖拽、动画、后续操作和浏览器错误。技能里的旧浏览器运行时路径不可用时，使用当前可用的浏览器工具，不反复尝试过期路径。替换高级人机为 pvp、跳过历史动画等测试简化必须标明，不能声称完全重现原会话。

- 26B025 的经验：0 血而倒计时为 0 可以是倒地扫描漏掉连锁伤害；需用同阶段事件和源码确认，不能只凭 UI 数字。
- 26F33E 的经验：先确认用户实际拖的是哪名角色（本次从白藏更正为零）。本地复原正常不能证明线上无问题，也不能确认网络就是原因。

只查日志时报告结论与限制即可。用户要求修复时再按仓库文档、测试与提交约定实施；取证授权不等于部署授权。结束临时测试时保持常驻 `0.0.0.0:5001` 可访问，核验本机和当前局域网地址。
