# 对局实体身份与白藏目标修复 · 2026-09-16

## 取证与规则口径

线上回放 1A138E 总第 20 回合，#389–393 使用「亦或是祝祷」。白藏 4/6，效果应造成 2 点伤害。我方伊洛伊 6→4、对方零 3→1、对方伊洛伊 5→3；对方白藏仍为 2 血，没有伤害事件。服务器 `_b04` 用角色模板 ID 排除自身，错误跳过了对方同名白藏。

该段零累计损失 4 血来自两次操作：#385 白藏普通出击使其 5→3，#391 祝祷使其 3→1。不能把这两次合计当作祝祷的单次伤害；本次未证明或修改录像演出存在的时序问题。

用户进一步指定：玩家、异能者、每张卡牌分别是类实例，具有独立实体 ID；白藏终结只斩杀对方异能者，不斩杀己方。敌我限制是用户的桌游规则调整，不作为 Everness 原作机制或数值。

## 实现

- 新增 JSON 兼容的 `PlayerEntity`、`CharacterEntity`、`CardEntity`。正式开局、教学、卡牌生成、动作副本及旧存档加载接入实体层；同名双方角色、同名原牌和复制牌拥有独立 `entity_id`。
- 独立对局计数器分配身份，不使用模板 ID 作实体 ID。移动区域、死亡/恢复、JSON 存取和快照复制保留身份；跨对局身份需要结合房间/对局标识。
- 旧存档稳定补齐身份并恢复类实例，处理选择区/结算中卡牌引用，拒绝重复或冲突身份。数据库格式仍是 JSON，没有批量改写线上存档。
- B04 按实体身份只排除施法者；白藏终结可处理对方同名白藏，并新增只允许对方目标的条件。薄荷攻击/穿透的回调也接收攻击者与防守者实体身份。
- 公开投影提供实体 ID 与 `entity_action`，事件提供 actor/target 实体 ID；暗牌不公开实体 ID。牌桌优先提交实体动作，保留旧 action 和 `a:角色模板ID` 渲染地址兼容既有页面/回放；阵营内 front 等索引暂未移除。
- native/CUDA 共用源码用阵营＋槽位的实体键区分同名对象，并同步 B04 和敌方斩杀。GPU 存储仍为扁平数值表示，不在 GPU 创建 Python 类；本次没有运行 Windows/CUDA 实机。

完整契约见 [V2 实现契约](duel-v2-implementation-contract.md#2026-09-16-对局实体身份)。
